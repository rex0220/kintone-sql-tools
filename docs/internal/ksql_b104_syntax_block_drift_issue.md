# B104 言語リファレンスの構文ブロックと文型テンプレートの乖離が検知されない

- 起票: 2026-07-30
- ステータス: ❌ **クローズ（何もしない・2026-07-30 オーナー判断）**＝**§5 の案 C**。**再起票の条件は §7**
- 出典: SELECT 基本構文から `KORDER BY` が落ちていた（2026-07-30・オーナー指摘）
- 関連: [B84 押し下げ表の生成・照合](../ksql_issue_tracker.md)

## 1. 実際に起きたこと

**`docs/ksql_language_reference.md` の SELECT 基本構文に `KORDER BY` が無かった。**

```
[ORDER BY キーリスト]              ← リファレンスの基本構文（欠けていた）
[ORDER BY|KORDER BY]               ← MCP の文型テンプレート（入っていた）
```

**`KORDER BY` は §10 に独立した節があり、詳しく書かれている。**
**冒頭の要約だけが落ちていた。**

**オーナーが読んで気づいた。機械は誰も見ていなかった。**

## 2. なぜ検知されなかったか

| | 検査されているか |
|---|---|
| **`STATEMENT_SYNTAX_CATALOG` のテンプレート** | **される**。`examples` を実際にパースし、`expectedTypes` と突き合わせる |
| **押し下げ可否の表**（[B84](../ksql_issue_tracker.md)） | **される**。実装から生成した表と文字列比較する |
| **リファレンスの構文ブロック** | **されない** |

**テンプレートはパーサに接地している。リファレンスの散文は接地していない。**
**両者は別管理で、突き合わせる仕組みが無い。**

## 3. **測ってみたが、他に乖離は見つからなかった**

**テンプレートの節キーワードが、リファレンスの構文ブロックに現れるかを機械的に照合した。**

**7 件が「無い」と出たが、すべて誤検知だった。**

| 検出 | 実際 |
|---|---|
| `select → INNER` | 基本構文は `[JOIN句]` と**意図的に略している**。JOIN 種別は専用節にある |
| `insert / update / upsert / validate → CHECK` | **`CHECK WHEN` は 5 箇所ある**。専用節に書かれている |
| `upsert / apply → ON DUPLICATE` | **16 箇所ある** |
| `apply → APPLY, VALIDATE ONLY` | **11 箇所 / 23 箇所ある** |

**実在した乖離は `KORDER BY` の 1 件だけだった**（修正済み・commit `5b3b9c0`）。

> **この測定は、課題の価値を下げる方向の事実である。**
> **素朴なキーワード照合は雑音だらけで、そのままでは検査に使えない。**

## 4. 案

### 案 A: 「基本構文ブロック」を指定して照合する

**文型ごとに、リファレンス内の「これが基本構文」というブロックを 1 つ指定し、
テンプレートの節キーワードがそこに現れることを検査する。**

- **略記の許可リストが要る**（`[JOIN句]` が `INNER` / `LEFT` / `RIGHT` を代表する、など）
- **リファレンス側にマーカーが要る**（B84 は `<!-- B84_..._START -->` を使っている。同じ手が使える）
- **費用**＝マーカーの埋め込み＋許可リストの設計。**節が増えるたびに許可リストの保守が要る**

### 案 B: テンプレートをリファレンスへ埋め込む（**生成する**）

**リファレンスの基本構文ブロックを、テンプレートから生成する。**

- **乖離が原理的に起きない**
- **リファレンスは日本語の説明的な書き方**（`[ORDER BY キーリスト]`）で、
  **テンプレートは英語の圧縮形**（`[ORDER BY|KORDER BY]`）。**読者が違う**
- **どちらかの表現を捨てることになる。**リファレンスの読みやすさが落ちる

### 案 C: 何もしない

- **実在した乖離は 1 件で、人が読んで見つかった**
- **リファレンスは節ごとに詳しい説明があり、要約の欠落は致命的ではない**
- **次に落ちたときも、同じように読んで見つかる可能性がある**

## 5. 現時点の見立て

**案 C（何もしない）に傾いている。優先度は 低・効果は 小。**

- **測った結果、乖離は 1 件だけだった**（§3）。**検査が守る対象が小さい**
- **素朴な照合は誤検知 7 件**。**使える検査にするには許可リストの設計と保守が要る**
- **案 B は乖離を原理的に無くすが、読者の違う 2 つの表現を 1 つに潰す**
- **B84 の表は「実装から導ける事実」なので生成が効いた。**
  **構文の要約は「何を強調して書くか」の判断を含むので、同じ手が効きにくい**

**起票しておく理由は、次に同じ欠落が見つかったときの出発点にするため。**
**2 件目が出たら、案 A の費用を払う根拠になる。**

**次に開くときに必要なもの**

- **2 件目の乖離の実例**。**それが出るまでは案 C のままでよい**

## 6. 対象外

| | 理由 |
|---|---|
| **リファレンス全体の自動生成** | **説明文書であって仕様書ではない**。人が書く価値がある |
| **テンプレート側の変更** | **パーサに接地しており、既に検査されている**。問題はリファレンス側 |
| **B84 の表の作り** | **既に生成・照合されている**。触らない |

## 7. クローズ（2026-07-30）

**§5 の見立て（案 C）どおり、何もしない。**

### 7.1 決め手

**測ったら、検査が守る対象が小さかった。**

| | |
|---|---|
| **実在した乖離** | **1 件**（`KORDER BY`・修正済み） |
| **見つけ方** | **人が読んで気づいた** |
| **素朴な機械照合** | **誤検知 7 件・真の検出 0 件** |

**検査を作る費用（略記の許可リスト＋リファレンス側マーカーの設計と保守）が、
守る対象に見合わない。**

### 7.2 **再起票の条件**

**2 件目の乖離の実例が出たとき。**

**そのときは「1 件だけの偶発」ではなく「構造的に起きる」ことの根拠になり、
§4 の案 A の費用を払う理由になる。**

### 7.3 クローズしても残る観察

**リファレンスの散文はパーサに接地していない。**

**文型テンプレートは `examples` を実際にパースして検査され、
押し下げ可否の表は実装から生成される。**
**リファレンスの構文ブロックだけが、人の目にしか支えられていない。**

**これは欠陥ではなく、現在の設計の性質である。**
**構文の要約は「何を強調して書くか」の判断を含み、機械が導ける事実ではない。**
