# B192 式の中のウィンドウ（隠しウィンドウ）に既定フレーム（RANGE）と全順序の警告が出ない — 列として出す形では出る

- 状態: 📝 **起票のみ（2026-09-16・実装は次の機会）**。B191 の棚卸しで見つけた警告・表示の穴。結果は正しく変わらない（値は列として出す形と同じ）。実測 v3.84.0（MCP・dev profile・SFA パック APP4149）。改善（警告の伝播・結果は不変・規模 S）。付随項目＝EXPLAIN に式の中のウィンドウの `window` / `frame:` 行が出ない

## 1. 現象

同額の行（売上 3,600,000 が 2 件）を含む範囲で、同じウィンドウ式を 2 経路で実行した。

| 形 | 同額 2 行の累計 | `warnings` |
| :--- | :--- | :--- |
| 列として出す `SUM(売上) OVER (ORDER BY 売上) AS 累計` | 7,200,000 / 7,200,000 | **あり**: 「累計 は既定フレーム（RANGE）で評価されます。ORDER BY の値が同じ行はすべて同じ値になります。…ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW を明示するか…」 |
| 式の中 `ROUND(SUM(売上) OVER (ORDER BY 売上) / 1000, 0) AS 累計千円`（v3.81.0 の B184-B） | 7,200 / 7,200 | **なし** |

- 値はどちらも既定 RANGE の結果で正しい（PostgreSQL でも既定は RANGE）。違いは合図の有無だけ
- `LAG` / `LEAD` の「ORDER BY は全順序でないため、同順内の前後関係は未規定です」警告も、式の中では出ない
- EXPLAIN の `window 別名: SUM OVER (ORDER BY …)` / `frame: RANGE … (既定)` 行も出力列のウィンドウだけ（`execute.ts` 14476 行付近）。式の中のウィンドウは B184-B の「EXPLAIN 不変」の設計どおり出ないが、上の警告の穴と合わせると、1 段版では実行前にも実行後にも RANGE を知る手段が無い

## 2. なぜ問題か

- 第 3 回の「落とし穴 — 既定の RANGE は同額の行に同じ累計を載せる」は、警告を唯一の合図として書いている。B188（v3.79.0）は「推奨した経路だけ警告が消える」ことを理由に直した。本件も同じ構図＝v3.81.0 以降に推奨する 1 段版（ウィンドウを式の中に書く形）だけ合図が消える
- 実害が出る条件は 3 つの重なり: ①フレームを省略する（標準 SQL の書き手と AI が最初に書く形）②ORDER BY の値に同額がある ③累積構成比を A/B/C の閾値判定に使う（同額 2 社が同じ累計になり、両方の区分が動く）
- 守りは「書かせない」側にしかない（MCP Writing rules 5 行目の ROWS + タイブレーク、第 3 回・第 9 回の ROWS 明示）。書かれてしまった SQL を検出する側の守りが 1 段版に無い

## 3. 原因

`collectDefaultRangeWindowWarnings`（`execute.ts` 3764 行付近・呼び出し 2 か所）が `stmt.columns` の `WINDOW_COL` だけを走査する。B184-B の隠しウィンドウは `stmt.hiddenWindows`（別配列）にあるので対象外。B190（取得列収集）・B191（B65 計画）と同じ型の 3 例目。

## 4. 対応案

**案 A（警告を式の中にも出す・純加法）**: 走査対象を `[...stmt.columns, ...(stmt.hiddenWindows ?? [])]` にする。警告文の主語は内部名 `__ksql_window_0` になるので、式の中のウィンドウは EXPLAIN と同じ書式（`SUM(売上) OVER (ORDER BY 売上)`）で「式の中の SUM(売上) OVER (ORDER BY 売上) は既定フレーム（RANGE）で評価されます。…」と表示する。同じウィンドウ式を複数箇所に書いても隠し列は 1 つなので警告も 1 つ。`canProveTotalWindowOrder`（同一 SELECT のグループキーが全部 ORDER BY にあれば警告なし・B184-A）はそのまま効く

**付随（EXPLAIN）**: 同じ走査で式の中のウィンドウにも `window (式の中): SUM OVER (…)` / `frame:` 行を出す。プラグイン同梱エンジンの EXPLAIN snapshot に波及するので、案 A と同じリリースで判断する。出さない選択もある（警告が出れば実行後には分かる）

推奨は **案 A + EXPLAIN 行**。既存の警告文テスト（b160・window.execute 等）は列として出す形の文言を固定しているだけなので不変のはず。式の中の形は新規テストで固定する

## 5. 受入条件

- §1 の式の中の形で、列として出す形と同じ趣旨の RANGE 警告が 1 件出る（主語は式の書式）
- `LAG` / `LEAD` を式の中に書いた形で全順序の警告が出る
- `ROWS BETWEEN … AND CURRENT ROW` を明示した式の中の形（第 3 回の 1 段版・R15 / R16）では警告なし・不変
- 同一 SELECT のグループキーが全部 ORDER BY にある形（B184-A の一意性）では式の中でも警告なし
- 結果行・列・取得列・API 回数は不変
