# B134 「取引の無い日を 0 として並べる」ことができない（連番・日付系列の生成）

- 起票: 2026-08-05
- ステータス: 📝 **評価（方向判断待ち）**
- 出典: [ksql-analytics の返信 §3](../../../ksql-analytics/docs/internal/kSQLエンジンへの返信-B129-20260805.md)。
  B129 の Q3「3 段 CTE で書けない形はあるか」への回答で、**ウィンドウとは別種の書けない形**として挙がった
- 関連: [B128](ksql_b128_window_phase2_spec.md)（移動平均が成立しない理由の 1 つがこれ）

## 1. 何が書けないか

> **「取引の無い日を 0 として並べる」ことができません。**
> kintone 側に日付ディメンションが無く、kSQL にも連番生成（`generate_series` 相当）が無いため、
> **CTE では 0 埋めした日次系列を作れません。**（依頼元）

`GROUP BY 日付` は**データのある日しか行を作らない**。標準 SQL なら日付ディメンション表や
`generate_series` と `LEFT JOIN` して 0 埋めするが、**kintone には起点になる表が無い**。

### 依頼元は同じ問題を別の形で踏んでいる

> v2 では**マスタ起点の `LEFT JOIN` ＋ `CASE`**で回避しました
> （直近 90 日に出庫の無い 2 製品が消え、8 行のはずが 6 行で返っていた）。
> **日付には起点になるマスタが無いため、同じ回避ができません。**

**製品は「製品マスタ」という起点があったので `LEFT JOIN` で 0 を出せた。日付には無い。**

---

## 2. なぜ効くか

### 2.1 B128（移動平均）が成立しない理由の 1 つ

日次集約しても**取引のあった日の行しかできない**ため、`ROWS BETWEEN 6 PRECEDING` は
「直近 7 日」ではなく「取引のあった直近 7 日」になる。
依頼元の実測では **7 行が相当する暦日が製品ごとに 15〜29 日（2 倍の開き）**。

### 2.2 「動きが止まった」ことが表から消える

> 直近 90 日の出庫では、**8 製品中 2 製品が出庫ゼロで行ごと存在しません**（ほうじ茶・ライ麦パン）。
> 0 埋めができないため、**「動きが止まった製品」が移動平均の表から消えます。
> 検出したいのはまさにその製品です。**

**これは B119〜B122 と同じ「静かに間違う」系列**である。エラーは出ず、
**行が無いことが「0」ではなく「無かったこと」になる。**

> 依頼元の分析記事にも同じ形の記録がある——「`GROUP BY` に現れない行に意味がある。
> 出庫ゼロ = 行が出ないから滞留在庫が見つかった」。**気づけたのは偶然だった**とも書かれている。

## 3. 対応の方向（いずれも未評価）

| 案 | 内容 | 論点 |
|---|---|---|
| **A** | **日付系列の生成**（`generate_series` 相当 / `CALENDAR(from, to)` 仮想テーブル） | kSQL は「kintone のデータを SQL で触る」方言であり、**データ源の無い行を作る**のは性格が変わる。範囲の上限・型（`DATE` / `DATETIME`）・タイムゾーンも要検討 |
| **B** | **汎用の連番生成**（`SERIES(1, n)` 等） | A より汎用だが、同じ「無から行を作る」問題。`WITH RECURSIVE`（[B53](ksql_b53_recursive_cte_cycle_phase1_spec.md)）があれば標準 SQL の書き方で書ける |
| **C** | **既存アプリを日付ディメンションとして使う運用**（エンジンは変更しない） | 利用側でカレンダーアプリを作り `LEFT JOIN`。**今日でもできる**。ただし全利用者に同じ準備を強いる |
| **D** | 何もしない（回避策を文書化） | 現状。**0 埋めが要る分析は SQL の外へ出る** |

### 見立て

**B53（再帰 CTE）との関係を先に整理すべき。** 標準 SQL では
`WITH RECURSIVE 日付 AS (SELECT 開始日 UNION ALL SELECT DATE_ADD(...) FROM 日付 WHERE ...)` で
日付系列を作る。**B53 が入れば案 A / B は不要になる可能性がある**。

B53 は「実需待ちで棚上げ」（見積り 18〜29 人日）だが、**再帰 CTE の実需として
「日付系列の生成」が挙がったのは初めて**。B53 の再評価材料になる。
