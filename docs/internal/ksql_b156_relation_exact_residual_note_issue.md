# B156 `relation: exact` が「取得＝答え」と誤読される（residual の明示）

- 起票: 2026-08-08（[依頼元の v3.62.0 返信 §4](../../../ksql-analytics/docs/internal/kSQLエンジンへの返信-20260808-v3620.md)）
- ステータス: ✅ **案 B 実施（2026-08-08・言語リファレンス §6 に「機構の全体像」「EXPLAIN の読み方」を新設・エンジン不変）**。案 A（`relation:` 行への 1 語追記）は次に同じ誤読の報告が来たら再評価。
- 関連: [B154](ksql_b154_join_prefilter_explain_note_issue.md)（同じ「表示の誤読」クラス・v3.62.0 で対応済み）

## 1. 何が起きたか

依頼元が自分たちの文書に「`relation: exact` は kintone 側で完全に絞れた」と書き、誤りだった
（自己訂正済み・当方への要望ではないと明言）。反証は単一表プレフィルタ＋LIKE 併用の形:

```
kintone query: 分類 in ("飲料")     relation: exact
→ 取得 4 件 / 結果 1 件（LIKE は取得後に JS 判定）
```

**`relation:` は「押し下げた葉が忠実に訳せたか」**（exact＝葉単位で等価・superset＝広め）であって、
**「押し下げから漏れた条件が無いか」ではない**。漏れ（residual）の有無は別の情報。

## 2. 論点

- `exact` / `superset` という語は「取得集合と答えの関係」と読める語感がある。
  同じ誤読は他の利用者でも起こりうる（依頼元の指摘）
- 情報自体は既に出ている（residual を示す reason・fetch 行）が、`relation:` 行単体を
  読んだ人には届かない

## 3. 案

- **案 A**: residual がある場合だけ `relation: exact (residual あり)` と 1 語添える（依頼元提案）
- **案 B**: 言語リファレンス §24 に「`relation:` は葉の忠実度であり、取得＝答えを意味しない。
  取得の実態は `fetch:` を読む」を明記（文書のみ・エンジン不変）
- 案 C: 何もしない（依頼元は運用規約「`fetch:` だけを根拠にする」で自衛済み）

**見立て**＝案 B は安価で確実（B154 と同じ「読み方の正」を文書に置く形）。案 A は表示行の
snapshot を持つテストへの波及を測ってから。**次に同じ誤読の報告が来たら案 A へ**。

## 4. 実測の裏付け

2026-08-08 の実機（APP4228）: `製品名 = '牛乳' AND 仕入先 LIKE '%乳業%'` →
`pushdown applied: 製品名 = "牛乳"`・`relation: exact`・取得 200 件は LIKE 判定後も 200 件
（この形は取得＝答えだが、LIKE 次第で乖離する）。依頼元の 4 件→1 件の形と合わせて、
`relation: exact` と「取得＝答え」が独立であることを両方向で確認。
