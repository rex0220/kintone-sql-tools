# 本文（送付版）

## 【報告】v3.43.0 — 「非対応と読み替えた」原因はこちらの診断でした

v3.42.0 の確認、ありがとうございました。

そちらの §5 に「**構文エラーを機能の非対応と読み替えていた**」と書かれていましたが、
**その読み替えを招いたのはこちらのエラーメッセージ**です。原因を測って直しました。

```
npm i @rex0220/kintone-sql-tools@3.43.0
```

## 1. 何が起きていたか

```
修正前  DATE_SUB(列, 1, 'MONTH')        → 文の区切りには ; が必要です
        DATE_ADD(列, INTERVAL 1 MONTH)  → 「)」が必要です

修正後  DATE_SUB(列, 1, 'MONTH')
          → 「DATE_SUB」という関数はありません。日付を減算するには
             DATE_ADD の加算値へ負数を指定してください
        DATE_ADD(列, INTERVAL 1 MONTH)
          → DATE_ADD の構文は DATE_ADD(列, n, '単位') です
```

**「その機能は無い」と読むしかないメッセージでした。**同じ状況に置かれた人は
同じ結論に至ります。文書の誤記としてではなく、**こちらの欠陥として直しました。**

## 2. あわせて見つかった、もっと重い欠陥

原因を調べる過程で、**引数の数が誤った呼び出しを黙認していた**ことが分かりました。

```
DATE_ADD(列, 1)     → 単位が無いのに DAY 扱いで通る
ROUND(列, 1, 2)     → 余分な引数を黙って無視
FORMAT(列)          → 既定パターンで黙って整形
```

**B117 と同じ「静かに間違う」形**です。エラーにならないので気づけません。
言語リファレンスの構文列を正本として引数の数を検証し、**`ksql_validate` でも
実行前に検出**するようにしました。

## 3. ⚠ 1 点だけ確認をお願いします — `FORMAT(列)`

**`FORMAT(列)` の 1 引数形はエラーになります。**`FORMAT(列, パターン)` が必要です。

- 1 引数形はリファレンスに記載が無く、既定パターンで黙って整形されていました
- **レシピ集・テンプレート・ハンズオン記事に `FORMAT(列)` の形があれば、
  影響を受けます。**お手数ですが確認をお願いします
- 例: `FORMAT(売上)` → `FORMAT(売上, '#,##0')`

他の関数も引数の数が正しければ**結果は完全に不変**です。

## 4. 経緯について

そちらは「こちらの誤記がエンジンの欠陥を掘り当てた」と書かれていましたが、
順序はこうでした。

```
こちらの診断が弱い → Pro が「非対応」と誤読 → こちらが訂正 →
Pro が実際に動かす → 月末の欠陥(B117)を発見 → 診断の弱さ自体も発見(B118)
```

**起点はこちらです。**誤読されたことで 2 つの欠陥が表に出たので、
結果的には良い往復でした。詳しく書いていただいたおかげです。
