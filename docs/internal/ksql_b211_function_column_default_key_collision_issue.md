# B211 別名の無い関数の列で、中の `CASE` を「case」と略すため、違う式の列が同じ名前になって片方が消える（黙って誤る）

- 状態: 🚧 **v3.95.0 に同梱（PR #424 でマージ）・タグと公開待ち（2026-11-10）**。Takashi「案 B ＋ 再帰 CTE を位置で受ける　で直す」
- 種別: 正しさ（**黙って誤る**。列が 1 つ消える・再帰 CTE では 2 列とも同じ値になる）
- 優先: 中（別名を付ければ起きない。ただし再帰 CTE の列名リストで受ける形は別名を書かないのが自然）
- 見つけ方: B210 の発端（在庫の事例の候補。発注ロットを `WITH RECURSIVE` で持ち越す形）を、公開した v3.94.0 で確かめ直したら、まだ「在庫の列に発注数の値が入る」ままだった。切り分けるとこの不具合だった（B210 はその切り分けの途中で見つけた別の不具合）。再現は `work-link/ksql-action-stock-lot-probe.cjs` の `CAST(CASE …)` を 2 列にした形
- 関連: [B210](ksql_b210_case_in_function_numeric_compare_issue.md)

## 1. 現象（v3.94.0 の実測。`x` は NUMBER で 1 と 5 の 2 行）

| # | SQL | 列 | 行 |
|---|---|---|---|
| 1 | `SELECT CAST(CASE WHEN x > 2 THEN 1 ELSE 0 END AS NUMBER), CAST(CASE WHEN x > 2 THEN 10 ELSE 20 END AS NUMBER) FROM APP1` | `CAST(case,'NUMBER')` が 2 つ | **1 列だけ**（20・10。1 列目の 0・1 が消える） |
| 2 | 同じ式に別名 `AS a`・`AS b` | `a`・`b` | 正しい（0・20 / 1・10） |
| 4 | `COALESCE(CASE …, 9)` を 2 列 | `COALESCE(case,9)` が 2 つ | **1 列だけ** |
| 7 | `WITH RECURSIVE r (n, a, b) AS (SELECT 番号, CAST(CASE …), CAST(CASE …) … UNION ALL …)` | `n`・`a`・`b` | **a と b が同じ値**（20・20。正しくは 0・20） |
| 9 | `CREATE TEMP TABLE #t AS SELECT CAST(CASE …), CAST(CASE …) …` | **1 列だけ** | 1 列目が消える |

起きないもの: 列そのものの CASE（`case`・`case_2` と番号が付く）、集計（`SUM(CASE WHEN x > 2 THEN 1 ELSE 0 END)` のように中身まで名前に入る）、中に CASE の無い関数（`CONCAT('a', x)` と `CONCAT('b', x)`）。
同じ式を 2 回（`ROUND(x), ROUND(x)`・`x, x`）も同じ名前になるが、値も同じなので消えても値は失われない（別の論点）。

## 2. 原因

関数の列の既定の名前（`stringFuncDefaultKey` → `scalarValueDefaultKey`。`src/engine/process.ts`）が、引数の CASE を `"case"` と略す。
中身の違う CASE を含む 2 つの列が同じ名前になり、射影の行のオブジェクトで後の列が前の列を上書きする。重なりを検出していない。
再帰 CTE の列名リストは位置で名前を付け替えるが、元の行のキーが 1 つしかないので両方に同じ値が入る。

## 3. 直し方の案

- 案 A（起票のときに勧めたが採らなかった。理由は §4）: 関数の列の既定の名前で、CASE を集計と同じく**中身まで書く**（`aggregateExpression.ts` の `caseLabel`）。集計の既定名と規則がそろう。**既定の列名が変わる**（`CAST(case,'NUMBER')` → `CAST(CASE WHEN x > 2 THEN 1 ELSE 0 END,'NUMBER')`）
- **案 B（採った）**: 名前が重なったら番号を付ける（列そのものの CASE と同じ `_2`）。今の名前は 1 列目だけ残る
- 案 C: 中身の違う式が同じ名前になったら止める（fail-closed。「別名を付けてください」）。今まで動いていた形（重なっても値が同じ・1 列しか使わない）も止まり得る
- どの案でも、再帰 CTE の列名リストは**射影の位置**で受け取るよう直すのが本筋（名前の重なりに頼らない）

## 4. 直したこと（案 B ＋ 再帰 CTE を位置で受ける）

前の版の説明（案 A を勧めた）から変えた理由: 案 A は**重なっていない（今は正しく動いている）列の名前まで変える**。案 B で変わるのは**今は列が消えて誤っている形だけ**。

- **案 B**（`src/engine/process.ts` の `buildDefaultExpressionOutputKeys`）: 別名の無い関数の列・式の列・算術の列の既定の名前が、**中身の違う式**と重なったら 2 つ目から番号を付ける
  （`CAST(case,'NUMBER')`・`CAST(case,'NUMBER')_2`・`_3`）。番号は、別名とほかの列の既定の名前に使われていないものを選ぶ（列そのものの CASE の `case_2` と同じ形）。
  - **重なっていない列の名前は変えない**。**中身が同じ式どうし**（`ROUND(x), ROUND(x)`）は値も同じなので、ふつうの SELECT では今までどおり同じ名前
  - 中身が同じかは構文の木で比べる（`expressionSignature`。数の書き方〈`raw`。`2` と `2e0`〉は名前に出ないので比べない）
- **出力の名前を、射影と同じ規則で 1 か所から引く**（`selectColumnOutputKeys`）。EXPLAIN の列名の推定（2 か所）と、ワイルドカードと一緒の一時テーブルの列の型は、これまで列を 1 つずつ・別名のある列だけで名前を決めていたので、番号を付けた名前と食い違っていた
- **再帰 CTE を位置で受ける**: 受け取り（`alignSelectResultByPosition`）は以前から位置で写している。誤りは、写す前の SELECT の結果の行で、同じ名前の列の値が上書きされることだった。
  案 B で別名の無い式の列の名前は重ならなくなったので、残るのは**書いた名前**（項目の名前・書いた別名）が中身の違う列と重なる形。そのときは実行の前に止める（`assertRecursiveOutputNamesDistinct`。`PlanningError`。どちらの値を受けるか決められない）。中身が同じ列どうし（`SELECT x, x`）は値も同じなので通す
  - 1 回目の実装では、別名の無い式の列に列名リストの名前を別名として付け足していたが、**付けた名前が残した項目の名前や書いた別名とぶつかり、3.94.0 では正しかった列まで誤った**（Codex の BLOCKER 2。`(n, x, b)` で seed の 1 列目が項目 x のとき n が 1 → 0）。付け足しはやめた
- **UNION の 1 つ目の枝の列名が重なっていたら**（`SELECT x, x` や中身が同じ式を 2 列）、UNION の結果では 2 つ目から番号を付けて位置どおりに持つ（`withUniqueColumnNames`）。
  重なったままだと、後の枝の値を位置どおりに写すときに同じキーへ入って片方が消えていた（`… UNION ALL SELECT 7, 8` の 7）。**v3.94.0 でも起きる、もとからの穴**（Codex の BLOCKER 1）

## 5. 試験（`src/flow-library/__tests__/b211DefaultKeyCollision.test.ts` 24 件）

2 列・3 列、`COALESCE`・算術の中の関数（名前まで）、集計を含む式の列、ワイルドカードと一緒、ワイルドカードと一緒の一時テーブルの `_2` を数値で比べる、INSERT … SELECT、
EXPLAIN の CTE の `_2`、一時テーブル、UNION（1 つ目の枝に同じ式 2 列・同じ項目 2 列・違う式）、
再帰 CTE（**再帰項から実際に行が出る形**で: 列名リスト・同じ式を 2 回・列名リストの名前が項目の名前と同じ・Codex の形・書いた別名が列名リストのほかの位置と同じ・書いた別名の重なりで止まる・書いた別名が項目の名前と重なって止まる）、
変えないこと（重なっていない列・数の書き方だけ違う式・中身が同じ式どうし・列そのものの CASE・別名を付けた列）。

**main（v3.94.0）では 24 件中 18 件、1 回目の実装（`447c7988`）では 9 件が落ちる。**
発端の形（`work-link/ksql-action-stock-lot-probe.cjs` の `CAST(CASE …)` を 2 列にした発注ロットの持ち越し）も手計算どおり（在庫 30 → 20 → 30 → 50 → 35 → 25 → 30）。
全体の試験（Mac）で落ちるのは main と同じ環境の差だけ（45 件・`--runInBand` の 3 件）。`build:flow`・`flow:bundle-guard`・`docs:check`（97 件＝main と同じ）。

## 6. 影響（結果が変わる）

- 中身の違う式の列が同じ既定の名前になっていた SELECT は、**消えていた列が `…_2` の名前で出る**（列の数が増える）。
- **UNION の 1 つ目の枝に同じ名前の列があると、UNION の結果の名前に番号が付く**（`x`・`x_2`）。後の枝の値が消えなくなる。
- 再帰 CTE の列名リストで受けた値が正しくなる。書いた名前（項目の名前・別名）が中身の違う列と重なる再帰 CTE は止まる（今までは誤った値で通っていた）。
- EXPLAIN の列名と、ワイルドカードと一緒の一時テーブルの列の型が、実行と同じ名前になる（別名の無い式の列にも型が付く）。
- 変わらないもの: 重なっていない列の名前、ふつうの SELECT の中身が同じ式どうし、列そのものの CASE、別名を付けた列、集計の列。

## 7. 別に見つけたこと（B212）

ワイルドカードと式を一緒に入れた一時テーブル（`CREATE TEMP TABLE #t AS SELECT *, 式 FROM APP200`）は、ワイルドカードで入った列を名前で読むと止まる
（`SELECT 番号 FROM #t` が `unknown field code(s): 番号 (#t)`）。`SELECT * FROM #t` は読め、式の列は名前で絞れる。v3.94.0 でも同じで、B211 とは別。→ [B212](ksql_b212_wildcard_temp_table_field_reference_issue.md)

## 8. Codex レビュー（2026-11-10。BLOCKER 2 / MAJOR 2 / MINOR 1）

依頼文と結果は work-link の `codex-review-b211-prompt.md`・`codex-review-b211-2026-11-10.md`（1 回目の起動はクレジット切れで止まり、補充後に流し直した）。

| # | 指摘 | 処置 |
|---|---|---|
| BLOCKER 1 | UNION の 1 つ目の枝に中身が同じ式が 2 列あると、後の枝の値が上書きされる | 直した（`withUniqueColumnNames`）。同じ項目を 2 列でも起きる、もとからの穴だった。試験 2 件 |
| BLOCKER 2 | 再帰 CTE で付け足した別名が、残した項目の名前・書いた別名とぶつかる | 直した。付け足しをやめ、出力の名前の重なりを調べて止める形に。試験 4 件（再帰項から行が出る形） |
| MAJOR 1 | EXPLAIN の列名の推定が列を 1 つずつ見るので番号が付かない | 直した（`selectColumnOutputKeys` を 2 か所で）。試験 1 件 |
| MAJOR 2 | ワイルドカードと一緒の一時テーブルで、別名の無い式の列に型が付かない | 直した（同じ helper で名前を引く）。`_2` を数値で比べる試験 1 件 |
| MINOR | 中身が同じかの比較が数の書き方（`2` と `2e0`）まで見る | 直した（`expressionSignature` で `raw` を除く）。試験 1 件 |
| 試験の不足 | 再帰項が 0 行・UNION・EXPLAIN・INSERT … SELECT・`ARITH_COL` の名前など | 足した（上の §5）。`_2` が書いた別名に使われているときの `_3` は、英字の別名が小文字になり既定の名前（大文字の関数名）と重ならないので試験していない |

## 9. 回避策（v3.94.0 まで）

関数の列には**必ず別名を付ける**（再帰 CTE の列名リストで受けるときも、SELECT の中で `AS 在庫` のように付ける）。
