# B165 再帰 CTE の診断が「非対応」と言わない（専用診断＋自己 JOIN レシピ）

- 起票: 2026-08-09（[依頼元の再帰 CTE 依頼書 §1・§6](../../../ksql-analytics/docs/internal/kSQLエンジンへの依頼-20260809-再帰CTE.md)。依頼は案 A のみ・案 B は独立同梱向き）
- ステータス: ✅ **v3.66.0 リリース済み（2026-08-09・B53 同梱）**。B53 実装で形 1（`WITH RECURSIVE` 構文）は合法化されるため、**実装対象は形 2 の専用診断（文言は最初から B53 後の形＝「自己参照には `WITH RECURSIVE` が必要です」）と案 B レシピに縮小**。[B53 実装依頼](ksql_b53_codex_impl_request.md) Stage 4 に組み込み
- 種別: 改善（診断・文書）／効果種別: 改善
- 関連: [B53](ksql_b53_recursive_cte_cycle_phase1_spec_r3.md)（本体実装。**本件は B53 と独立**で、B53 出荷後も §2 の形 2 は残る）／B80・B73（エラー `code` 維持の契約）

## 1. 問題（依頼元の実測・2026-08-09・v3.65.0）

言語リファレンスは「再帰 CTE は非対応」と明記しているが、**診断が文書を指さない**:

| 書いた形 | 現在の診断 | 誤読 |
|---|---|---|
| 形 1: `WITH RECURSIVE 系譜 AS (...)` | `ParseError: 「AS」が必要です（位置 15、トークン: 「系譜」）` | `RECURSIVE` が CTE 名として読まれた結果。「AS の位置を直せばよい」と書き換えを試行する |
| 形 2: CTE 本体から自分自身を JOIN 参照 | `ParseError: テーブル名は APP + 数字（...）で指定してください。「系譜」は無効です` | CTE の JOIN 参照は一般には合法なのに、自己参照（スコープ未登録）のときだけ別文言。原因に辿り着けない |

依頼元の表現＝「文書は正しい。応答が文書を指していない」。

## 2. 案

- **案 A（専用診断・依頼の本体）**
  - 形 1: `WITH` 直後の `RECURSIVE`（IDENT）の**次も IDENT が続く形**を検出し、
    「再帰 CTE（`WITH RECURSIVE`）は非対応です。深さが固定なら自己 JOIN で書けます」級の専用 ParseError にする。
    **`WITH RECURSIVE AS (...)`（RECURSIVE という名前の CTE）は現在合法なので壊さない**
    （検出対象は現在も ParseError になる形だけ＝fail 経路のみの変更・純加法）。
  - 形 2: CTE 定義本体の解析中に**定義中の自分自身の名前**への参照を検出し、
    「CTE の定義内から自分自身は参照できません（再帰 CTE は非対応です）」級の専用 ParseError にする。
    parser は定義名を本体解析前に読んでいる（`src/parser/parser.ts:1246`）ので判定材料はある。
  - どちらも `code` は `PARSE_ERROR` を維持（B80/B73 の契約）。
- **案 B（レシピ・独立同梱向き）**: `ksql://recipes` に「固定深さの階層は自己 JOIN で書く」を 1 節
  （2〜3 段の例。`JOIN ... ON` 等値 1 本で書ける形であることを明記）。
- 案 C（`WITH RECURSIVE` 本体）＝ [B53](ksql_b53_recursive_cte_cycle_phase1_spec_r3.md)。**本件に含めない**（実需待ち・依頼元も明記）。

## 3. B53 との関係（設計上の注意）

- B53 を出荷すると形 1 は合法になり消える。**形 2（`RECURSIVE` なし自己参照）は B53 の R3 仕様でも
  未登録名のままなので残る**＝B53 後は文言を「自己参照には `WITH RECURSIVE` が必要です」へ差し替える。
  実装時に**形 2 の文言を B53 出荷時に差し替えやすい形（1 箇所の定数）**にしておく。

## 4. 受入条件（実装時にテスト化）

1. 形 1・形 2 で §2 の専用文言が返る（`ksql_validate`・CLI・プラグインの各面で同一）。
2. `WITH RECURSIVE AS (SELECT ...)`（RECURSIVE 名の CTE）・`RECURSIVE`/`系譜` という
   フィールド名・alias の既存合法形が**すべて不変**。
3. `code` は `PARSE_ERROR` のまま。
4. 既存の CTE 前方参照エラー（定義順違反）の文言・挙動が不変。
5. 案 B: レシピの SQL は掲載前に `ksql_validate` を通す（B141 の教訓）。
