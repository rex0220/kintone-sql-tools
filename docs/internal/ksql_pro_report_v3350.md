# 本文（送付版）

## 【連絡】v3.35.0 — `PRIMARY_ORGANIZATION()` が使えるようになりました

```
npm i @rex0220/kintone-sql-tools@3.35.0
```

**ダッシュボードから自組織のデータを抽出できます。**`LOGINUSER()` と同じ位置づけです。

```sql
SELECT 案件名 FROM APP100 WHERE 担当組織 IN (PRIMARY_ORGANIZATION())
```

**あわせて、ダッシュボードで使う場合の注意が 1 つあります**（§2）。

---

## 1. 使い方

| | |
|---|---|
| **使える型** | **組織選択（`ORGANIZATION_SELECT`）のみ** |
| **使える演算子** | **`IN` / `NOT IN` のみ**。**リストの単独要素**として書きます |
| **評価する場所** | **kintone サーバー**。REST クエリへそのまま素通しします |

`ORGANIZATION_SELECT` 以外の型、`IN` / `NOT IN` 以外の演算子、`IN` リストで他の値と
混ぜた場合は、いずれも**レコードを取得する前に**拒否します。

**押し下げは実機で確認しました**（`EXACT_PUSHDOWN`・client 評価 0）。

---

## 2. ⚠ **優先組織が未設定の利用者では、絞り込みが効きません**

**kintone の仕様です。**公式にこう書かれています。

> **API を実行したユーザーに優先する組織が設定されていない場合、
> `組織 in (PRIMARY_ORGANIZATION())` の条件は無視され、
> それ以外の絞り込み条件を満たすすべてのレコードが取得されます。**

**エンジン側からは、条件が無視されたかどうかを判別できません。**
**そのため `SELECT` ではそのまま返します。kintone の一覧の絞り込みと同じ挙動です。**

### 2.1 ダッシュボードで効きます

**「自組織の実績」のつもりの数字が、優先組織が未設定の利用者には
全社の数字として見えます。**

**画面からは区別がつきません。**警告も出ません（出せません）。

**Pro 側で利用者への案内が要るかもしれません。**
たとえば「この絞り込みは優先組織の設定が前提です」といった注記です。
**判断はお任せします。**

### 2.2 こちらでは再現していません

**優先組織を持たない利用者を用意できませんでした**（ユーザー管理の変更が要るため）。
**上記は kintone 公式の記述によるもので、こちらの実測ではありません。**

**正常系は実測しました。**組織選択フィールドを持つ検証アプリで、
`IN` と `NOT IN` が全件を正しく分割することを確認しています。

### 2.3 検出する方法はあります（今回は入れていません）

**`IN` と `NOT IN` の件数を突き合わせると、条件が落ちたかどうかが分かります。**

```
正常          in + not in ≤ 全件
落ちたとき    in = 全件 かつ not in = 全件   ← この組み合わせは正常時に起こりません
```

**`COUNT(*)` 2 回で判定できます**が、**狭い条件のために常時払う費用としては重い**と判断し、
今回は入れていません。**実運用で踏むことが分かれば、上積みします。**

**Pro 側でこの判定を使うこともできます。**

## 3. DML の `WHERE` では使用できません

```sql
DELETE FROM APPn WHERE 担当組織 IN (PRIMARY_ORGANIZATION())
-- → エラー。レコード取得も書き込みも行いません
```

**条件が無視されると、`DELETE` や `UPDATE` の対象がアプリ全件になるためです。**
**静的検証で拒否するので、API は 1 回も呼ばれません**（実機で確認済み）。

対象は `UPDATE` / `DELETE` / `UPSERT` と、`INSERT ... SELECT` / `UPSERT ... SELECT` の
`SELECT` 側 `WHERE` です。

**`LOGINUSER()` の扱いは変えていません。**押し下げも DML も従来どおりです。

> **Pro の出荷物は `SELECT` 中心なので、この拒否は影響しないはずです。**
> **効くのは「利用者が自分で書く SQL」のほう**——B98 と同じ構図です。
