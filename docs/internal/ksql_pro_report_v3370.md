# 本文（送付版）

## 【連絡】v3.37.0 — 日本語の論理アプリ名と `logicalApps` オプションが出ました

```
npm i @rex0220/kintone-sql-tools@3.37.0
```

**K-87 でご依頼いただいた両方が入っています。**

```ts
await runBatch(
  "SELECT * FROM LAPP_案件管理 WHERE 担当組織 IN (PRIMARY_ORGANIZATION())",
  { client, logicalApps: { 案件管理: 4149 } }
);
```

- **`RunQueryOptions` / `RunBatchOptions` / `explainQuery` に `logicalApps` を追加**（純加法）
- **論理名に日本語が使えます**（CLI / MCP / engine ライブラリの全面で同時）
- **未定義名は kintone API を呼ばずに名前入りエラー**で停止します
  （`logical app LAPP_案件管理 is not defined` の形。構文チェックにそのまま出せます）
- **`@profile` 接尾辞はブラウザでは明確なエラー**です。環境差は渡すマッピングの
  差し替えで表現してください（設定スキーマ共通とのことなので、この形が揃うはずです）

## 1. 確認事項への正式回答

### 1.1 ASCII 名は引き続き使えるか

**使えます。拡張は純粋な上積み**で、`LAPP_ORDERS` の挙動は 1 つも変わっていません。

### 1.2 字句規則

| | |
|---|---|
| 開始文字 | ASCII 英字 `[A-Za-z]` **または** 日本語（ひらがな・カタカナ・漢字・全角英数記号） |
| 継続文字 | 開始文字 ＋ 数字 `[0-9]` と `_` |
| 長さ上限 | **64 UTF-16 コードユニット**（`LAPP_` の後の名前部） |
| 正規化 | **両側 NFC**（SQL 中の名前と、config / `logicalApps` のキーの両方）。macOS 由来の NFD（濁点分解）も一致します |
| 空白 | 文字集合外なので名前に含められません（そこで名前が終わります） |
| 区切り | **半角 `$`（サブテーブル）と半角 `@`（profile）だけ**が区切りです |

**注意 1 つ**——全角の `＄`・`＠`・中黒 `・`・長音 `ー` は**名前の文字**です
（`LAPP_案件＄明細` は「案件＄明細」という 1 つの名前になります）。
設定 UI の入力検査を作られる場合はこの点だけご留意ください。

### 1.3 大小無視の扱い

**ご想定のとおり「ASCII 部分のみ大小無視」に近い形です。**
正確には **ASCII 英字と全角英字（`ａ`→`Ａ`）に効き、かな・漢字は区別しません**
（というより大小の概念がありません）。

## 2. 破壊的変更の正確な規則（利用者向けドキュメント用）

**`LAPP_` に日本語が続く識別子は、論理アプリ参照として予約されます。**

- 従来＝正当なフィールド参照としてパースされ得た → 今後＝未定義ならエラー（fail-closed）
- **退避＝バッククォート**: `` WHERE `LAPP_案件` = 'x' `` は従来どおりフィールド参照
- **「定義済みのときだけ解決」は採っていません**——同じ SQL の意味が設定で変わるためです

出荷資産に該当なしをご確認済みの件、そのままで大丈夫です。

## 3. レシピ集の更新タイミング

**「`LAPP_案件管理` → PARSE_ERROR」という現行仕様の記載を、対応版取り込み時に
更新するとのことでした——その時が来ました。**v3.37.0 では同じ SQL が
（マッピングがあれば）動き、（無ければ）`is not defined` の名前入りエラーになります。

## 4. あわせて修正（B108）

`EXPLAIN` を文として実行したときの論理アプリ表示が、内部の仮想 ID
（`APP900000000`）ではなく**論理名の併記**（`LAPP_案件管理@dev`）になりました。
設定画面で EXPLAIN 結果を見せる場合、利用者が書いた論理名と表示が一致します。
