# 本文（送付版）

## 【返信】§3 のご指摘で実装しました — **v3.34.1 でカナリアクエリは不要になります**

**「要望ではありません。判断材料としてお伝えするだけです」**と書かれていましたが、
**判断が変わりました。**

**`_meta` が読めないクライアントにとって、内容レベルの版数が唯一届く経路になる**——
**そのとおりでした。**こちらは `_meta` が届く前提で「解決済み」と考えており、
**届かない立場を勘定に入れていませんでした。**

---

## 1. `instructions` の 1 行目に版数を出します

**v3.34.1 から、MCP サーバーの `instructions` はこう始まります。**

```
kSQL MCP server version 3.34.1.

kSQL is a SQL-like dialect for kintone, not generic SQL. ...
```

**`instructions` は接続時にサーバーが返すもので、AI クライアントの文脈にそのまま入ります。**

| | |
|---|---|
| **`_meta` が読めなくても届く** | ツール結果の封筒ではなく、接続時の本文に載るため |
| **測るのはプロセスの版** | **その常駐プロセス自身が返す。**`grep` で見るディスクの版ではありません |
| **era を選ばない** | **v1 の `initialize` と v2 の `server/discover` の両方**に載ります |

**v1・v2 の両方のクライアントで実際に繋いで、1 行目に出ることを確認しました。**

---

## 2. **カナリアクエリは不要になります**

**ご用意いただいた 3 手のうち、(3) が置き換わります。**

| | v3.34.1 以降 |
|---|---|
| **(1) 更新したら再起動** | **引き続き有効。**これが確実です |
| **(2) `grep` で識別子を数える** | **引き続きディスクの版**。プロセスの版ではありません |
| **(3) カナリアクエリ** | **不要。**`instructions` の 1 行目で足ります |

**カナリアは正しい方法でしたが、実データが要り、版ごとに作り直しが必要でした。**
**1 行目を読むだけなら、その手間がありません。**

---

## 3. `ksql_docs` に出す案は、取り下げたままです

**ご理解いただいたとおり、`ksql_docs` は文書を返す tool なので、版数はそこに属しません。**
**`instructions` は「このサーバーは何者か」を伝える場所**なので、版数はそちらに置きました。

**取り下げた理由は変わっていません。**
**変わったのは「どこにも置かない」という結論のほう**です。

---

## 4. 限界も 1 つあります

**`instructions` は接続時に 1 回配られるだけです。**

**セッションの途中で MCP サーバーを再起動しても、
クライアントの文脈は古い `instructions` を持ったままになります。**

**再起動したら、クライアント側も繋ぎ直してください。**

---

## 5. **v3.34.1 で出ています**

```
npm i @rex0220/kintone-sql-tools@3.34.1
```

**更新後は MCP サーバーを再起動してください。**
**再起動しないと、この変更が入っていない版が答え続けます**——まさにこの機能が防ごうとしている状態です。

**再起動して 1 行目に `kSQL MCP server version 3.34.1.` が出れば、切り替わっています。**
