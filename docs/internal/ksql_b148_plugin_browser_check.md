## 0. なぜプラグインだけ別に測るのか

**engine の変更は `prod/js/desktop.js` へ自動で入ります**（`src/ui/desktop.ts` からの生成物）。
**「入っているか」は仕組みで担保済み**なので、**測るのは「どう見えるか」だけ**です。

| 測ること | なぜブラウザが要るか |
|---|---|
| **エラーが読める形で表示されるか** | 文字列は同じでも、**UI が途中で切る・改行を潰す**ことがある |
| **レコード API より前に止まるか** | **Network タブでしか見えない** |
| **示された移行 SQL をそのまま貼れるか** | **コピーできる形で出ているか**は UI 依存 |

---

## 1. 前提

1. **`ksql-plugin-v3.57.0.zip` を kintone のプラグイン画面から読み込む**
   （[v3.57.0 リリース](https://github.com/rex0220/kintone-sql-tools/releases/tag/v3.57.0) の添付）
2. **プラグイン画面でバージョンが `3.57.0` になっていることを確認**
3. **ブラウザの開発者ツールを開き、Network タブを表示**（`records.json` を見るため）
4. 対象アプリ＝**APP4228**（`製品名` / `個数` / `日付` / `入出庫区分`）と
   **APP4233**（サブテーブル `テーブル`・明細に `数値_0`）

> **プラグインは論理アプリ参照（`LAPP_`）に非対応**です。`APPnnnn` で書いてください。

## 2. エラーが読める形で出るか

**各 SQL を実行し、①エラーが表示されること ②本文が最後まで読めること を見る。**

### 2.1 `GROUP BY` あり — **書き換え例まで出る形**

```sql
SELECT 製品名, 個数, SUM(個数) AS 合計 FROM APP4228 GROUP BY 製品名
```

**期待**＝エラー。本文に次がすべて含まれ、**途中で切れていないこと**。

- `SELECT 式「個数」`
- `（APP4228、非グループ化依存: 個数）`
- `GROUP BY 製品名 の各グループでは`
- **`実行可能な書き換え例: 「SELECT 製品名, MIN(個数) FROM APP4228 GROUP BY 製品名」`**

> **いちばん見たいのは最後の 1 行**です。**保存クエリ・プラグイン利用者にとって、
> エラー文が唯一の移行案内**なので、**そこが切れていたら意味がありません。**

### 2.2 `GROUP BY` 無し — **説明文が変わる形**

```sql
SELECT 製品名, 個数, SUM(個数) AS 合計 FROM APP4228
```

**期待**＝エラー。**`GROUP BY がないため入力全体が1グループになり`** と書かれていること
（`GROUP BY 製品名 の各グループでは` **ではない**）。

### 2.3 `HAVING`

```sql
SELECT 製品名, SUM(個数) AS 合計 FROM APP4228 GROUP BY 製品名 HAVING 個数 > 0
```

**期待**＝エラー。**`HAVING 式`** で始まること（`SELECT 式` ではない）。

### 2.4 `SELECT *`

```sql
SELECT *, SUM(個数) AS 合計 FROM APP4228 GROUP BY 製品名
```

**期待**＝エラー。**`必要な grouping 列を明示して SELECT してください`**。

### 2.5 式の呼び名

```sql
SELECT DATE_FORMAT(日付,'%m') AS 月, SUM(個数) AS 合計 FROM APP4228 GROUP BY 製品名
```

**期待**＝**`SELECT 式「月」`**（別名で呼ぶ）。**「式」とだけ書かれていたら不合格。**

### 2.6 **内部語が出ていないこと**（全ケース共通）

**本文に `B65` や `Phase1` が出ていないこと。**
**末尾の `(reason=B65_NON_GROUPED_DEPENDENCY)` は機械可読の識別子なので、出ていて正常です。**

## 3. レコード API より前に止まるか

**§2 の各 SQL について、Network タブを見る。**

**期待**＝**`/k/v1/records.json`（および `/k/v1/records/cursor.json`）へのリクエストが 0 件。**

> **実行するたびに Network タブをクリアしてから**実行してください。
> **フォーム定義の取得（`/k/v1/app/form/fields.json`）は出ます。** それは正常です
> （**判定にフォーム定義が要る**ため）。**見るのはレコード取得だけ。**

**1 件でもレコード取得が出ていたら、それは仕様違反**です（R3 §7）。

## 4. 通り続けるものが通るか（**最重要の回帰**）

**エラーになってはいけません。値も従来どおりのはずです。**

```sql
-- 4.1 主用途（月次集計）
SELECT DATE_FORMAT(日付,'%Y-%m') AS 年月, SUM(個数) AS 出庫数
FROM APP4228 WHERE 入出庫区分 = '出庫' GROUP BY 年月
```
**期待**＝13 行（2025-08 〜 2026-08）。

```sql
-- 4.2 CASE の別名グループ化
SELECT CASE WHEN 個数 > 100 THEN '大' ELSE '小' END AS 区分, SUM(個数) AS 合計
FROM APP4228 GROUP BY 区分
```
**期待**＝2 行（大 48425 / 小 37013）。

```sql
-- 4.3 grouping 式を部分木に持つ式
SELECT YEAR(日付) + 1 AS 翌年, SUM(個数) AS 合計 FROM APP4228 GROUP BY YEAR(日付)
```
**期待**＝2 行（2026 / 38525、2027 / 46913）。

```sql
-- 4.4 キーから計算した式
SELECT 個数 + 1 AS 加算, SUM(個数) AS 合計 FROM APP4228 GROUP BY 個数
```
**期待**＝エラーにならない（先頭は 647 / 1292）。

```sql
-- 4.5 集計もグループ化も無い素の SELECT（ここが壊れたら重大）
SELECT 製品名, 個数, 日付 FROM APP4228 LIMIT 5
```
**期待**＝5 行。**B148 とは無関係に通ること。**

```sql
-- 4.6 ウィンドウだけ
SELECT SUM(個数) OVER () AS 総計 FROM APP4228 LIMIT 3
```
**期待**＝3 行（すべて 85438）。

```sql
-- 4.7 拡張 grouping（従来どおり）
SELECT 製品名, SUM(個数) AS 合計 FROM APP4228 GROUP BY ROLLUP(製品名)
```
**期待**＝製品ごとの行＋総計行。

## 5. サブテーブルの移行案（**リリース直前に直した箇所**）

**リリース前の最終チェックで、ここが親 APP を指しており「従うと壊れる助言」になっていました。**
**直っていることをブラウザでも確かめます。**

```sql
SELECT _pid, 数値_0, SUM(数値_0) AS 合計 FROM APP4233$テーブル GROUP BY _pid
```

**期待**＝エラー。本文に次があること。

- **`（APP4233$テーブル、非グループ化依存: 数値_0）`** ← **`APP4233` だけになっていたら不合格**
- **`実行可能な書き換え例: 「SELECT _pid, MIN(数値_0) FROM APP4233$テーブル GROUP BY _pid」`**

**次に、示された SQL をそのままコピーして貼り、実行する。**

```sql
SELECT _pid, MIN(数値_0) FROM APP4233$テーブル GROUP BY _pid
```

**期待**＝13 行返る（`_pid=1` → 2、`_pid=2` → 1）。

> **これが「従うと壊れる助言」を出していないことの確認**です。
> **コピーできる形で表示されているか**も、ここで分かります。

## 8. 不合格だったときの見方

| 症状 | 何が起きているか |
|---|---|
| **本文が途中で切れる** | UI の表示幅・行数制限。**engine ではなく UI の問題** |
| **レコード取得が出ている** | **検査位置が実行より後**。仕様違反（R3 §7） |
| **通るはずの形がエラーになる** | **偽陽性**。**最も重い**。SQL と本文をそのまま知らせてください |
| **サブテーブルの案内が `APP4233`** | プラグインが**古い bundle** を読んでいる可能性。版数を再確認 |
