## 1. 直したいこと

**集計の別名が、同じ `SELECT` 句の他の式が参照するフィールドを上書きする。**

```sql
SELECT DATE_FORMAT(日付,'%Y-%m') AS 年月, SUM(個数) AS 合計 FROM APP4228 GROUP BY 年月
  → 年月="2025-08"   ✅

SELECT DATE_FORMAT(日付,'%Y-%m') AS 年月, SUM(個数) AS 日付 FROM APP4228 GROUP BY 年月
  → 年月=""          ❌  別名を 合計 から 日付 に変えただけ
```

**エラーも警告も出ない。集計値は正しい。壊れるのは別の列だけ。**

## 2. 実測で確定している事実（**再導出せず、そのまま使うこと**）

**v3.57.0・実アプリ APP4228（製品名 / 個数 / 日付 / 入出庫区分・1000 レコード）。**

### 2.1 症状は式の種類で変わる

| 式の種類 | 別名を衝突させたとき | 衝突させないとき |
|---|---|---|
| 日付関数 `DATE_FORMAT(日付,'%Y-%m')` | **空になる** | `2025-08` |
| 算術 `個数 * 2` | **2584**（＝2 × 合計） | **1292**（＝2 × キー） |
| 文字列連結 `製品名 \|\| '-x'` | **`23429-x`**（合計を連結） | `食パン-x` |
| **`CASE`** `CASE WHEN 個数 > 100 …` | **`大`**（合計 783 で判定） | **`小`**（キー 27 で判定） |

**`CASE` は分類が反転する**（「小」を「大」と言う）。**空になるより悪い。**

### 2.2 グループが 1 件だと偶然合う

```
SELECT 製品名, 個数 * 2 AS 倍, SUM(個数) AS 個数 FROM APP4228 GROUP BY 製品名, 個数
  食パン  倍 2584  個数 1292   ← 2 件のグループ。誤り（正しくは 1292）
  牛乳    倍 1412  個数 706    ← 1 件のグループ。偶然一致
```

**集約が実際に集約したときだけ壊れる。小さなデータで試すと正しく見える。**

### 2.3 影響しないもの

- **`ORDER BY` の別名解決**（`ORDER BY` は別名優先。**言語リファレンス §8 の契約どおり**で本件ではない）
- **CTE の下流**（`WITH m AS (… SUM(個数) AS 個数) SELECT 個数 * 2 FROM m` は正しい）

## 4. 直し方の原則（**決まっている**）
