# B138 文書の構造検査を `npm test` に入れる（台帳の破損とリンク切れを検知する）

- 起票: 2026-08-06
- ステータス: ✅ **v3.51.0 でリリース**（2026-08-06）
- 同系: [B132](../ksql_issue_tracker.md)（`ksql_docs` のキー）／[B135](../ksql_issue_tracker.md)（`mcp:smoke` の期待値）／[B136](ksql_b136_language_reference_examples_issue.md)（文書の例）

---

## 1. なぜ要るか

**2026-08-06 に台帳を 2 回壊し、どちらも「静かに壊れた」。**

| 事故 | 原因 | どう見つけたか |
|---|---|---|
| **バッククォート消失** | `node -e "..."` の二重引用符内でシェルがコマンド置換として解釈し、`` `sql/`・`scripts/` `` を食った | **たまたまシェルがエラーを出した**。出なければ気づけなかった |
| **テーブルのセル数 10**（期待 7） | Edit の `new_string` に `|` を含めた。markdown の表では区切り文字 | **この検査を書いて初めて見つけた**（数時間気づかなかった） |

**2 件目は目視では見つかっていない。** 台帳の 1 行が 4,000 字あり、
表として描画されたときに列がずれても誰も気づかなかった。

**B135 の教訓がそのまま当てはまる**＝`mcp:smoke` は存在したが `npm test` に入っていなかったので、
3 版にわたり失敗し続けても誰も気づかなかった。**検査はゲートに入っていなければ効かない。**

---

## 2. 実測（2026-08-06）

試作した検査を `docs/` 全体に当てた結果。

### 2.1 台帳の行構造

| 検査 | 結果 |
|---|---|
| セル数（期待 7） | **1 件違反**（B129 の行が 10）→ 修正済み |
| バッククォートの偶奇 | 違反なし |
| 空欄化の痕跡（`＝・` など） | 違反なし |

### 2.2 相対リンク

**3,214 件中 184 件が切れている。** 内訳:

| 種別 | 件数 | 直し方 |
|---|---|---|
| **深さ違い**（`docs/internal/` から `../src/...` と書いている。正しくは `../../src/...`） | **177** | **機械的に直る** |
| 文書参照 | 6 | 個別に判断 |
| その他 | 1 | 個別に判断 |

**切れているファイルは 11 本だけ**で、上位 4 本（`perf-sql-execution-implementation-plan.md` 56 件 /
`perf-sql-execution-improvements.md` 41 件 / `cli-code-guide.md` 34 件 /
`sql-execution-flow.md` 20 件）で 151 件を占める。

**つまり「あちこちが少しずつ腐っている」のではなく、
数本の文書が最初から間違った深さで書かれている。**

## 3. 対応案

### 案 A（推奨）: `docs:check` を作り `npm test` に入れる

検査項目（試作済み・いずれも実測で有効性を確認）:

1. **台帳の課題行のセル数**が 7 であること
2. **バッククォートが偶数**であること
3. **相対リンクの参照先が存在する**こと
4. （任意）**空欄化の痕跡**（`＝・` / `（）` / `「」` / 連続する空セル）が無いこと

**前提作業**＝リンク切れ 184 件を 0 にする。**177 件は機械的**、残り 7 件は個別判断。

### 案 B: 台帳を JSON にする

**セル数の事故は完全に防げるが、バッククォート消失は防げない**
（書き込み経路の問題であり格納形式と無関係。**文字列値の一部が消えても `JSON.parse` は通る**）。
加えて**表として読めなくなる**ため Markdown 生成が要り、
**生成側と表示側の二重管理**という B132 / B135 / B136 で繰り返し踏んだ形を新たに持ち込む。

**採らない。** ただし「表として読む」より「機械で保証する」を優先する判断はあり得る。
その場合は **JSON を単一の正とし、Markdown は生成物として扱う**（コミットしないか、
生成の一致をテストで固定する）ことが条件。

### 案 C: 文書化のみ

**採らない。** 今日の 2 件はどちらも規律を守るつもりで踏んでいる。

## 4. 併せて行う整理（別課題）

**今日の 2 件はどちらも「4,000 字の 1 行を書き換えた」ことで起きた。**
台帳の運用ルールには既にこう書いてある。

> **本書は一覧（インデックス）**。仕様・診断・受入条件などの本文は各文書に置く。

**このルールが守られていない。** 行が 200 字なら Edit で安全に置換でき、
`|` の混入も目で分かる。

**効果は実証済み**＝v3.49.0 のリリースで B129 と B130 の巨大行が抜けただけで、
**最長行は 4,030 → 1,700 字に落ちた**。

検査（本件）と整理は独立して進められる。**整理は別途行う。**
