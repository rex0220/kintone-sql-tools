# 本文（送付版）

## 【報告】`HAVING` のウィンドウ別名参照は v3.85.0 で実行前に止まります（B193）

```
npm i @rex0220/kintone-sql-tools@3.85.0
```

v3.84.0 の取り込みと Ver.2 の出荷、ありがとうございます。B184 / B191 を実データで 3 段形と突き合わせていただいた確認は、こちらの受入条件と同じ形で、心強いです。

ご報告の 1 件は再現し、こちらの欠陥として修正しました。

### 再現（こちらの dev・SFA パック）

```sql
SELECT 会社名, SUM(売上) AS 売上合計, RANK() OVER (ORDER BY SUM(売上) DESC) AS 順位
FROM APP4149
GROUP BY 会社名
HAVING 順位 <= 5
```

- `HAVING 順位 <= 5` → 10 行すべて（順位 1〜9）、エラーも警告もなし
- `HAVING 順位 = 1` → 0 行

ご報告どおりです。**CHANGELOG v3.81.0 の「`HAVING` でのウィンドウ参照は従来どおり拒否」は正確ではありませんでした。** 拒否していたのは `HAVING SUM(x) OVER () > 0` のようにウィンドウ**式**を直接書いた形だけで、**別名経由の参照**は検査を素通りしていました。集計依存の検査が `HAVING` の別名をその定義式の依存（`RANK() OVER (ORDER BY SUM(売上) DESC)` の中身＝集計式）で判定していたためです。実行時の `HAVING` はウィンドウより先に評価されるので、その時点で別名の値は無く、空文字との比較になっていました（`'' <= 5` は真、`'' = 1` は偽）。

### 修正（v3.85.0）

`HAVING` の未修飾名が同じ SELECT のウィンドウ列の別名に解決されたら、静的検証・EXPLAIN・実行のすべてで実行前に止めます。

```text
ArgumentError: HAVING からは同じ SELECT のウィンドウ関数の結果（別名 順位）を参照できません。HAVING はウィンドウより先に評価されます。WITH で段を分け、次の段の WHERE で絞ってください (reason=HAVING_WINDOW_ALIAS)
```

- **結果が変わる形**: `HAVING` にウィンドウ別名を書いた文だけ（v3.81.0〜v3.84.0 は静かに全件／0 件、修正後はエラー）
- **変わらない形**: 集計別名・集計式・グループキーの `HAVING`、`WITH` で段を分けて次の段の `WHERE` で絞る形、文レベルの `ORDER BY 順位`（ウィンドウの後に評価されるので可）
- Pro の設定画面の構文チェックは静的検証と同じ経路なので、取り込めば同じ文で止まります

Pro 側の対処（確認用 JSON に「止まらない形」として置く、レシピ集は「順位で絞るときは CTE で段を分ける」）は、修正後もそのまま正しい書き方です。「止まらない形」の記述だけ、取り込み後に「実行前に止まる」へ戻していただければ足ります。
