> **この回で読めるようになる SQL**
>
> ```sql
> SELECT 会社名, 顧客ランク FROM APP4148 WHERE 顧客ランク = 'A'
> ```
>
> - `FROM` どのアプリから、`WHERE` どの行を、`SELECT` どの列を。読む順番はこの 3 つです
> - 依頼文は「顧客ランクが A の会社を出して」。Claude が書き、あなたはプラグインで実行します

前回（[第 0 回: シリーズの狙いと準備](https://qiita.com/rex0220/items/XXXXXXXX)）で、
SFA（営業支援）パック・kSQL プラグイン・Claude Desktop の準備をしました。
今回から SQL を読みます。最初は一番短い形、「あるアプリから、条件に合う行の、いくつかの列を出す」です。

## 0. まず眺める — `SELECT *`

Claude に頼む前に、自分の目でアプリの中身を見ておきます。kSQL プラグインの実行画面で次を実行してください
（`APP4148` は、あなたの顧客管理のアプリ番号に読み替えます。以下同じです）。

```sql
SELECT * FROM APP4148 LIMIT 5
```

- `SELECT *` … 全部の列
- `FROM APP4148` … 顧客管理から
- `LIMIT 5` … 5 行まで（「どの 5 件を先に出すか」は指定していません。今回は中身を眺めるだけなので、それで構いません）

<!-- 図: プラグインで SELECT * FROM APP4148 LIMIT 5 を実行した結果。列が横に長く続いている -->

顧客管理には 20 個以上のフィールドがあるので、表が横に長くて読めません。
**ここで「列を絞りたい」「行を絞りたい」という気持ちになる**のが、この回の出発点です。
kSQL プラグインの記事にある「最初は `SELECT *` で全体を把握、次に列を絞る、最後に `WHERE` を足す」という順番そのものです。

## 1. Claude に依頼する

Claude Desktop で新しい会話を開き、最初に**共通の前置き**を貼ります（シリーズを通して毎回同じものです）。

```text
このチャットでは kSQL MCP を使って kintone 用の SQL を書いてもらいます。約束は 4 つです。
1. SQL は書いて ksql_validate で検証するだけにしてください。ksql_query で実行しないでください（実行は私がプラグインで行います）
2. フィールドコードは推測せず、必ず ksql_describe_app で確認してから使ってください
3. 完成した SQL は、そのまま貼れるように SQL だけのコードブロックで見せてください
4. そのあとに、SQL の各句（SELECT / FROM / WHERE …）が何をしているかを 1 行ずつ説明してください
5. 依頼していない列・条件・並べ替えは追加しないでください
```

5 番は「まだ習っていない句を混ぜないでほしい」という約束です。それでも `ORDER BY` のような見慣れない句が付いてきたら、
「今回は並べ替えなしで書き直して」と頼んでください。

続けて、この回の依頼文を打ちます。

```text
顧客管理は APP4148 です。顧客ランクが A の会社を、会社名と顧客ランクの 2 列で出してください。
```

Claude は `ksql_describe_app` で顧客管理のフィールド一覧を取り、SQL を書いて `ksql_validate` にかけ、SQL と説明を返します。

## 2. Claude が書いた SQL

私の環境ではこう返ってきました（ある回の一例です。改行の位置や説明の言い回しは、あなたの Claude では違うかもしれません）。

```sql
SELECT 会社名, 顧客ランク
FROM APP4148
WHERE 顧客ランク = 'A'
```

Claude の説明はだいたいこうでした。

> - `SELECT 会社名, 顧客ランク` — 表示する列を会社名と顧客ランクの 2 つに絞ります
> - `FROM APP4148` — 顧客管理アプリ（APP4148）を対象にします
> - `WHERE 顧客ランク = 'A'` — 顧客ランクが「A」のレコードだけに絞り込みます

このコードブロックをコピーして、kSQL プラグインの実行画面に貼り、実行してください。

## 3. 句ごとに読む — 順番は FROM → WHERE → SELECT

SQL は上から書いてありますが、**読むときは `FROM` から**です。「どこから」「どの行を」「どの列を」の順に頭に入れると迷いません。

| 順 | 句 | 読み方 | この SQL では |
| :-: | :--- | :--- | :--- |
| 1 | `FROM APP4148` | **どのアプリから** | 顧客管理から |
| 2 | `WHERE 顧客ランク = 'A'` | **どの行を** | 顧客ランクが A の行だけ |
| 3 | `SELECT 会社名, 顧客ランク` | **どの列を** | 会社名と顧客ランクの 2 列 |

`WHERE` が無ければ全行、`SELECT *` なら全列です。つまり第 0 節の `SELECT * FROM APP4148` は「顧客管理の、全行の、全列」でした。

### 結果

以下の件数と会社名は、この記事で使った初期サンプルデータ（顧客 9 件）での結果です。
自分の環境で違う場合は、kintone の一覧との突き合わせを正としてください。この注記は、この回のすべての件数に当てはまります。

ランク A は 3 件です。

| 会社名 | 顧客ランク |
| :--- | :--- |
| 株式会社サイボウズ商事 | A |
| 株式会社キントーンシステムズ | A |
| 平川ファイナンスサービス株式会社 | A |

3 社が出ることが大事で、表示される順番は環境によって違うことがあります。この SQL には並び順の指定が無いためです。
順番を決める `ORDER BY` は次回扱います。

**突き合わせ**: 顧客管理の一覧を開き、顧客ランクで「A」に絞り込んでください。同じ 3 社が出ます。
一覧の絞り込みと `WHERE` は、やっていることが同じです。違いは、`WHERE` は文字で書けるので**あとから読み返せて、人に渡せる**ことです。

## 4. kintone 方言メモ

> **ラベルとフィールドコードは別物。SQL に書くのはフィールドコード**
>
> kintone のフォームで見えている名前は「ラベル」で、SQL に書くのは「フィールドコード」です。
> 顧客管理では、ラベル「〒」のフィールドコードは `郵便番号`、ラベル「顧客No.」のフィールドコードは `顧客No`（末尾のピリオド無し）です。
> 会社名や顧客ランクのように両方が同じ場合もあるので、普段は気になりません。気になるのは違うときだけです。
>
> Claude が毎回 `ksql_describe_app` を呼んでいるのは、このためです。あなたが確かめたいときは、プラグインで次を実行すると一覧が出ます。
> Claude が裏で見ているのと同じ情報です。
>
> ```sql
> DESCRIBE APP4148
> ```

> **文字は `'` で囲む。数値は囲まない**
>
> 会社名やランクのような文字の値は `'A'` のようにシングルクォートで囲みます。
> 次回以降に出てくる売上のような数値は `WHERE 売上 >= 1000000` のように、囲まずに書きます。

> **`ksql_validate` は「構文と静的検査」。フィールドの実在は実行時に分かる**
>
> `ksql_validate` は kintone に接続せず、SQL の構文と、SQL だけから静的に判断できる範囲を検査します。kintone のフォーム定義は読みません。
> そのため Claude が `ランク` という存在しないフィールドコードを書いても、SQL の形として成立していれば `ok: true` になります。
> プラグインで実行すると、フォーム定義との照合で初めてエラーになります。
>
> ```text
> ArgumentError: WHERE predicate is unsupported (field=ランク, operator==, reason=WHERE_FIELD_UNRESOLVED).
> ```
>
> 「検証を通った」と「動く」は別です。**最後に確かめるのは、いつも実行結果です。**

## 5. 自分で 1 箇所変える

ここからが本番です。**変える前に結果を予想して、それから実行**してください。
予想が当たれば読めています。外れたら、どの句を読み違えたかが分かります。

### 変更 1: `'A'` を `'B'` にする

```sql
SELECT 会社名, 顧客ランク
FROM APP4148
WHERE 顧客ランク = 'B'
```

予想: 何件出るでしょうか。一覧をランク B で絞り込めば分かります。

実行結果は 3 件（株式会社倉本インターナショナル、篠村食品株式会社、株式会社橘川ケミカル）。
文字を囲む `'`（シングルクォート）を落とすとエラーになります。**文字の値は `'` で囲む**、が SQL の約束です。

### 変更 2: 表示する列に `都道府県` を足す

`SELECT` だけを変えます。`WHERE` はそのままです。

```sql
SELECT 会社名, 顧客ランク, 都道府県
FROM APP4148
WHERE 顧客ランク = 'A'
```

予想: 行数は変わるでしょうか。列数はどうなるでしょうか。

実行結果は 3 件のまま、列が 2 列から 3 列になります。**`SELECT` を変えても行は増減しません。行を決めるのは `WHERE` です。**

### 変更 3: 条件を `AND` で足す

今度は `WHERE` だけを変えて、「ランク A **かつ** 東京都」にします。

```sql
SELECT 会社名, 顧客ランク, 都道府県
FROM APP4148
WHERE 顧客ランク = 'A' AND 都道府県 = '東京都'
```

予想: ランク A の 3 社のうち、東京都の会社は何社でしょうか。変更 2 の結果を見れば分かります。

実行結果は 1 件（株式会社サイボウズ商事）。`AND` は「両方を満たす行だけ」です。
変更 2 で `都道府県` を表示に足しておいたので、この 1 件が正しいことを目で確かめられます。
**絞り込みに使う列を先に表示に足しておく**のは、SQL を読む人の基本の癖です。

### 変更 4: 存在しない値にする

```sql
SELECT 会社名, 顧客ランク
FROM APP4148
WHERE 顧客ランク = 'Z'
```

予想: エラーになるでしょうか、0 件でしょうか。

実行結果は **0 件で、エラーになりません**。「条件に合う行が無い」は正常な結果です。
AI に集計を任せたとき、「0 件でした」が「本当に無い」のか「条件を書き間違えた」のか、SQL を読まないと区別できません。
これが第 0 回で書いた「読める人が要る」の、いちばん身近な例です。

## 6. 宿題

依頼文だけ出します。**Claude に打つ前に**、`FROM` に何が来て、`WHERE` に何が来て、`SELECT` に何が来るかを自分で予想してください。
それから Claude に書かせて、予想と突き合わせ、プラグインで実行します。

```text
顧客管理は APP4148 です。業種が「金融業」の顧客の、会社名と電話番号を出してください。
```

ヒント: 業種のフィールドコードは `業種`、電話番号は `電話番号` です。サンプルデータでは 2 件出ます。
