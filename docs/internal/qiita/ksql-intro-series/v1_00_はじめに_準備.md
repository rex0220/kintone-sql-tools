> **このシリーズで身につくこと（3 行）**
>
> - SQL を**ゼロから書く**必要はありません。書くのは Claude です
> - 身につけるのは、Claude が書いた SQL を**読んで、何をしているか説明できて、1 箇所変えて結果を予想できる**力です
> - 題材は kintone 公式のサンプルアプリ「SFA（営業支援）パック」。結果は kintone の一覧やグラフ、元のレコードと突き合わせられます

## はじめに — なぜ「読める」だけで得なのか

kintone のデータを「顧客ごとの受注合計」「月別の商談件数」のように集計したいとき、
一覧とグラフの機能で足りる場面と、足りない場面があります。
複数のアプリをまたぐ集計や、「案件が 1 件も無い顧客」のような**無いものを数える**集計は後者です。

こういう集計は SQL なら 1 文で書けます。そして今は、その 1 文を AI が書いてくれます。
私は kintone を SQL 風の構文で操作する
[`kintone-sql-tools`](https://github.com/rex0220/kintone-sql-tools)（kSQL）を開発していて、
Claude Desktop から kintone に SQL を投げる構成を日常的に使っています。
[AI エージェントに kintone を操作させるには SQL が最適解である](https://qiita.com/rex0220/items/fbed33b11251cdf7e31e) という記事で、
その理由を「1 文 = 1 意図で、実行前に人間が読んでレビューできるから」と書きました。

ただ、この主張には前提があります。**人間が SQL を読めること**です。

AI が書いた SQL を読めない状態で使うのは、「AI がやったと言っているから正しいのだろう」と
結果を鵜呑みにするのと同じです。
AI は間違えます。実際に私は、AI が自信満々に**存在しない構文を発明した**場面も、
`ksql_validate` は通るのに**意味がずれた SQL** を書いた場面も観測しています
（[構文を「発明」する話](https://qiita.com/rex0220/items/4d9fc0ed48ebd5b32a7b)／
[30 シナリオの検証ループ](https://qiita.com/rex0220/items/7f229c87a20f2d45777c)）。

逆に言えば、SQL を読めれば AI の誤りに気づきやすくなり、集計を任せる運用の安全性を大きく高められます
（読めるだけで万全ではありません。フィールドの取り違えや取得上限のような、読むだけでは分からない点は、
このシリーズの中で実行系に確かめさせる手順として扱います）。
そして「読む」は「書く」よりずっと簡単です。
このシリーズは、SQL を書いたことのない kintone 担当者が、**AI が書いた SQL を読んでレビューできる**ところまでを目標にします。

## シリーズの学び方

毎回、同じ流れで進めます。

1. **依頼文**を Claude Desktop に打つ（例: 「ランク A の顧客を出して」）
2. Claude が書いた **SQL** を見る
3. SQL を**句ごとに読み解く**（`SELECT` は何を、`WHERE` は何を、の単位）
4. **kintone 方言メモ** — 一般的な SQL と違う kintone 固有の点を、毎回同じ体裁で 1〜2 個だけ
5. **自分で 1 箇所変える** → 実行する前に結果を予想する → kSQL プラグインで実行する → kintone の一覧・グラフや元のレコードと突き合わせる
6. **宿題** — 依頼文だけ出します。Claude に書かせる**前に**「`SELECT` に何が来て `WHERE` に何が来るか」を自分で予想し、
   Claude の SQL と突き合わせます。書けそうなら自分で書いてから Claude に添削させても構いません

### 書くのは Claude、実行するのはプラグイン

道具は 2 つ使い、役割を分けます。

| 役割 | 道具 | 理由 |
| :--- | :--- | :--- |
| SQL を書く・句の意味を説明する・質問に答える | **Claude Desktop + kSQL MCP** | フィールドの定義を自分で調べ、言語リファレンスを自分で引いて答えられる |
| SQL を実行して結果を見る・1 箇所変えて試す | **kSQL プラグイン**（kintone 画面内・無償） | 自分の手で SQL を触る場所が要る。結果が加工されずに表で出る。隣のタブの一覧や元のレコードと突き合わせられる |

Claude に「実行して」と頼めば実行もしてくれます。でもこのシリーズでは、**結果を見るのはプラグイン側**に固定します。

> **このシリーズの一番大事な約束**
>
> - **集計結果の数字は AI の口から聞かない。実行結果を自分の目で見る。** AI は結果を要約して伝えることがあり、行数や合計を言い間違えることがあります
> - **変えた SQL は自分で実行する。** ここを AI に頼むと「AI に書き換えてもらう」に戻り、読む力が付きません

### 掲載する SQL について

記事の SQL は「ある回の Claude の一例」です。同じ依頼文を打っても、あなたの Claude は別の書き方をするかもしれません。
それで構いません。目標は同じ SQL を再現することではなく、**出てきた SQL を読めること**です。

掲載する SQL はすべて `ksql_validate` で検証し、サンプルアプリで実行して結果を確認したものです。

## 準備

必要なものは 4 つです。道具はすべて無償です。
kintone を契約していない場合も、学習・開発目的に限り、無料の
[kintone 開発者ライセンス](https://cybozu.dev/ja/kintone/developer-license/) で環境を用意できます（本番利用は不可）。
本番環境ではなく、サンプルデータを入れた学習用の環境で進めることをお勧めします。

1. kintone 環境と、サンプルアプリ「SFA（営業支援）パック」
2. kSQL プラグイン（kintone 画面内で SQL を実行する）
3. Claude Desktop と kSQL MCP（Claude に SQL を書かせる）
4. 動作確認

### 1. サンプルアプリ「SFA（営業支援）パック」を入れる

kintone アプリストアの「SFA（営業支援）パック」（旧称: 営業支援パック）を追加します。
スペースの「kintone アプリストア」から「営業・セールス」カテゴリーで見つかります。

- **「サンプルデータを含める」のチェックはオンのまま**「このアプリパックを追加」を押してください。
  データが無いと集計の練習になりません
- 顧客管理・担当者管理・案件管理・活動履歴の **4 アプリ**ができます

![2026-09-10_16h59_16.png](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/100572/710c7113-5a16-44e6-b05e-e8260a5b6bd6.png)

このシリーズの SQL は、私の環境のアプリ番号で書いています。**あなたの環境では別の番号になる**ので、
アプリの URL（`/k/1234/` の数字）を控えて読み替えてください。

| アプリ | 記事中の表記 | 自分の環境 |
| :--- | :--- | :--- |
| 顧客管理 | `APP4148` | `APP____` |
| 案件管理 | `APP4149` | `APP____` |
| 活動履歴 | `APP4147` | `APP____` |
| 担当者管理 | `APP4150` | `APP____` |

もう 1 つ注意があります。サンプルデータの日付は、導入した環境によって記事と異なる場合があります
（私の環境と、アプリストアの説明画像とで年が違います）。
記事で「4 月にデータが無い」のように書いても、あなたの環境では別の月かもしれません。
そのため各回では、必ず「まず自分の環境で実行して確かめる」手順を入れます。

### 2. kSQL プラグインを入れる

kintone の画面内で SQL を実行し、結果を表で見るためのプラグインです。ログイン中のユーザー権限で動くので、API トークンなどの設定は要りません。

- 入手: [v3.77.0 の release フォルダ](https://github.com/rex0220/kintone-sql-tools/tree/v3.77.0/release) から
  `ksql-plugin-v3.77.0.zip`（プラグイン本体）と `ksql-app-template-v1.11.0.zip`（専用アプリのテンプレート）
- 手順: kintone のプラグイン画面で zip を読み込む → テンプレートから専用アプリを作る（設定済みなので追加設定なし）
- 使い方（実行画面・結果の表・表示オプション）は
  [rex0220 kSQL プラグイン](https://qiita.com/rex0220/items/ed9e101cb28b0ed40869) を参照してください

### 3. Claude Desktop に kSQL MCP を入れる

Claude に kintone のアプリ構造を調べさせ、SQL を書かせるための MCP サーバーです。
Claude Desktop の拡張機能（`.mcpb` ファイル）として入れるので、Node.js のインストールは要りません。

手順は [kSQL MCPB Claude Desktop インストール手順](https://qiita.com/rex0220/items/f3942613edf943593270) のとおりです。
このシリーズ向けに補足する点だけ書きます。

**API トークンはアプリごとに 4 本発行します。** kSQL はアプリごとに REST API を呼ぶので、
結合（第 4 回）で 2 つのアプリを使うなら両方のトークンが要ります。
権限は「レコード閲覧」だけで十分です（このシリーズは読み取りしかしません）。

`ksql.config.json` の `tokenMap` にはこう書きます（番号はあなたの環境に読み替えてください）。

```json
{
  "version": 1,
  "defaultProfile": "learn",
  "profiles": {
    "learn": {
      "baseUrl": "https://example.cybozu.com",
      "auth": "token",
      "tokenMap": {
        "APP4147": "env:KSQL_TOKEN_KATSUDO",
        "APP4148": "env:KSQL_TOKEN_KOKYAKU",
        "APP4149": "env:KSQL_TOKEN_ANKEN",
        "APP4150": "env:KSQL_TOKEN_TANTO"
      }
    }
  }
}
```

`env:KSQL_TOKEN_ANKEN` は API トークンそのものではなく、**Windows のユーザー環境変数の名前**です。
4 本のトークンを対応する環境変数に登録し（登録方法は上のインストール手順記事の「4. API トークンを環境変数に設定」）、
そのあと **Claude Desktop を完全に終了して再起動**してください。再起動しないと、新しく登録した環境変数が読み込まれません。

**版を揃えてください。** プラグイン・MCPB とも **v3.77.0 以降**を使います。
このシリーズでは比較的新しい構文（第 7 回の `GENERATE_SERIES` など）を使うので、片方が古いと途中で動かなくなります。
今つながっている MCP が何版かは、Claude に「`ksql_docs` を引数なしで呼んで」と頼むと索引の先頭行で分かります。

**Claude のプランについて。** Claude Desktop のローカル拡張機能は**無料プランでも使えます**
（2026 年 9 月時点。リモート MCP のカスタムコネクタも無料プランから 1 個まで使えますが、このシリーズでは使いません）。
ただし無料プランには**セッション単位の利用上限**があり、利用枠は 5 時間ごとにリセットされます。
MCP を使う会話も、この利用上限の対象です。
**1 回分の学習を 1 つの会話に収める**、**実行はプラグイン側で行う**という本シリーズの進め方は、この点でも無駄がありません。

### 4. 動作確認

プラグインと Claude を、それぞれ 1 回ずつ動かします。

**プラグイン**: 専用アプリの実行画面で、案件管理に対して次を実行します。

```sql
SELECT * FROM APP4149 LIMIT 5
```

案件が 5 件、表で出れば成功です。`APP4149` はあなたの案件管理の番号に読み替えてください。
`SELECT *` は「全部の列」、`LIMIT 5` は「5 行まで」です。第 1 回で詳しく読みます。

**Claude Desktop**: チャットに次のように打ちます。

```text
kSQL MCP の ksql_validate で SELECT 'ok' AS result を検証して
```

Claude が `ksql_validate` を呼び、`ok: true` と返れば成功です。
これは kintone には接続せず、MCP が動いているかだけを確かめる手順です。
続けて次を打つと、kintone への接続まで確認できます（`4149` は読み替えてください）。

```text
kSQL MCP の ksql_describe_app で APP4149 のフィールド一覧を見せて
```

案件名・会社名・商談フェーズ・売上・受注予定日といったフィールドが並べば準備完了です。
この `ksql_describe_app` は、第 1 回以降で Claude が「フィールドコードを調べる」ために毎回使う道具です。

## kintone 方言メモとは

kSQL は「kintone 方言」の SQL です。日常の集計で使う `SELECT` / `WHERE` / `GROUP BY` / `JOIN` はごく普通の SQL ですが、
kintone がデータベースではない以上、どうしても一般的な SQL と違う点が出ます。
たとえば、文字の並び順は Unicode のコードポイント順で日本語の辞書順ではありません。
数値の空セルは、足し算では 0 として扱われます。

こうした点は、各回の本文に混ぜず、**「kintone 方言メモ」**という同じ見出しの枠に切り出して書きます。
「ここは一般の SQL と違う」と分かる形にしておけば、将来ほかの SQL を読むときにも混乱しません。

## シリーズの目次

| 回 | テーマ | 依頼文の例 |
| :-: | :--- | :--- |
| 0 | この記事 — 狙いと準備 | — |
| 1 | 絞り込み — `SELECT` と `WHERE` | 「ランク A の顧客を出して」 |
| 2 | 並べ替えと上位 N — `ORDER BY` と `LIMIT` | 「売上が大きい案件 5 件」 |
| 3 | 集計 — `GROUP BY` と `HAVING` | 「商談フェーズ別の売上合計」 |
| 4 | 結合 — `JOIN` | 「顧客ごとの受注合計」 |
| 5 | 条件分岐 — `CASE WHEN` | 「会社別に、フェーズごとの売上を列に分けて」 |
| 6 | 中間結果に名前を付ける — `WITH`（一時テーブルとの違い） | 「上位顧客の担当者別内訳」 |
| 7 | 月別集計と無い月の 0 埋め — `GENERATE_SERIES` | 「月別の初回商談件数を出して」 |
| 8 | 実行前に見る — `EXPLAIN` と押し下げ | 「この SQL は kintone に何をする？」 |
| 9 | 仕上げ — 学んだ SQL をダッシュボードに並べる | — |

1〜4 回で SQL の基本（抽出・並べ替え・集計・結合）、5〜7 回で kintone の集計で現場が一番困る形
（条件付きの集計、中間結果の扱い、日付軸の 0 埋め）を扱い、第 7 回はそれまでの全部を使う応用回です。
第 8 回で「その SQL が kintone に何をするか」を実行前に見る方法を覚え、
最終回では、それまでに読んだ SQL をそのまま無償の
[kSQL Dashboard プラグイン](https://qiita.com/rex0220/items/9cc28b6d52913a533360) に貼って、
1 画面のダッシュボードにします。「AI が書いた SQL が、AI 抜きで毎日動く資産になる」ところまでがこのシリーズの範囲です。

次回は第 1 回「絞り込み」です。まずプラグインで `SELECT *` を打ってアプリの中身を眺めるところから始めます。
