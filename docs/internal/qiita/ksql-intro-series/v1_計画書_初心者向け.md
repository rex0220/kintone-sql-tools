## 1. 位置づけ

既存の公開記事（紹介・仕組み・AI エージェント論・構文の教え方・検証ループ）はすべて
エンジニアか AI 設計者向け。**SQL を知らない kintone 担当者**向けの記事は無い。
本シリーズはその層に向け、「Claude が書いた SQL を読めるようになる」ことを目標に置く。

- 読者像: SQL 未経験の kintone 担当者（アプリ管理権限があり、自分の環境にサンプルアプリを作れる）
- 到達点: Claude が書いた SQL の各句が何をしているか説明でき、1 箇所変えて結果を予想できる
- 主張の接続: AI エージェント記事の「1 文 = 1 意図でレビューできる」「AI の成果物が AI 抜きで回る資産になる」を読者自身が体験する

## 3. 各回のテンプレート

毎回同じ構成にする。

1. 依頼文（日本語。読者が Claude に打つ文）
2. Claude が書いた SQL（ある回の一例と明記。再現ではなく読む力が目標）
3. 句ごとの読み解き
4. **kintone 方言メモ**（標準 SQL と違う点だけを毎回同じ体裁で隔離）
5. 自分で 1 箇所変える課題 → 実行前に結果を予想 → プラグインで実行 → kintone の一覧・グラフや元レコードと突き合わせる（外部結合や 0 埋めは標準グラフに同じ結果が出ないので「答え合わせ」とは言わない）
6. 宿題（依頼文だけ出す。Claude に書かせる**前に**「SELECT に何が来て WHERE に何が来るか」を予想し、Claude の SQL と突き合わせる。書けるなら自分で書いて添削させてもよい。「書くのは Claude」の約束と矛盾しない形にする）
7. （末尾一行）この SQL が返す形（ラベル＋値 or 表）と、無償版ダッシュボードでどう見えるか

掲載する SQL はすべて `ksql_validate` で検証し、サンプルパックで実行して結果を確認する
（AI エージェント記事と同じ作法）。

## 5. 第 7 回（月別 0 埋め）の SQL（2026-09-10 実機確認済み・APP4149 案件管理 20 件）

### 5.1 題材は「初回商談日」にする

サンプルパックの日付分布（実測）:

| 軸 | 値のある月 | 途中の歯抜け |
| :--- | :--- | :--- |
| 受注予定日 | 2026-02〜2026-10 に毎月 | **なし**（抜けるのは端の 1 月・11 月・12 月だけ）。空セル 4 件 |
| 初回商談日 | 2025-11, 2026-01, 02, 03, 05, 06, 07 | **2025-12 と 2026-04** |

「GROUP BY したら月が飛んだ」を途中の月で見せられるのは初回商談日なので、依頼文は
**「月別の初回商談件数を出して」**にする。受注予定日は第 3 回（集計）の題材に回す。

### 5.2 段階 1: GROUP BY だけ（7 行。12 月と 4 月が無い）

```sql
SELECT DATE_FORMAT(初回商談日, '%Y-%m') AS 年月, COUNT(*) AS 件数
FROM APP4149
GROUP BY DATE_FORMAT(初回商談日, '%Y-%m')
ORDER BY 年月
```

### 5.3 段階 2: 月系列に LEFT JOIN（9 行。12 月と 4 月が 0）

```sql
WITH 月系列 AS (
  GENERATE_SERIES('2025-11-01', '2026-07-01', '1 month') AS 月初
),
月キー AS (
  SELECT DATE_FORMAT(月初, '%Y-%m') AS 年月 FROM 月系列
),
月別 AS (
  SELECT DATE_FORMAT(初回商談日, '%Y-%m') AS 年月, COUNT(*) AS 件数
  FROM APP4149
  GROUP BY DATE_FORMAT(初回商談日, '%Y-%m')
)
SELECT s.年月,
       CASE WHEN a.件数 = '' THEN 0 ELSE a.件数 END AS 商談件数
FROM 月キー s
LEFT JOIN 月別 a ON s.年月 = a.年月
ORDER BY s.年月
```

実測結果: 2025-11=1, **2025-12=0**, 2026-01=2, 02=1, 03=1, **04=0**, 05=2, 06=5, 07=8。

### 5.4 実機で分かったこと（方言メモと本文に反映する）

- **`ON` 句に関数は書けない。** `ON DATE_FORMAT(s.月初, '%Y-%m') = a.年月` は ParseError
  （「フィールド名またはテーブル名が必要です」）。年月キーは CTE（上の `月キー`）で列にしてから、列同士の等式で結合する。
  CTE を 3 段重ねる形は、第 6 回で覚えた WITH の応用としてそのまま読める
- **LEFT JOIN の不一致は空文字。** `CASE WHEN a.件数 = '' THEN 0 ELSE a.件数 END` で 0 にする（COALESCE は使わない）
- **空の日付セルは `''` のグループになる。** 受注予定日で GROUP BY すると年月 `''`・4 件の行が先頭に出る。
  除外は `WHERE 受注予定日 != ''`（実測で 9 行になる）。第 3 回の方言メモに置く
- **月 step の start は月初限定。** `'2025-11-01'` のように書く
- 読者環境の注意: サンプルパックの日付が読者の導入時期で変わる可能性がある。記事は「まず段階 1 を実行して、
  自分の環境でどの月が抜けるかを見る」と書き、月の値を断定しない

## 6.1 Claude Desktop に打つ共通プロンプト（第 1 回以降で毎回使う・第 0 回の図にも使う）

会話の最初に 1 回だけ貼る前置き。「書いて検証するだけ・実行しない」をここで固定すると、
Claude が `ksql_query` で勝手に実行して数字を要約する動きが止まり、無料枠のツール呼び出しも減る。

```text
このチャットでは kSQL MCP を使って kintone 用の SQL を書いてもらいます。約束は 4 つです。
1. SQL は書いて ksql_validate で検証するだけにしてください。ksql_query で実行しないでください（実行は私がプラグインで行います）
2. フィールドコードは推測せず、必ず ksql_describe_app で確認してから使ってください
3. 完成した SQL は、そのまま貼れるように SQL だけのコードブロックで見せてください
4. そのあとに、SQL の各句（SELECT / FROM / WHERE …）が何をしているかを 1 行ずつ説明してください
5. 依頼していない列・条件・並べ替えは追加しないでください
```

5 番は第 1 回レビューで追加（未習の句を混ぜさせない）。付いてきたら「今回は並べ替えなしで書き直して」と頼む、と各回で案内する。
そのあとに、その回の依頼文を打つ。第 0 回の図（第 1 回の題材を先取り）:

```text
顧客管理は APP4148 です。顧客ランクが A の会社を、会社名と顧客ランクの 2 列で出してください。
```

想定される SQL（2026-09-10 実機確認・手元環境では 59 行。素の SFA パックなら 9 件中の A ランク分）:

```sql
SELECT 会社名, 顧客ランク FROM APP4148 WHERE 顧客ランク = 'A' ORDER BY 会社名
```

- 図は**素の SFA パックを入れた環境で撮る**（手元の顧客管理は検証用レコードを足してあり 215 件。読者の画面と行数が合わない）
- 右側（プラグイン）は、左のコードブロックをそのまま貼って実行した直後の結果表。行数が画面に収まる依頼文にする
- Claude が約束を破って `ksql_query` を呼んだ場合は、それ自体を第 1 回で「AI は約束を守るとは限らない。だから実行結果は自分で見る」の例に使える

## 6.2 第 1 回の実機確認メモ（2026-09-10・APP4148 顧客管理）

- 素のサンプル 9 件の内訳: ランク A = 3（サイボウズ商事・キントーンシステムズ・平川ファイナンス）、B = 3、C = 2、D = 1。東京都 = 3。A かつ東京都 = 1（サイボウズ商事）。業種「金融業」= 2（林コンサルティング・平川ファイナンス）
- 手元の顧客管理は検証用に 206 件足してあり計 215 件。記事の結果表は `$id <= 9` で絞って取った（記事にはその旨をコメントで残す。本文の SQL には書かない）
- ラベルとフィールドコードが違う例: 「〒」= `郵便番号`、「顧客No.」= `顧客No`。`SELECT 〒` は LexError（予期しない文字）
- **`ksql_validate` は存在しないフィールド名でも ok を返す**（静的検査・API 0 回）。実行時に `ArgumentError: WHERE predicate is unsupported (field=ランク, operator==, reason=WHERE_FIELD_UNRESOLVED)`。「検証を通った ≠ 動く」の教材にした
- `WHERE 顧客ランク = 'Z'` は 0 行・エラー無し。「0 件」の読み方の教材にした
- ラジオボタンの `=` はエンジンが `in` へ正規化して押し下がるので、第 1 回では `=` のまま教える。`in` が必須になる複数選択系は後の回
- R1 レビュー反映（2026-09-10・Gemini / ChatGPT）: `ksql_validate` を「文法」ではなく「構文と静的検査。フォーム定義は読まない」に訂正／「1 箇所変える」を守るため変更 2（列を足す）と変更 3（AND）に分割し、'Z' は変更 4 に／並び順が未指定である注記と `LIMIT 5` の注記／件数は記事環境の値だと一度だけ注記／共通前置きに 5 番を追加／文字と数値のクォートの方言メモ／`DESCRIBE` は Claude が見ているのと同じ情報と補足／管理コメント内の `<!-- 図 -->` 入れ子を解消（HTML コメントは入れ子不可）
