## 第 3 回（https://qiita.com/rex0220/items/d417ba52766f73cb965d）

- [ ] 「kSQL では、この『ウィンドウ関数を式の中で使う』ができません」の直後:

> **注記（v3.81.0 以降）**: できるようになりました。集計と同じ SELECT にウィンドウを書くこと、ウィンドウの結果を `ROUND` や割り算・`CASE` の中で使うことの両方が対象で、集計から区分までを 1 つの SELECT に書いた形が下の 3 段版と同じ 10 行を返します（実測）。`OVER` の中で参照できるのはグループキー・集計の別名・集計式・`GROUPING()` で、`WHERE` / `HAVING` では使えません。3 段版は、段ごとに確かめたいときの書き方として有効です。

<!-- 上の「標準 SQL ならこう書く」のように集計を `base` に分けて次の SELECT の `CASE WHEN … OVER () = 0` に書く形は、v3.81.0〜v3.82.0 では `unknown field code(s): __ksql_window_0` で落ち、v3.83.0 で修正（B190）。注記は v3.83.0 以降に載せるなら上の文面のままでよい。版を細かく書くなら「集計と同じ SELECT に書く形は v3.81.0 以降、CTE を残して CASE 条件に書く形は v3.83.0 以降」 -->

1 つの SELECT に書いた形（実測に使った SQL・注記に添えるなら）:

```sql
SELECT RANK() OVER (ORDER BY SUM(b.売上) DESC) AS 順位,
       a.会社名, a.顧客ランク, COUNT(*) AS 案件数, SUM(b.売上) AS 売上合計,
       CASE WHEN SUM(SUM(b.売上)) OVER () = 0 THEN 0
            ELSE ROUND(SUM(b.売上) * 100.0 / SUM(SUM(b.売上)) OVER (), 1) END AS 構成比,
       CASE WHEN SUM(SUM(b.売上)) OVER () = 0 THEN 0
            ELSE ROUND(SUM(SUM(b.売上)) OVER (ORDER BY SUM(b.売上) DESC, a.会社名
                                              ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
                       * 100.0 / SUM(SUM(b.売上)) OVER (), 1) END AS 累積構成比,
       CASE WHEN SUM(SUM(b.売上)) OVER () = 0 THEN 'C'
            WHEN SUM(SUM(b.売上)) OVER (ORDER BY SUM(b.売上) DESC, a.会社名
                                        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
                 * 100.0 / SUM(SUM(b.売上)) OVER () <= 80 THEN 'A'
            WHEN SUM(SUM(b.売上)) OVER (ORDER BY SUM(b.売上) DESC, a.会社名
                                        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
                 * 100.0 / SUM(SUM(b.売上)) OVER () <= 95 THEN 'B'
            ELSE 'C' END AS 区分
FROM APP4149 AS b
INNER JOIN APP4148 AS a ON b.顧客No_ = a.顧客No
GROUP BY a.会社名, a.顧客ランク
ORDER BY 売上合計 DESC, a.会社名
```
