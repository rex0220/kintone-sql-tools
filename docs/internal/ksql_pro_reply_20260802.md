# 本文（送付版）

## 【返信】K-96 — v3.38.0 で `displayName` を追加しました。ご提案の非破壊案です

```
npm i @rex0220/kintone-sql-tools@3.38.0
```

**ご提案いただいた非破壊の代替案をそのまま採用しました。**
`QueryColumn` に `displayName`（SQL に書かれた表記）が加わります。
結果行のキーと `columns[].name` は従来どおり小文字のままなので、取り込むだけで壊れません。

```ts
const result = await runQuery("SELECT $id AS ランクA FROM APP100", { client });
// rows:    [{ "ランクa": "1" }]                              ← 不変
// columns: [{ name: "ランクa", displayName: "ランクA", ... }] ← 新設
```

表の見出し・グラフの凡例に `displayName` をお使いください。
顧客ランク A〜D のクロス集計（`SUM(...) AS ランクA` の形）も確認済みです。

## 1. ドキュメントの件 — 未記載の暗黙挙動でした

**ご指摘のとおり、別名の小文字化はどこにも書かれていませんでした。**
「仕様どおりです・記載場所はここです」とお答えできる状態ではなかったため、
v3.38.0 で言語リファレンス §1「大文字・小文字」に明文化しました:

- SELECT 別名の英字（**全角を含む**）は結果列名で小文字へ正規化される
- **バッククォートで囲んでも保持されない**（実測いただいたとおりです）

Pro 側ドキュメントの注意書きは「表示は `displayName` で書いたとおりに出る」前提で
書いていただけます。

## 2. `displayName` の決定規則

| 列 | `displayName` |
|---|---|
| 明示別名（`AS ランクA` / バッククォート / キーワード別名 `AS AVG`） | **書かれたとおり**（バッククォートは剥がした中身） |
| 別名なし（フィールド参照・集計の合成名） | `name` と同一（フィールドコードは元々表記保持） |
| UNION | **第 1 枝**の SELECT リストの表記 |
| temp テーブル / CTE の `SELECT *` | 定義時の表記を引き継ぐ |
| 明示的な再選択（`SELECT ランクa FROM #t`） | その位置に書かれた表記 |

照合（重複検査・ORDER BY / HAVING・UNION の列合わせ）は従来の大小無視のまま一切
変わっていません。`displayName` は常に入ります（別名なしの列は `name` と同じ値）。
