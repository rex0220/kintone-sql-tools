## 2. ⚠ 前回の案内を 1 点訂正します — **メタデータの取得量は増えます**

**v3.30.0 の連絡で「メタデータの取得量は増えません」とお伝えしましたが、
次リリースから正確でなくなります。**

### 経緯

**アプリ定義のキャッシュに無効化の仕組みがありませんでした。**

```
kintone に項目を追加してデプロイ → SELECT <その項目>  → unknown field code(s)
                                → SELECT *           → 同じ項目が見えている
```

**同じプロセス・同じアプリで、`SELECT *` には見えているのに名指しすると拒否される**という
矛盾が起きていました。原因はプロセス生存期間のキャッシュで、**再起動するまで直りません**。

古くなっていたのはフィールド定義だけではなく、**選択肢・プロセス管理・数値精度・
そして v3.30.0 でご案内したばかりの必須／文字数／上下限**も同じでした。
**管理者が制約を厳しくしても、常駐プロセスは古い条件で「エラーなし」を返します。**

**常駐プロセス（Pro のダッシュボード・MCP サーバー）だけが該当**します。

### 修正と、その代償

キャッシュを**実行単位**に変えました。**設定変更が次の実行から必ず反映されます。**

**その代わり、メタデータ取得が増えます。**

| | 変化 |
|---|---|
| 1 実行 × 1 アプリ | **`fields.json` の GET が 1 回増える** |
| **同じアプリへの並行実行** | **実行数ぶん取得する**（従来は 1 回に集約されていた） |
| 1 回の実行の中 | **不変**（2 アプリ JOIN は 2 回・4 文のバッチは 2 回） |

**10 ペイン × 2 アプリを同時更新される場合、1 回の更新あたり最大 20 回の増加**です。

レコード取得に比べれば小さい増分ですが、**前回「増えません」と申し上げた以上、
黙って変えるべきではないと判断しました。**

**実測で問題になるようでしたらお知らせください。**緩和策（TTL など）を検討します。
**先回りして選択肢を増やすことはしません** — 実際に困っていない設定を足すと、
どちらを使うべきかの判断をそちらに押し付けることになるためです。

## 3. ①`explainQuery` のバッチ対応 — **「配線するだけ」ではありませんでした**

**最優先で受けます。**ご指摘のとおり、**こちらが出した `runBatch` を採用いただいた結果として
生じた欠落**です。検証が効かなくなるのは本末転倒なので、次リリースに含めます。

ただし **1 点、ご想定と違う部分があります。**

### 論点はプランナではなく、**受け付ける文の集合**です

バッチ EXPLAIN のプランナは確かに既にあります。**問題はその手前です。**

| API | 受け付ける文 |
|---|---|
| `runBatch` | read-only 全般（**`CREATE TEMP TABLE` / `SET` / `DECLARE` / `VALIDATE`** を含む） |
| **`explainQuery`** | **`SELECT` / `WITH` / `UNION` のみ** |

**複文対応だけを足すと、バッチの中身で弾かれます。**
そちらのバッチには `CREATE TEMP TABLE` と `SET` が入るので、状況は変わりません。

**そこで「`explainQuery` が `runBatch` と同じ集合を受ける」形にします。**
単文の `VALIDATE APPn` なども通るようになります（**従来拒否していたものを通す方向のみ**なので、
既存の使い方には影響しません）。

**「`runBatch` は単文もそのまま流せるので実行経路を一本化する」**と書かれていたのが決め手でした。
**実行経路を一本化されるなら、検証経路も同じ集合でなければ必ずずれます。**

### 戻り値の形について（ご確認いただきたい点 1/2）

**現行 `ExplainResult` の `lines` に、文番号付きで連結する**形を予定しています。

理由は、配列を足すと engine ライブラリの公開型が変わるためです。
**「構文が通るか」「エラーならどの文か」が分かれば足りる**とのことでしたので、
これで要件を満たすと考えています。

**エラー時の文の特定は既に手当て済み**で、エラーに `statementIndex` / `statementType` が載ります。

**別の形がよろしければ、着手前にお知らせください。**特にご意見がなければ上記で進めます。

## 4. ②変数の直接算術 — **(a) 直接算術を許可します**

```sql
SELECT 提案商品, 売上, (売上 * 100) / @total AS 構成比 FROM #g;
```

**構成比という具体的な用途を共有いただいたのが判断材料になりました。**
「今後のフェーズ」に置いていた項目でしたが、**最も要望の多い列の 1 つ**であれば話は別です。

### 0 行の `SELECT *` が列を失う問題

```sql
CREATE TEMP TABLE #e AS SELECT * FROM APPn;   -- 0 件だった日
SELECT * FROM #e                              -- 従来: 列名まで消えていた
```

**「データがある日は動き、0 件の日だけ落ちる」**という壊れ方をしていました。
`INSERT ... SELECT` の列数エラーや、一時テーブルを JOIN 入力にしたときのエラーとして出ます。

**日付で絞るペインは 0 件の日が普通に発生する**はずなので、
**心当たりがあればこの修正で解消しているかご確認ください。**

あわせて、v3.30.0 で「残る限界」としてお伝えした
**`rows=[] && columns=[]` の JOIN 入力エラーも解消**しています。
