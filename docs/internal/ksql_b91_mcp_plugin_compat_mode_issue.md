# B91 MCP にプラグイン互換モードを追加する（環境変数）

- 起票: 2026-07-29
- ステータス: 📝 **評価・起票（優先 低／Pro 側に代替あり・B89 の後）**
- 出典: [Pro からの連絡 2026-07-29](../../../ksql-dashboard-pro/docs/internal/kSQLエンジンへの連絡-20260729-送付版.md) 依頼③（継続）
- 関連: [B89 explainQuery バッチ](ksql_b89_library_explain_batch_issue.md) / [B68](ksql_b68_engine_library_readonly_impl_plan.md)

## 1. 依頼内容

環境変数（例 `KSQL_PLUGIN_MODE=1`）で、`ksql_validate` / `ksql_explain` / `ksql_query` に
**`runQuery` と同じ許可リスト**を適用してほしい。

**ツール引数ではなく環境変数**を希望する理由は、**引数だと AI が渡し忘れる**ため。
環境変数なら `.mcp.json` に探索用と互換モード用の 2 エントリを登録して併存できる。

## 2. 解きたい問題

**AI が MCP で書いた SQL が、CLI / MCP 専用構文を含んでいても MCP 上では通ってしまう。**
それをプラグイン（Pro のペイン）へ持っていくと動かない。

## 3. Pro が優先度を下げた理由

**設定画面の構文チェックが `explainQuery`（＝プラグインの guard 経路）を通す**ため、
CLI / MCP 専用構文は**ペインを開いた時点で既に弾かれる**。

本件が埋めるのは
**「AI が MCP で書いた SQL が、設定画面を開くまで誤りと分からない」という時間差だけ**である。

## 4. B89 との関係

> **B89 が実現すると本件の価値も上がる。**
> B89 でバッチが検証できるようになれば、互換モードでも同じ判定が返せるため（Pro 談）。

**先に B89 を片付けるべき**で、本件を単独で進める理由は無い。

## 5. 検討事項

- **環境変数という形が妥当か。**MCP サーバーの設定は `.mcp.json` に集約されており、
  プロファイル指定は既にツール引数（`profile`）で行っている。
  **面ごとの許可集合を環境変数で切り替える前例が無い**
- **「`runQuery` と同じ許可リスト」の定義。**B68 で `isReadOnlyStatement()` へ一本化済みなので、
  参照先は明確。ただし **`runQuery` は行を返す文に限られる**（`isRowReturningReadOnlyStatement`）ため、
  Pro が実際に欲しいのが `runQuery` 相当か `runBatch` 相当かを確認する必要がある
  （**Pro は `runBatch` を採用済み**なので、後者の可能性が高い）
- **モードが増えることの保守コスト。**MCP の許可集合が 2 通りになると、
  B68 で作った parity テストの対象も 2 通りになる

## 7. 優先度の根拠

**Pro 自身が優先度を下げており、代替手段（設定画面が弾く）が機能している。**
埋まるのは時間差だけで、**誤った結果が出る類ではない。**

**B89 の完了後に、Pro が実際に欲しい許可集合を確認してから再評価する。**
