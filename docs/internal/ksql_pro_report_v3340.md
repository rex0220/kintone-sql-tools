# 本文（送付版）

## 【連絡】v3.34.0 — **JOIN の残件（B98）が閉じました**

```
npm i @rex0220/kintone-sql-tools@3.34.0
```

**v3.33.0 の連絡で「`JOIN` は対象外です。別課題として残しています」とお伝えした件**——
**LEFT JOIN で右側が打ち切られると `NULL` が入る**——**を実装しました。**

もう 1 件（B99・MCP を SDK v2 へ移行）も入っていますが、
**Pro には影響しません**（§3）。

## 1. 外部結合の保持されない側が打ち切られたら、止まります

**`LEFT JOIN` / `RIGHT JOIN` の保持されない側が取得上限に達した場合、
`onLimitReached: "truncate"` を選んでいても `FetchAllLimitError` になります。**

**理由は B97 と同じです。**結果を見ても誤りに気づけないためです。

```
APP4226 LEFT JOIN APP4225   maxRecords=20 / truncate

  A → a01     （相手が上限内にあった）
  B → （空）  ← 真の値は b01。相手が 21 件目以降にあり、上限の外へ落ちた
  C → （空）  ← 本当に相手がいない
```

**`B` と `C` はバイト単位で同一に見えます。**
「取りこぼし」なのか「本当に該当なし」なのかを、**結果から判定する手段がありません。**

**実機で再現させてから実装しました**（`APP4225` 30 件のうち 29 件が `'A'`・最後の 1 件が `'B'`、
`APP4226` に `'A'` `'B'` `'C'`。`maxRecords=20` / `truncate` で `B` の行が空になることを確認）。
**実装後も同じ 2 アプリで、`LEFT` は結果が返り `RIGHT` はエラーになることを確認しています。**

### 1.1 対象外（従来どおり）

| 形 | v3.34.0 |
|---|---|
| **保持側だけが打ち切られた** | **行が減るだけ**なので、**警告付きで返します** |
| **`INNER JOIN`** | **変更ありません** |

**保持側の打ち切りは「行が足りない」だけで、返した行そのものは本物です。**
**対して保持されない側の打ち切りは、返した行の中身が誤りになります。**この違いで線を引いています。

### 1.2 移行方法

- **`WHERE` で候補を絞る**か、**`maxRecords` を引き上げる**
- **`onLimitReached: "error"` を選んでいる場合、挙動は変わりません**

## 2. **影響するかどうかの確かめ方**

**3 つが同時に成り立つときだけ**エラーになります。

1. **`LEFT JOIN` または `RIGHT JOIN` を使っている**
2. **その保持されない側（`LEFT` なら右、`RIGHT` なら左）が `maxRecords` に達する**
3. **`onLimitReached: "truncate"` で実行している**

**1 つでも欠ければ、v3.33.0 と挙動は同じです。**

**`INNER JOIN` だけ、あるいは JOIN を使っていないダッシュボードは、確認不要です。**

**該当しそうな SQL がある場合**は、`maxRecords` を実運用値にしたうえで
`metrics.limitReached`（v3.32.0 の B95）を見てください。
**打ち切りが起きていなければ、この変更の影響はありません。**

```ts
if (result.metrics.limitReached) {
  // どのアプリで起きたかは result.metrics.limitReachedApps
}
```

**エラーになった場合、メッセージにどのアプリで起きたかが入ります。**

```
外部結合の正しい結果には完全な候補集合が必要です。
complete input reason: OUTER_JOIN_NON_PRESERVED（APP4225）。
onLimit=truncateは使用できません。
取得件数が上限（20 件）を超えました。
WHERE 句で絞り込むか、maxRecords を引き上げてください。
```

## 3. B99（MCP を SDK v2 へ移行）は **Pro には影響しません**

**MCP のプロトコル改訂 2026-07-28 に対応しました。**
**この対応で Node.js 20 以上が必要になるのは、MCP サーバーを起動する面だけです。**

| 面 | 要件 |
|---|---|
| **engine ライブラリ**（Pro が使っている面） | **変更なし** |
| CLI | 従来どおり Node.js 18 以上 |
| プラグイン | 変更なし |
| MCP サーバー | Node.js 20 以上が必要 |

**`package.json` に `engines` は宣言していません。**
**Node 20 を要求するのが MCP の面だけである以上、
engine ライブラリの利用者に制約を課すべきではないからです。**
**Pro の Node 環境を上げる必要はありません。**

**公開 package の runtime 依存もゼロのままです。**
MCP SDK は配布物にバンドルしており、`npm install` で Pro の `node_modules` に入ることはありません。
**Pro が別途 MCP SDK を使っていても、版が衝突しません。**

> **MCP 経由で kSQL を使っている場合のみ**、その実行環境の Node.js が 20 以上か確認してください。
> Claude Desktop の MCPB 版をお使いの場合は、Claude Desktop 側の実行環境が対象です。
