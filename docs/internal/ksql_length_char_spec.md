## 0. 要約

**`LENGTH_CHAR(x)` — コードポイント単位の文字数を返す。実装は `[...x].length` の 1 行。**

- **`LENGTH` は変更しない。** 根拠と実測経路は横断仕様 §2.1 を参照。
- **`LENGTH_CHAR` はコードポイント計数という別契約を明示的に追加する**（横断仕様 原則4）。
- 副産物として **`LENGTH(x) - LENGTH_CHAR(x)` がサロゲートペアの個数**になる（§4）。

---

## 1. 動機

### 1.1 用途 A: 「人が数える文字数」（記事・論文の文字数制限など）

**`𠮟`（U+20B9F）は 2010 年に常用漢字表へ追加された正式な表記だが、サロゲートペアである。**

```
800 字の記事に「𠮟る」が 10 回出た場合
  人が数えると        800 字
  LENGTH（現状）      810 字 ← 10 字多く数え、上限超過と誤判定する
  LENGTH_CHAR         800 字 ✓
```

同様に `𩸽`（ほっけ）・`𠮷野家`（つちよし）も BMP 外。**日本語の実データで普通に出る。**

### 1.2 用途 B: サロゲートペアの検出・計数（§4）

### 1.3 用途 C: 他言語の実装と数え方を揃える

kintone のデータを外部システムへ渡すとき、**相手が何で数えるか**に合わせる必要がある。

| 相手の実装 | 数え方 | 対応する kSQL 関数 |
|---|---|---|
| **JavaScript の Web フォーム**（`.length`） | UTF-16 | **`LENGTH`（現状）** |
| Java（`String.length()`） | UTF-16 | `LENGTH` |
| **Python（`len()`）** | コードポイント | **`LENGTH_CHAR`** |
| Go（`utf8.RuneCountInString`） | コードポイント | `LENGTH_CHAR` |
| Swift（`String.count`） | 書記素 | （§7 の将来候補） |

---

## 2. 既存 `LENGTH` との関係

`LENGTH` と kintone `maxLength` がコードユニットを使う事実、素の `INSERT` で Tier-0 を迂回した実測方法、空文字の扱いは横断仕様 §2.1 を参照。B23 はその事実を変更せず、**コードポイント数が必要な操作へ別名を与える**。

---

## 3. `LENGTH_CHAR` の対象範囲

| 値 | 人が数える | `LENGTH` | `LENGTH_CHAR` | 書記素 | 説明 |
|---|---|---|---|---|---|
| `日本語` | 3 | 3 ✓ | 3 ✓ | 3 ✓ | 普通の漢字（BMP） |
| **`𠮟`** | 1 | **2 ✗** | **1 ✓** | 1 ✓ | **常用漢字（2010 追加）だがサロゲートペア** |
| `𠮟る` | 2 | 3 ✗ | 2 ✓ | 2 ✓ | 常用漢字表の「しかる」 |
| `𩸽` | 1 | 2 ✗ | 1 ✓ | 1 ✓ | ほっけ |
| `𠮷野家` | 3 | 4 ✗ | 3 ✓ | 3 ✓ | つちよし |
| `髙橋` | 2 | 2 ✓ | 2 ✓ | 2 ✓ | はしごだか（BMP・問題なし） |
| **`葛󠄀城`** | 2 | 4 ✗ | **3 ✗** | 2 ✓ | **IVS 付き人名（異体字セレクタ）** |
| `が`（NFD） | 1 | 2 ✗ | 2 ✗ | 1 ✓ | 結合文字 |
| `😀` | 1 | 2 ✗ | 1 ✓ | 1 ✓ | 絵文字 |
| `👨‍👩‍👧‍👦` | 1 | 11 ✗ | 7 ✗ | 1 ✓ | ZWJ 家族絵文字 |
| **正解数** | — | **2/10** | **7/10** | **10/10** | |

**`LENGTH_CHAR` は「人が数える文字数」として完全ではない**（IVS・NFD・ZWJ 絵文字を外す）。完全なのは書記素だけだが、それは**ホスト依存**のため v1 では入れない（§7）。

**それでも `LENGTH_CHAR` を足す理由:**

- **`LENGTH` の 2/10 から 7/10 へ改善する**。外すのは IVS・NFD・ZWJ という限られたケースで、**記事・論文の本文ではまず出ない**（IVS は人名データで出るため、そこは §7 の将来課題）
- **ホスト依存が無い**（§5）。書記素と違い、どこでも同じ結果
- **実装が `[...x].length` の 1 行**

`LENGTH_CHAR` は書記素数を名乗らない。コードポイント列の要素数という機械的な契約を、既存 `LENGTH` を置き換えずに**足す**。

## 4. 副産物: サロゲートペアの検出・計数

```
LENGTH      = a + b + c + 2d     （a=ASCII, b/c=BMP, d=サロゲートペアの個数）
LENGTH_CHAR = a + b + c +  d
─────────────────────────────
LENGTH − LENGTH_CHAR = d          ← サロゲートペアの個数そのもの
```

```sql
-- サロゲートペアを含む行を検出
SELECT 会社名 FROM APP100 WHERE ...   -- LENGTH(会社名) > LENGTH_CHAR(会社名)
-- ペアの個数
SELECT LENGTH(会社名) - LENGTH_CHAR(会社名) AS ペア数 FROM APP100
```

**実測で全 9 ケース一致**（`'😀'` / `'𩸽'` / `'あ'` / `'Aあ😀'` と、紛らわしい `'éé'` / `'ΑΒ'` / `'йц'` / `'Aあéé'` / 孤立サロゲート）。

### 4.1 経緯: `LENGTHB`（バイト数）では判定できない（R1 で検証・却下）

レビューで **「`LENGTH` と `LENGTHB` が異なることでサロゲートペアがあるか判定できるのでは」** という提案があった。**発想は正しいが、比較する相手がバイト数では原理的に成立しない。**

```
"😀"    → LENGTH 2, LENGTHB 4   ペアあり
"éé"    → LENGTH 2, LENGTHB 4   ペアなし   ← 完全に同一
"ΑΒ"    → LENGTH 2, LENGTHB 4   ペアなし
"Aあ😀"  → LENGTH 4, LENGTHB 8   ペアあり
"Aあéé"  → LENGTH 4, LENGTHB 8   ペアなし   ← 完全に同一
```

**理由**: UTF-8 には「2 バイト / 1 ユニット」の文字（U+0080–U+07FF ＝ ラテン拡張・ギリシャ・キリル・アラビア・ヘブライ）があり、**サロゲートペア（4 バイト / 2 ユニット）とバイト/ユニット比が同じ 2.0** になる。

```
LENGTH  = a +  b + c + 2d
LENGTHB = a + 2b + 3c + 4d
```

**`d`（ペア）と `b`（2 バイト文字）はどちらも「バイト = 2 × ユニット」に寄与する**ため、どんな線形結合でも分離できない。

**「2 つの長さの差で判定する」という発想はそのまま活き、相手をバイト数からコードポイントへ替えるだけで厳密に成立する**（§4）。

## 5. 4 面の一貫性

`LENGTH_CHAR` は ECMAScript の文字列イテレータでコードポイントを数え、Node / ブラウザで同じ契約になる。4 面全体の根拠、`Intl.Segmenter`・正規表現との違いは横断仕様 §§6–7 を参照する。

---

## 6. 実装

**意味型は numeric。** 現在の評価器が値を文字列で保持していても、B26 の型メタでは `LENGTH_CHAR` の戻り値を typed number として伝播させる。値の表現から string/number を再判定しない（横断仕様 原則3・§4.5）。

| ファイル | 変更 |
|---|---|
| `src/lexer/tokens.ts` | `LENGTH_CHAR` を予約語へ追加 |
| `src/types/ast.ts` | `StringFuncName` へ追加 |
| `src/parser/parser.ts` | `tryStringFuncName` のマップへ追加。`FUNC_CALL_PREFIX_KINDS` へも追加 |
| `src/engine/evalFunc.ts` | `case "LENGTH_CHAR": return String([...(args[0] ?? "")].length);` |

**arity は 1 固定**（B19 の `assertArity` を再利用）。

**`LENGTH` は 1 文字も変更しない。**

### 6.1 予約語

`LENGTH_CHAR` は新しい予約語。同名フィールドはバッククォート（`` `LENGTH_CHAR` ``）で参照する。B19 で 8 語追加した際に、バッククォート回避が全経路（SELECT / WHERE / GROUP BY / ORDER BY）で機能することを実機確認済み。

`LENGTH_CHAR` がフィールドコードである可能性はほぼ無い（B19 の `LEAST` より安全）。

### 6.2 SemVer

**minor**。追加のみで既存の挙動は完全に不変。

## 7. 対象外・将来

| 項目 | 判断 |
|---|---|
| **`LENGTH` の単位変更** | **対象外**。根拠は横断仕様 §2.1 |
| **`LENGTHB`（バイト数）** | **本仕様には含めない**。①サロゲート判定には使えない（§4.1）②**`TextEncoder` は UTF-8 しか出力できない**（`TextEncoder('shift_jis')` は引数を無視して UTF-8 になる。Node もブラウザも同じ）ため、日本のレガシー連携で要る **Shift_JIS のバイト数は Web 標準では実現できない**③kintone 側にバイト制約が無い。**UTF-8 連携の実需が具体的に出てから**、B19 の「需要が薄い追加は予約語を増やすリスクに見合わない」に照らして判断する |
| **`LENGTH_GRAPHEME`（書記素）** | 将来候補。`Intl.Segmenter` は **Firefox 125（2024-04）で初対応**のためホスト依存。プラグインはブラウザで動くため、**非対応環境では `ArgumentError` に倒す**設計が要る。加えて**対応していてもエンジンの Unicode バージョン差で結果が変わり得る**。`葛󠄀城`（IVS 人名）を正しく数えるにはこれが要る |
| **`LEFT_CHAR` / `SUBSTRING_CHAR` 等の切り出し系** | 対象外。既存切り出しは「コードユニット予算内の最大安全部分列」（横断仕様 原則4、B22）であり、コードポイント版は別名・別課題にする |

### 7.1 B24（`TRANSLATE`）との関係

**同じ「コードポイント単位で文字を扱う」土台の上にある。**

```
B23  LENGTH_CHAR(x)          = [...x].length
B24  TRANSLATE(x, from, to)  = [...from] / [...to] で整列し [...x] を写像
```

B24 は B23 を機能として必要としない（`LENGTH_CHAR` を呼ぶわけではない）が、**同じ設計判断を共有する**ため、**まとめて 1 リリースにすると筋が通る**。

**B22（切り出しの修正）とは契約が違う。** B23 はコードポイントを数え、B22 はコードユニット予算内の最大安全部分列を返す。一般則は横断仕様 原則4を参照し、本書へ再掲しない。

## 8. 受入条件

- [ ] `LENGTH_CHAR('日本語')` = `3`（BMP・`LENGTH` と一致）
- [ ] **`LENGTH_CHAR('𠮟')` = `1`**（`LENGTH` は `2`）＝ **常用漢字がサロゲートペアである実例**
- [ ] `LENGTH_CHAR('𠮷野家')` = `3`（`LENGTH` は `4`）
- [ ] `LENGTH_CHAR('😀')` = `1`（`LENGTH` は `2`）
- [ ] `LENGTH_CHAR('')` = `0`
- [ ] **孤立サロゲート**: `LENGTH_CHAR('\ud83d')` = `1`（イテレータは孤立サロゲートを 1 要素として返す。**ペアではないので差は 0**）
- [ ] **サロゲート判定**: `LENGTH(x) - LENGTH_CHAR(x)` がペアの個数と一致する。**紛らわしいケースを含めること**（`'éé'` / `'ΑΒ'` / `'йц'` は差 0・`'😀'` / `'𩸽'` は差 1・`'Aあ😀'` は差 1）
- [ ] **`LENGTH_CHAR` は書記素ではない**（§3 の制限の確認）: `LENGTH_CHAR('葛󠄀城')` = `3`・`LENGTH_CHAR('👨‍👩‍👧‍👦')` = `7`
- [ ] arity 違反が `ArgumentError`
- [ ] 予約語: `` SELECT `LENGTH_CHAR` FROM APP100 `` が FIELD 参照になる。素の `SELECT LENGTH_CHAR FROM APP100` は `ParseError`
- [ ] SELECT 列 / WHERE / HAVING / `CREATE TEMP TABLE … AS SELECT` / CTE で動く
- [ ] **`LENGTH` の非回帰**: `LENGTH('😀')` = `2`・`LENGTH('𠮟')` = `2`（横断仕様 §2）
