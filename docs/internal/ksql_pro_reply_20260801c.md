# 本文（送付版）

## 【返信】K-88 — v3.37.1 で直しました。凡例は畳めます

**ご指摘のとおり、B108 の残りでした。**

```
npm i @rex0220/kintone-sql-tools@3.37.1
```

**原因はこちらの修正範囲の見落としです。** B108 で「文として書いた EXPLAIN」の
復元を配線した際、対象を CLI と MCP の経路だけに絞ってしまい、
**engine ライブラリの `explainQuery` / `runBatch` 面を挙げていませんでした。**
実行計画ボタンの実機確認で見つけていただき、助かりました。

## 1. v3.37.1 での表示

**お使いの呼び方そのまま**（`explainQuery(pane.sql, { client, maxRecords, logicalApps })`）で
確認しています。

```
修正前  app:           APP900000000 AS APP900000000 (900000000)
修正後  app:           LAPP_案件管理 -> APP4149
```

- **`runBatch` に `EXPLAIN` 文を流した場合も同じ形**になります
- **論理アプリが複数ある計画でも、それぞれの行に対応が出る**ので、
  凡例で追えなかった対応関係も出力から読めます
- ブラウザには profile の概念が無いため **`@profile` は付きません**
  （CLI / MCP の表示は従来どおり `@profile` 付きです）
- 復元は EXPLAIN の計画出力に限定され、**データ行には適用されません**
  （`SELECT 'APP900000000' AS x` のようなデータは書き換わりません）

**公開型・挙動の変更はありません。**取り込むだけで、自前の凡例は畳めます。

## 2. まとめ

| | |
|---|---|
| **原因** | こちらの B108 の修正範囲の見落とし（engine ライブラリ面の漏れ） |
| **修正** | v3.37.1。`LAPP_名前 -> APP番号` の併記・複数論理アプリも各行に対応 |
| **影響** | 表示のみ。公開型・挙動の変更なし |
| **凡例** | 畳んでいただけます |
