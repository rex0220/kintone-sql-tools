## 0. 用語（誤解を避ける）

- **述語分割プレフィルタ**は **LIKE を kintone に押し下げる最適化ではない**。LIKE は**従来どおり JS 評価**のまま。
- LIKE と **AND で並ぶ「他の安全な条件」だけ**を kintone クエリに渡して**取得件数を絞り**、その縮小集合に対して JS で **WHERE 全体（LIKE 含む）を再評価**する。
- したがって kintone の `like`（単語検索・全角半角正規化・トークン化）の仕様を**再現する必要はない**。論点は「押し下げる**他の条件**が正しく働くか」だけ。

## 1. 目的と現状

### 目的
LIKE（や関数・サブクエリ等 JS 評価が必要な要素）を含む SELECT は現状 **WHERE 全体が FULL_SCAN**（全件取得）になる。LIKE と併記された**数値・日付などの絞り込み条件を kintone 側プレフィルタ**にして取得件数を減らし、`maxRecords` 到達や実行時間を緩和する。

### 現状（コードで裏取り済み）
- **FULL_SCAN 判定**: `whereRequiresJsEval`（[selectToKintone.ts:81](../../src/converter/selectToKintone.ts#L81)）が WHERE 内に LIKE / 左辺関数 / 右辺式 / サブクエリ / EXISTS のいずれかを見つけると true → `resolveSelectMode` が FULL_SCAN。
- **押し下げ基盤は既に存在**: `extractTableCondition`（[wherePredicatePushdown.ts](../../src/core/optimization/wherePredicatePushdown.ts)）が **AND を分解して各テーブルの押し下げ条件を抽出**し、**LIKE は除外**（[:17](../../src/core/optimization/wherePredicatePushdown.ts#L17)）。`executeFullScanSelect`（[execute.ts:1082-1096](../../src/execute.ts#L1082)）が各テーブル（メイン含む）にこれを適用し、`fetchTableRecordsForFullScan` が `(baseQuery) and (pushQuery)` で kintone に渡す（[:1540](../../src/execute.ts#L1540)）。EXPLAIN にも反映（[:3194](../../src/execute.ts#L3194)）。
- **ただし押し下げは「エイリアス付きフィールド」に限定**: `extractTableCondition` は `isSingleTableField`（`field.tableAlias === tableAlias`）で判定し、`executeFullScanSelect` は `if (stmt.from.alias)` でのみ計算する。→ **`FROM APP100 WHERE 売上 >= 1000000 AND 会社名 LIKE '%A%'`（無エイリアス・JOIN なし）は押し下げ対象がなく全件取得**になる。これが本課題の主対象。
- **FULL_SCAN では `selectToFetchAllParams` は WHERE を出さない**（[:162](../../src/converter/selectToKintone.ts#L162) の `!whereRequiresJsEval` ガードで false）ため、メインの `baseQuery` は空。押し下げは `pushQuery` のみが担う。
- **現状すでにテキスト `=` / `in` を押し下げ対象にしている**: `isPushDownableRight`（[wherePredicatePushdown.ts:53](../../src/core/optimization/wherePredicatePushdown.ts#L53)）は `STRING` / `NUMBER` / `KINTONE_FUNC` / `IN_LIST` を許可。演算子は `!=` / `<` 等も区別なく押し下げる（右辺型のみで判定）。

## 2. 正しさモデル（超集合性 = この最適化の生命線）

押し下げる条件 `P` について、**「kintone が `P` で返す集合」が「JS が `P` を真とする集合」を包含（⊇）**していなければならない。

- 縮小集合に対し JS が WHERE 全体（`P ∧ 残差`）を再評価するため、最終結果は `{ kintone-P } ∩ { JS: P ∧ 残差 }`。
- これが押し下げ無し（`{ JS: P ∧ 残差 }`）と一致する条件は **`{JS-P} ⊆ {kintone-P}`**。
- **kintone-P が JS-P より狭い（取りこぼす）と、正しい行が fetch されず結果から静かに欠落**する（サイレント不具合）。逆に kintone-P が広い分には JS 再評価が捨てるので無害。

→ **「kintone の P 評価が JS の P 評価より狭くならない」と保証できる述語だけ**を押し下げてよい。

### 2.1 同値性の前提: 上限打ち切りがないこと（[P2]）

超集合性による同値性（§7）は、**候補集合の取得が最後まで完了し、`maxRecords` で打ち切られていない場合にのみ**成立する。`onLimitReached = "truncate"` では、全件取得とプレフィルタ取得で「先頭 N 件」の母集合が変わるため、一般には結果が一致しない。

> **仕様**: 同値性保証は「打ち切りなしで候補集合を取得しきれた場合」に限定する。`truncate` で打ち切りが発生した実行では、押し下げの有無で結果が変わり得ることを許容する（EXPLAIN は**一般注記**、実際の打ち切りは**実行時の取得上限警告**で通知＝§4.4）。既定 `onLimitReached = "error"` では打ち切りは起きないため影響しない。

→ **押し下げ可否は「右辺リテラルの型」では決められない**（[P1-2]）。`NUMBER` 右辺でも左辺が文字列フィールドかもしれず、`STRING` 右辺は日付とテキストを、`IN_LIST` 右辺は選択系とテキストを区別できない。**対象テーブルの `FieldTypeMap`（フィールド定義）で左辺フィールド型を確定**したうえで、演算子・型・方向の組で押し下げ可否を決める。メタデータを取得できない場合は**押し下げない**。`$id` 等の**型が静的に確定するシステムフィールドだけ例外**。

## 3. 述語型ごとの安全性評価（[P1] 現行 JS 実装の意味論に基づく）

前提となる現行 JS 意味論（[evalWhere.ts:118-133](../../src/engine/evalWhere.ts#L118)）:
- **範囲比較 `> < >= <=` は数値化して比較**し、`Number("") === 0`（空セルは NaN でなく 0）。よって **`数値 >= 0` / `<= 0` / `> -1` は空セルで真**になる。
- **`=` / `!=` は文字列比較**（`leftStr === rightStr`）。数値の書式差（`"100"` vs `"100.0"`）で不一致になり得る。
- 日付・日時は**日付型でなく文字列比較**（`>=` は文字列辞書順）。`TODAY()` は JS 実行環境のローカル TZ、`NOW()` は評価時点で値が変わる、`LOGINUSER()` は JS 側で空文字。

| 述語 | 例 | 超集合性の評価 | 判定 |
|---|---|---|---|
| `$id` の**肯定**比較 | `$id >= 1000` / `$id = 5` | レコード番号は必ず存在（空なし）・数値・型が静的確定。kintone と JS が一致 | **確実に安全（第0段）** |
| 数値 `=` | `売上 = 100` | JS は文字列比較。kintone `=` は数値一致で**書式差を吸収して広い**方向 → 超集合性は保たれやすい | 条件付き（型メタ必須・要検証） |
| 数値**範囲** `> < >= <=` | `売上 >= 0` | **空セルが JS で真**（`Number("")=0`）。kintone が空を範囲条件から除外すると **JS で真の行を取りこぼす**（[P1]・**既存経路にも潜在バグ**） | **第1段から除外**（空セル意味論の決着が前提・§4.1） |
| 日付・日時 範囲 | `作成日時 >= '2026-07-01'` | JS は**文字列比較**、TZ・分精度丸め・`TODAY()/NOW()` の評価時点差が絡む。`KINTONE_FUNC` は評価タイミングで値が変わる | **第1段から除外**（実機検証後・§4.2） |
| 選択系 `in`（**スカラー文字列型のみ**） | `ステータス IN ('完了')` | `DROP_DOWN` / `RADIO_BUTTON` / `STATUS` は JS 側でスカラー文字列。オプションコード完全一致が期待できる | 条件付き（型メタ必須・実機検証） |
| 選択系 `in`（**配列/オブジェクト型**） | `CHECK_BOX IN ('完了')` | `CHECK_BOX` / `MULTI_SELECT` / USER・組織・グループ選択は JS 側で**JSON 文字列**（例 `["完了"]`。[process.ts:64](../../src/engine/process.ts#L64)）。kintone の `in` は選択肢要素判定で**述語の対象単位が違う** | **非押し下げ（除外）** |
| テキスト `=` / `in` | `会社名 = 'ABC'` | kintone のテキスト照合は全角半角・大小・トークン化の正規化（詳細非公開）。通常は広い方向だが**狭くする端を排除できない** | **要実機検証（既定は非押し下げ）** |
| `!=` / `<>` / `NOT` / `NOT IN` | `会社名 != 'ABC'` | 否定は超集合性が反転。kintone-`=` が広いと kintone-`!=` は**狭く**なり取りこぼす。空/NULL の扱いでも差 | **非押し下げ（即時除外）** |
| `IS NULL` / `IS NOT NULL` | `顧客コード IS NULL` | kintone の空判定と JS の空文字判定の一致は型依存で不確実 | **非押し下げ（即時除外）** |
| `KINTONE_FUNC` 右辺 | `作成日時 >= TODAY()` | `TODAY()/NOW()` は kintone 評価時点と JS 再評価時点で異なり、`LOGINUSER()` は JS で空。**一括許可は禁止** | **非押し下げ（第1段除外）** |
| OR / NOT / GROUP | `A OR B` | 否定・型不明を含み得る。安全リーフのみを対象とする本抽出では**扱わない**（AND リーフ抽出が主対象） | 非押し下げ |

> **[P1-4] 現状コードは上記の危険述語（テキスト `=`/`in`・`!=`・`IS NULL`・`NOT`・`KINTONE_FUNC`・OR）を既に押し下げている**（エイリアス付き / JOIN 経路。[wherePredicatePushdown.ts:16-42](../../src/core/optimization/wherePredicatePushdown.ts#L16)）。よって本仕様は**新規経路だけでなく既存経路も同じ安全抽出器へ統一**する（§5・[P1-3]）。「別名を付けた瞬間に押し下げ挙動が変わる」ことを避けるため。

## 4. 提案（順序に依存関係あり — A は安全抽出器の完成後）

**[P1-3] A（単一テーブル押し下げ有効化）は B（安全抽出器）の完成が前提**。既存 `extractTableCondition` は危険述語を広く押し下げるため、それを再利用して A だけ入れるのは不可。**先に安全 AND リーフ抽出器を作り、既存・新規の両経路をそれに統一**する。

### B. 安全 AND リーフ抽出器【最初に作る・正しさの核心】

新しい抽出器 `extractSafePushdownLeaves(where, { tableAlias?, fieldTypes? })` を作る（**`fieldTypes` は任意**。第0段は渡さない）:

- **AND のリーフだけを対象**にする（AND を分解し、各リーフが安全述語なら採用）。
- **`GROUP`（括弧）は透過して再帰**（[P2-4]）。`WHERE ($id >= 1000 AND … LIKE …)` のような一般的な書き方でも抽出できるようにする:
  - `GROUP` → 内側を再帰処理。内側が AND なら安全リーフを抽出。
  - `GROUP` 内が **OR / NOT** → そのサブツリーは非押し下げ。
  - 外側が **`NOT`** → 内側に入らず全体を非押し下げ（否定は超集合性が反転）。
  - **`EXISTS` / `OR`** サブツリー → 非押し下げ。
- 各リーフの採否は、型依存の述語では **`FieldTypeMap`（`getFieldTypeMap`）で左辺フィールド型を確定**して決める。**`$id` 等の静的確定フィールドはメタ不要**。
- **メタデータの扱い（[P2-2]・「空」と「取得失敗」を区別）**:
  - 型定義が**空**（モック環境で `getFields()` が空配列 [execute.ts:1051-1056](../../src/execute.ts#L1051)）または**対象フィールド型が不明** → その述語は**非押し下げ**。
  - `getFields()` が **reject する通信・認証エラー** → **既存どおり例外を伝播**し、押し下げなしで実行継続はしない（[getFieldsCached:1834](../../src/execute.ts#L1834) の await がそのまま throw）。
- **押し下げ可の条件**（すべて満たす）:
  - 左辺が単純フィールド参照（関数・算術・CASE 不可。単一テーブル版は修飾なしフィールドも許可）
  - 右辺が**リテラル**（`STRING` / `NUMBER` / `IN_LIST`）。**`KINTONE_FUNC` は不可**（評価時点差）
  - 演算子が**肯定**（`= < > <= >=` / `in`）。**`!=` / `<>` / `NOT IN` は不可**
  - **`IS NULL` / `IS NOT NULL` は不可**
  - フィールド型ごとの許可（§4.3 の段階表）に合致
- 既存の per-table 押し下げ（[execute.ts:1082-1096](../../src/execute.ts#L1082)）と JOIN 押し下げ（[:3194](../../src/execute.ts#L3194)）を、この新抽出器に**差し替える**（統一）。`extractTableCondition` は廃止 or 内部で新抽出器を呼ぶ薄いラッパに。

### A. 単一テーブル（JOIN なし・無エイリアス）への適用【B の上に載る】

- `executeFullScanSelect` のメインフェッチで、**JOIN が無い**場合は `extractSafePushdownLeaves(where, { fieldTypes })`（tableAlias 不問）を使って `pushQuery` を作る。単一テーブルなのでフィールド曖昧さなし。
- これにより `FROM APP100 WHERE $id >= 1000 AND 会社名 LIKE '%A%'`（無エイリアス）がプレフィルタされる。
- **第0段は `$id` のみで `getFieldTypeMap` を呼ばない**（[P2-3]。`$id` は静的確定・メタ不要）。型依存の述語を追加する段（選択系以降）で初めて型メタ取得を結線する。

### 4.1 依存: 数値範囲の空セル意味論＋数値精度（別課題・[P1]）

数値**範囲**を押し下げ対象にするには、2 つの前提を満たす必要がある（別課題 [ksql_evalwhere_empty_cell_numeric_issue.md](./ksql_evalwhere_empty_cell_numeric_issue.md) で扱う）:

- **(1) 空セル意味論（実機で解決済み）**: kintone は空の数値セルを **−∞** として扱う（`>`/`>=` で除外・`<`/`<=` で含む）。現状 JS は `Number("")===0` のため `>=`/`>` で乖離。→ **JS を −∞ 準拠に揃える**（値ベース: `leftStr==="" && rightStr!=="" && 数値化可能`）ことで SIMPLE/FULL_SCAN を一致させる。**案a（空→常に偽）は棄却**。
- **(2) 数値精度（未解決）**: JS の `Number` は IEEE-754 で、桁の大きい整数は丸められる。kintone（10 進比較）と JS で `<=` の結果がずれ得るため、**空セルを直しても数値範囲の押し下げが全面的に安全とは限らない**。正確な 10 進比較か、安全整数域への限定が別途必要。**型メタだけでは解決しない**。

→ **本仕様の第1段では数値範囲を含めない**（§4.3）。(1) は −∞ 修正の完了、(2) は数値ドメイン設計を、数値段の着手条件とする。

### 4.2 依存: 日時の実機検証（[P2]）

日時は**フィールド型・関数名・演算子方向**の組で、TZ・分精度丸め・文字列比較・`TODAY()/NOW()` の評価時点差を**実機で検証**してから追加する。第1段では除外。

### 4.3 段階導入（安全な順）

| 段 | 対象 | 前提 |
|---|---|---|
| **第0段（確実）** | **`$id` の肯定比較のみ**（`= < > <= >=`、右辺 NUMBER） | 型が静的確定・空なし。**メタデータ取得なし** |
| 第1段 | 型メタで確定した**スカラー文字列型の選択系 `in`**（`DROP_DOWN` / `RADIO_BUTTON` / `STATUS`、オプションコード完全一致） | `FieldTypeMap` 前提・実機で超集合性確認。**`CHECK_BOX`/`MULTI_SELECT`/USER 等（JSON 文字列化）は除外** |
| 第2段 | **数値**（範囲は §4.1 の空セル決着後、まず `=`） | 空セル意味論の決着 |
| 第3段 | **日時**（§4.2 の実機検証後） | TZ・関数評価時点の検証 |
| （保留） | テキスト `=`/`in` | 実機で超集合性を確認できたら |

いずれの段でも **`!=`/`NOT`/`IS NULL`/`KINTONE_FUNC`/OR は押し下げない**。

### 4.4 EXPLAIN の扱い（[P2]・同期契約）

現 `executeExplain`（[execute.ts:3147](../../src/execute.ts#L3147)）は**同期・kintone 非アクセス**。型依存の押し下げ判定は `getFieldTypeMap`（async）を要するため、EXPLAIN では**確定した押し下げクエリを出せない**。次のいずれかを仕様化:

- 案 A（推奨・契約維持）: EXPLAIN は「**押し下げ候補**（型メタ取得後に確定）」と表示し、`$id` 等の静的確定分のみ確定表示。
- 案 B: EXPLAIN を async 化して型メタを引く（契約変更・影響大）。→ 非推奨。

**EXPLAIN と実行時の役割分担（[P2]・EXPLAIN は実行しない）**: EXPLAIN は実行オプションや実際の打ち切りを知り得ないため、truncate については「**`truncate` 時は結果集合が変わり得る**」という**一般注記**にとどめる。実際の打ち切りは**実行時の既存の取得上限警告**で通知する（§2.1）。

## 5. 判断論点と決定（codex レビューでの回答を反映）

| 論点 | 決定 |
|---|---|
| B の適用範囲 | **既存 JOIN / エイリアス経路も含めて統一**。別名の有無で押し下げ挙動（＝正しさ）が変わるのを避ける。既存が押し下げていた `!=`/NULL/NOT/型不明は**即時除外**（安全側へ収束。一部 JOIN クエリは押し下げが減り遅くなり得るが、正しさを優先） |
| 右辺型からの近似 | **不採用**。`FieldTypeMap`（`getFieldTypeMap`）でフィールド型を確定。**取得不能時は押し下げなし**。`$id` 等の静的確定フィールドのみ例外 |
| 日時境界 | **第1段から除外**。TZ・空値・文字列表現・`TODAY()/NOW()` の評価時点を実機確認後に追加 |
| 既存テキスト押し下げ | **放置せず統一抽出器の厳格化対象に含める**。否定・NULL・NOT・型不明述語は即時除外 |
| 選択系 `in` の対象型 | **スカラー文字列型（`DROP_DOWN`/`RADIO_BUTTON`/`STATUS`）のみ**。`CHECK_BOX`/`MULTI_SELECT`/USER・組織・グループは JSON 文字列化で述語単位が違うため**除外**（[P1-1]） |
| メタ「空」と「取得失敗」 | **区別**。空/型不明＝非押し下げ、`getFields()` reject＝既存どおり例外伝播（押し下げなしで続行しない）（[P2-2]） |
| `GROUP`（括弧） | **透過再帰**（内側 AND は抽出、内側 OR/NOT と外側 NOT は非押し下げ）（[P2-4]） |
| 第0段のメタ取得 | **行わない**（`$id` 静的確定・`fieldTypes` は任意引数）（[P2-3]） |
| 最初の確実な範囲 | **`$id` の肯定比較のみ**。以降、空セル数値意味論の決着 →（型メタ付き）スカラー選択系・数値・日時、の順に段階追加 |

## 6. 非対象・限界

- LIKE 単独、またはテキスト条件だけと AND した SELECT は**押し下げ対象がなく無効果**（従来どおり全件取得）。効果は「LIKE ＋ 数値/日付/id/選択in」の併記時に限られる**条件付き**。
- サブテーブル仮想テーブルは親レコード取得のため、押し下げ設計は別途（本仕様はメイン/親アプリの通常フィールドを対象）。

## 7. 正しさ担保テスト（**「打ち切りなし」前提で** 押し下げ後 == 全件 JS 評価）

- **単体（安全抽出器）**: `extractSafePushdownLeaves` が押し下げ**しない**こと＝ LIKE / 関数左辺 / `!=`/`<>`/`NOT IN` / `IS (NOT) NULL` / `NOT` / OR / `KINTONE_FUNC` 右辺 / 型メタ不明フィールド / **`CHECK_BOX`・`MULTI_SELECT` の `in`**。押し下げ**する**こと＝ `$id` 肯定比較（第0段・`fieldTypes` なし）、（型メタ付き）**スカラー選択系（`DROP_DOWN`/`RADIO_BUTTON`/`STATUS`）の `in`**。
- **`GROUP` 透過**: `WHERE ($id >= 1000 AND 会社名 LIKE '%A%')` で `$id >= 1000` が抽出される。`WHERE ($id >= 1000 OR …)` / `WHERE NOT ($id >= 1000)` は抽出しない。
- **メタの空 vs 失敗**: `getFields()` 空配列 → 型依存述語は非押し下げ（実行は継続）。`getFields()` reject → 例外が伝播（実行が止まる。押し下げなしで続行しない）。
- **第0段の同値**: `WHERE $id >= 1000 AND 会社名 LIKE '%A%'`（無エイリアス／エイリアス両方）で、押し下げ結果 == 全件 JS 評価。件数・行一致。`$id` は `getFieldTypeMap` を呼ばずに判定。
- **[P1] 空セル数値の回帰**: `数値 >= 0` を含む WHERE が**第1段では押し下げられない**ことを固定（空セルの取りこぼし防止）。§4.1 の決着後に数値範囲を足す際は、空セル・0・負値で同値を検証。
- **[P2] 打ち切り**: `onLimitReached="truncate"` かつ候補が上限超過のとき、同値保証の対象外である旨（＝押し下げ有無で結果が変わり得る）を仕様どおりに扱う。既定 `error` では打ち切りが起きないことを固定。
- **統一の回帰**: 既存 JOIN / エイリアス経路が、危険述語（テキスト `=`/`!=`/NULL 等）を**もう押し下げない**方向に変わることを固定（安全側の意図的な挙動変更）。安全述語（`$id` 等）の押し下げは維持。
- **実機（超集合性・第1段以降の追加時）**: 選択系 `in`・（追加時）テキスト `=`（全角半角・末尾空白・大小）・日時境界（TZ・分丸め・`TODAY()/NOW()`）で「押し下げ後 == 全件 JS 評価」を実データで確認。崩れる型/演算子はホワイトリストから外す。

## 8. 効果評価（実装可否の材料）

| 観点 | 評価 |
|---|---|
| 実装コスト | **B（安全抽出器＋既存/新規統一＋型メタ結線＋EXPLAIN 契約）が中〜大**。A（単一テーブル適用）は B の上に載るため小だが単独では入れられない |
| 正しさリスク | **中**。ただし段階導入で管理: 第0段（`$id` 肯定比較）は静的に安全でメタ不要。以降は型メタ＋実機超集合性テストで 1 段ずつ |
| 既存挙動の変更 | **あり（安全側）**。既存 JOIN 経路のテキスト `=`/`!=`/NULL 押し下げを止める＝一部クエリが遅くなり得るが、**サイレント欠落リスクを除去**（正しさ優先） |
| 効果 | 条件付き（LIKE ＋ 押し下げ可能な述語の併記時のみ）。第0段は `$id` 併記に限られ効果は限定的。段が進むほど適用範囲拡大 |
| 依存 | 数値範囲は空セル意味論の決着（§4.1・別課題）、日時は実機検証（§4.2）が前提 |

## 9. 結論（推奨）

- **実装は可能だが、当初想定より B（安全抽出器）が本体**。「既存 `extractTableCondition` を再利用して A だけ入れる」は**危険**（既存抽出器が `!=`/NULL/NOT/KINTONE_FUNC/OR/テキストまで押し下げるため）。
- **順序**: ① 安全 AND リーフ抽出器 `extractSafePushdownLeaves`（型メタ前提・肯定のみ・否定/NULL/NOT/OR/KINTONE_FUNC 除外）を作り、②既存 JOIN 経路と③新規単一テーブル経路を**それに統一**、④ EXPLAIN は「押し下げ候補」表示で同期契約を維持。
- **最初の確実な導入は `$id` の肯定比較のみ**（静的型・空なし・メタ不要）。以降、**空セル数値意味論の決着（§4.1）→ 型メタ付き選択系 `in` → 数値 → 日時（実機検証）**の順で 1 段ずつ、各段で「打ち切りなし前提の同値」実機テストを通してから拡大。
- ユーザ懸念（テキストの全角半角・単語切り分け）は**テキスト述語を押し下げない**ことで原理回避。**否定・NULL・型不明も即時除外**。
- **前提の別課題**: (i) `evalWhere` の空セル数値意味論（§4.1）、(ii) 既存 JOIN 押し下げの厳格化に伴う性能影響の許容（§5）、(iii) 日時の実機超集合性検証（§4.2）。これらの決着が数値・日時段の前提。

### 実装可否の判断（要約）
第0段（`$id` 肯定比較の統一抽出器）は**低リスクで実装可能**。ただし効果は限定的。**実用的な効果（数値・日時・選択系）を出すには、空セル意味論の決着と型メタ連携・実機検証が前提**で、中規模の段階プロジェクトになる。「まず第0段だけ入れて基盤（安全抽出器・統一・EXPLAIN）を整え、需要を見て段を進める」のが現実的。

## 10. 第0段 実装指示（Codex 向け・確定スコープ）

**目的**: 安全 AND リーフ抽出器を新設し、既存・新規経路を統一。押し下げ対象は **`$id` の肯定比較のみ**。主眼は**既存の危険な押し下げを停止する安全化**（機能追加は `$id` 併記時の限定的プレフィルタ）。空セル意味論・型メタには依存しない。

### 10.1 新抽出器

`extractSafePushdownLeaves(where, { tableAlias?, fieldTypes? })` を [wherePredicatePushdown.ts](../../src/core/optimization/wherePredicatePushdown.ts) に新設し、`extractTableCondition` を置換（または内部で新抽出器を呼ぶ薄いラッパに）。

- **AND を分解**し、各リーフを個別判定。`GROUP`（括弧）は**透過して再帰**。
- **押し下げる**リーフ（第0段）: 左辺が **`$id`**（レコード番号・システムフィールド）、演算子が**肯定の `= < > <= >=`**、右辺が **`NUMBER`** リテラル。
- **押し下げない**（第0段では全て非対象）: `OR` / `NOT`（外側）/ `GROUP` 内 OR・NOT / `IS (NOT) NULL` / `LIKE`・`NOT LIKE` / `!=`・`<>`・`NOT IN` / 一般フィールド（`$id` 以外＝型メタが要る）/ 左辺が関数・算術・CASE / 右辺が `STRING`・`IN_LIST`・`KINTONE_FUNC` / `EXISTS`。
- **JOIN あり**: `tableAlias` を渡し、**対象エイリアスの明示フィールドだけ**抽出（クロステーブルは対象外）。
- **JOIN なし**: `tableAlias` なしで呼び、**修飾なしフィールド、またはメインテーブルの正しい別名**を許可（単一テーブルなので曖昧さなし）。
- **第0段では `getFieldTypeMap` を呼ばない**（`fieldTypes` は渡さない・任意引数のまま）。`$id` は静的確定。

### 10.2 差し替える呼び出し箇所

- 実行（FULL_SCAN）: メイン [execute.ts:1082-1096](../../src/execute.ts#L1082) / JOIN [:1116-1131](../../src/execute.ts#L1116)。**加えて、JOIN なし・無エイリアスのメインでも新抽出器を呼ぶ**ようにゲート（`if (stmt.from.alias)`）を単一テーブル対応へ拡張。
- EXPLAIN: メイン [execute.ts:3193-3194](../../src/execute.ts#L3193) / JOIN [:3206-3207](../../src/execute.ts#L3206)。**EXPLAIN は実際に確定した `$id` 押し下げだけ表示**（第0段は静的なので同期のまま可）。**将来の「型依存候補表示」基盤は第0段では作り込まない**。

### 10.3 テスト

- 新抽出器の単体: `$id` 肯定比較（`= < > <= >=`・右辺 NUMBER）を抽出、`GROUP` 透過（`WHERE ($id>=1000 AND … LIKE …)` で抽出）、非押し下げ（OR/NOT/NULL/LIKE/`!=`/一般フィールド/`KINTONE_FUNC`/`STRING`・`IN_LIST` 右辺）。
- 第0段の同値（打ち切りなし前提）: `WHERE $id >= 1000 AND 会社名 LIKE '%A%'`（無エイリアス／エイリアス両方）で押し下げ結果 == 全件 JS 評価。`getFieldTypeMap` を呼ばないこと。
- **既存のテキスト等値押し下げテストは「押し下げない」期待へ変更**（意図的な安全化）。既存の `$id`・安全述語の押し下げは維持。
- EXPLAIN: `$id` 押し下げが `kintone query` に出る／危険述語は出ない。

### 10.4 リリース記載

- CHANGELOG に **「意図的な安全化：既存の JOIN/エイリアス経路で `!=`・`IS NULL`・テキスト等値・`KINTONE_FUNC` 等を kintone へ押し下げていた挙動を停止（結果の取りこぼしリスク除去）。一部クエリで取得件数が増え性能が低下し得る。`$id` 併記時は新たにプレフィルタ押し下げ」** を明記。
