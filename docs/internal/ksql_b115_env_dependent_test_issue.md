# B115 CLI テストが開発者のシェル環境変数に依存して緑赤する

- 起票: 2026-08-04
- ステータス: 📝 **評価（原因特定済み・実測）**
- 出典: B114 第 1 段の実装レビュー中に発見（2026-08-04）。**B114 の回帰ではない**
- 関連: `src/cli/__tests__/logicalExecution.test.ts` / `src/node/runtime.ts:292-297`

## 1. 症状（実測 2026-08-04）

**`logicalExecution.test.ts` の 2 件が、リポジトリの状態と無関係に、実行するシェルの
環境変数で緑にも赤にもなる。**

```
そのまま実行                                  → 2 failed / 9 passed
KSQL_USERNAME・KSQL_PASSWORD 等を外して実行     → 11 passed
```

- **B114 を退避した HEAD でも同じ 2 件が落ちる**＝コード変更が原因ではない
- v3.39.0 のリリースゲート（2026-08-02）は全 green だった＝**その後に環境変数が
  設定されただけで、リポジトリは何も変わっていない**

## 2. 原因

対象テストは **`tokenMap` だけを書いた設定**（`auth` も `username` / `password` も無い）を
一時ファイルに作り、アプリごとに正しい API トークンで振り分けられることを検証する。

認証の解決は **CLI 引数 → 環境変数 → 設定ファイル**の順で、`auto` は
「ユーザー名とパスワードが揃っていれば `userpass`、無ければ `token`」である
（`src/node/runtime.ts:292-297`）。

```ts
const username = envString("KSQL_USERNAME") ?? profile.username ?? null;
const auth = authReq === "auto" ? (hasUserPass ? "userpass" : "token") : authReq;
```

したがって開発者のシェルに `KSQL_USERNAME` / `KSQL_PASSWORD` があると、
テストの設定は `tokenMap` しか持たないのに **`userpass` が選ばれ、
`X-Cybozu-API-Token` が付かない**。実測の失敗（トークンが `null`）と一致する。

**優先順位そのものは仕様どおり**（環境変数が設定ファイルより優先）。
**問題はテストが環境を遮断していないこと。**

## 3. 方針

**テスト側で認証系の環境変数を遮断する。**

- 対象は少なくとも `KSQL_AUTH` / `KSQL_USERNAME` / `KSQL_PASSWORD`、および
  同じ経路で読まれる `KINTONE_*` 系（**実装を確認して網羅すること**）
- 遮断は**このテストだけの小細工にしない**＝CLI をサブプロセスや `runWithArgv` で
  駆動するテストは同じ罠を踏む。**共通のヘルパー**（例: 認証系 env を退避して復元する
  `withCleanAuthEnv()`）を用意し、該当テストへ適用する
- **`process.env` を直接書き換えたまま戻さない形にしないこと**（他テストへ漏れる）

### 3.1 受入条件

1. `KSQL_USERNAME` / `KSQL_PASSWORD` を**設定した状態でも**全テストが green
2. 設定していない状態でも green（現状維持）
3. 遮断が**テストの外へ漏れない**（後続テストの `process.env` が元に戻る）
4. 同じ罠を踏みうる他の CLI テストにも同じヘルパーを適用する
   （**どれが該当するかは実装側で洗い出し、報告に列挙すること**）

## 4. 優先度

**中。** 誤った実装を見逃す危険がある——**開発者の環境によっては赤が常態化し、
「またあれか」で無視されるようになる**。今回も B114 の実装レビューで
「B114 が壊した」と誤認しかけた（実際は無関係）。

修正は小さい。

## 5. 確認していない論点（本件とは別）

**設定ファイルに `tokenMap` があるとき、環境変数のパスワード認証を優先するのが
妥当かどうかは確認していない。** 優先順位（env > config）自体は一貫しているが、
「アプリごとのトークンを明示している設定」を環境変数が黙って上書きする形が
利用者の期待に合うかは別途の検討事項。**必要になったら測ってから判断する。**
