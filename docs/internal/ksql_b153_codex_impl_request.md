# B153 実装依頼（codex）——B150 と同梱・空キーの JOIN 一致欠落の修正

**[B153 起票](ksql_b153_join_key_empty_in_issue.md) を B150 実装済みの作業ブランチ
`b150/dev` へ追加実装する**（オーナー判断＝v3.61.0 同梱）。禁止事項は従来どおり
（git・version・CHANGELOG・README・release/・台帳・ビルド・MCP・MEMORY.md）。

## 1. 背景（実測済み・再導出しない）

- **kSQL の JOIN ローカル評価器は空=空を一致とみなす**（CTE 間 JOIN で実証）
- 現行の結合キー押し下げ `in` 経路は **空キーを trim で捨て、非空 0 件なら取得ゼロへ短絡**
  → 物理側に空キー行があると空=空一致が**静かに欠落**する
- **kintone は TEXT・NUMBER・選択系で `in ("")` を受理**（v3.60.0 で押し下げ実測・エラーなし。
  選択系は従来から公式の未選択検索手段）

## 2. 実装内容

1. **空キーを捨てない**＝ソースキー集合に空値（`""`・null・undefined・trim 後空）が含まれる場合、
   `in` 選択時は **`""` を 1 要素としてリストへ含める**（重複除去後 1 回だけ）
2. **全キーが空の場合も取得ゼロへ短絡しない**＝`in ("")` で取得する
3. **`in ("")` の受理が未確認の型はフォールバック**＝確認済み（TEXT / LINK / NUMBER / CALC /
   選択系）以外——特に**ユーザー系・レコード番号**——は、空値を含むキー集合なら
   全件取得へフォールバック（reason code `JOIN_KEY_EMPTY_VALUE` を `in` 経路にも適用）。
   受理確認済みの型の集合は pure policy に明示し、テストで固定する
4. **範囲経路（B150）の空値フォールバックは変更しない**
5. trim の扱い＝**キー値の trim をやめる**か維持するかを、JOIN ローカル評価器の突合
   （trim するのか）とそろえてあなたが決め、理由を報告に書く。**押し下げと突合で
   意味論が食い違う選択をしないこと**

## 3. テスト

- 空キー混在の JOIN（mock）＝物理側の空キー行が取得され、空=空の一致が**現れる**こと
  （**修正前は欠落することを確認してから直す**＝結果が変わる正しさ修正の証明）
- 全キー空・`in ("")` の query 逐語固定・受理未確認型のフォールバック
- 既存の非空キーのみのケースは挙動不変（回帰）
- B150 の受入（範囲・フォールバック）に影響が無いこと
- `npm test` 全体（環境変数除外可）
