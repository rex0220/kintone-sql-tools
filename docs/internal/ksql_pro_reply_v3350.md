# 本文（送付版）

## 【返信】§4 — **取れます。ただし設定画面では使えません**

**`kintone.user.getOrganizations()` が使えます。**
**一般利用者の権限で動き、`organization.primary` で優先組織かどうかが分かります。**

**ただし公式に「プラグイン設定画面では利用できない」と明記されています。**
**まさに今回、注意書きを置かれた画面です。**

---

## 1. API の中身

```js
const orgs = await kintone.user.getOrganizations();   // 引数省略＝ログインユーザー
// [{ organization: { id, code, name, primary }, title }, ...]

const hasPrimary = orgs.some((o) => o.organization.primary);
```

| | |
|---|---|
| **権限** | **一般利用者で動きます**（cybozu.com 共通管理の権限は不要） |
| **`organization.primary`** | **優先する組織かどうかの真偽値**。まさに必要な情報です |
| **引数** | 省略でログインユーザー。ログイン名を渡せば他ユーザーも引けます |

**制限**——**ユーザーごとに 1 分あたり 50 回**を超えると Promise が reject されます。
**画面遷移が起きるまでキャッシュ**されるので、**1 画面 1 回**なら問題ありません。

## 2. ⚠ **使えない画面に、設定画面が含まれます**

公式の「利用できる画面」にこう書かれています。

> ただし、次の画面では利用できません。
> - 検索画面
> - アプリストア
> - **プラグイン設定画面**

**現在の注意書きの置き場所（設定画面）では、この API を呼べません。**
**「未設定です」という事実の表示へ変えることは、その画面ではできません。**

## 3. **むしろ閲覧画面のほうが筋が良いと思います**

**この API はダッシュボードを表示する画面では使えます。**

そして**条件は見る人ごとに変わります。**

| | |
|---|---|
| **設定画面** | **書いた人**の環境。§1 で書かれたとおり、**管理者の画面では正しく絞られている** |
| **閲覧画面** | **見る人**の環境。**優先組織が未設定なのは、この人かもしれない** |

**「前提です」という一般的な注意は、書く人に向けたもの。**
**「あなたには優先組織が設定されていません」という事実は、見る人に向けたもの。**

**後者は閲覧画面でしか出せませんが、閲覧画面でなら出せます。**
**しかも、出すべき相手にだけ出ます。**

**設定画面の注意書きを消す必要はありません。**
**書く人への注意と、見る人への事実は、別の役割だと思います。**

> **判断はお任せします。**
> **1 画面 1 回の呼び出しで済み、キャッシュも効きます。**

## 4. こちらは実機で試していません

**上記は kintone 公式ドキュメントの記述です。**
**こちらのプラグイン面で実際に呼んで確かめたわけではありません。**

**とくに「プラグイン設定画面では利用できない」の実挙動**——
**例外になるのか、空配列が返るのか**——**は確認していません。**
**組み込まれる際に、そちらで一度お確かめください。**

## 5. §1・§2・§3 について

**§1 の「実行時ではなく書いた時点で出す」は良い判断だと思います。**
**実行時費用がゼロで、設定した人が必ず一度は見る位置**というのは、
**こちらが「エンジンからは判別できない」と書いた穴を、別の層で埋めるもの**です。

**§2 の判断も同じ結論です。**
**1 画面 12 ペインで該当ごとに `COUNT(*)` 2 本**という具体的な数字は、
こちらが「重い」とだけ書いた部分の実際の姿で、参考になりました。
**配布前に 1 回だけ実行する手順**へ回されたのは、費用の置き場所として妥当だと思います。

**§3 はご想定のとおりです。**

**テンプレートギャラリーに入れない判断**——**「フィールドを選ぶだけで動く」保証と、
環境側の前提が要る関数は両立しない**——も、筋が通っていると思います。
