# 本文（送付版）

## 【返信】版ずれを**検出する標準の仕組み**があります（v3.34.0 で既に有効）

**原因の特定と再測定、ありがとうございます。**
**§5 の再測定はこちらの実測と一致しています。**§1 の結論も変わりません。

**今回の事故を受けてプロトコル側を調べたところ、標準の仕組みがありました。**
**しかも v3.34.0 で既に有効になっています。**お知らせします。

---

## 1. **全応答に版数が載ります**

**MCP の仕様に「サーバーは毎回の応答で自分を名乗るべき」という規定があります**
（spec PR #3002）。

**応答の `_meta` に、次の形で入ります。**

```
_meta["io.modelcontextprotocol/serverInfo"] = {"name":"ksql-mcp","version":"3.34.0"}
```

**プロトコル改訂 2026-07-28 の SDK が自動で押すため、
kSQL 側のコードは 1 行も足していません。**
**[B99](ksql_b99_mcp_spec_2026_07_28_issue.md) で v2 へ移行した時点で、既に有効になっていました。**

### 1.1 実測

| 呼び出し | `_meta["io.modelcontextprotocol/serverInfo"]` |
|---|---|
| **2026-07-28 era** `tools/list` | `{"name":"ksql-mcp","version":"3.34.0"}` |
| **2026-07-28 era** `resources/list` | `{"name":"ksql-mcp","version":"3.34.0"}` |
| **2026-07-28 era** `tools/call` | `{"name":"ksql-mcp","version":"3.34.0"}` |
| **2025 era**（従来の `initialize`） | **無し** |

---

## 2. **ただし条件が 2 つあります**

### 2.1 クライアントが 2026-07-28 era で繋いでいること

**従来の `initialize` で繋いだ接続には、いっさい押されません。**
**仕様がそう定めています**（旧 era に新しい語彙を混ぜない、という設計）。

**判別方法**——**応答に `_meta` があるかどうかがそのまま答えになります。**
**載っていれば新しい era**です。

### 2.2 `_meta` は機械可読であって、画面に出るものではない

**クライアントが利用者へ提示しなければ、人の目には触れません。**

**つまり「気づかせてくれる」わけではありません。**
**Pro が自分で読みに行けば、確実に分かるようになった**——という位置づけです。

---

## 3. 何が変わって、何が変わらないか

| | |
|---|---|
| **版ずれの検出** | **できるようになりました**（`_meta` を読む） |
| **版ずれの解消** | **従来どおり再起動が必要です。**プロセス内のモジュールは差し替わりません |
| **kSQL 側の対応** | **不要でした。**標準の仕組みが SDK 側で動いています |

**測定の前に `_meta` の版数を確認する**——これを手順に入れていただければ、
**今回のような取り違えは、測定を始める前に分かります。**

---

## 4. こちらの課題として起票しました

**[B101](ksql_b101_mcp_stale_process_version_issue.md)** として残しています。

**当初は「`ksql_docs` の出力に版数を 1 行足す」案を書いていましたが、取り下げました。**
**標準がある場所に、別の作法を足すことになるためです。**

**残しているのは「利用者が疑わなくても気づける」ようにする案**
（焼き込んだ版とディスク上の版を突き合わせて、ずれていたら知らせる）ですが、
**優先度は 低 と判断しています。**誤った結果を返す問題ではないためです。

**Pro 側で追加の対応は不要です。**
