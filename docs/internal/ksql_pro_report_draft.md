#### ⚠ v3.25.0 は破壊的変更を含みます（`^3` に自動更新で届きます）

**① ユーザー系・複数選択系フィールドへの `=`**

```sql
WHERE 作成者 = 'taro'        -- ❌ エラー（従来は黙って0件）
→ WHERE 作成者 in ('taro')   -- ✅
```

対象は `CREATOR` / `MODIFIER` / `CHECK_BOX` / `MULTI_SELECT`。
`ドロップダウン` / `ラジオボタン` / `ステータス` は対象外。

**② 押し下げできない位置の `TODAY()` / `NOW()` / `LOGINUSER()`**

`OR`・JOIN・入れ子 SELECT・実体化文脈の `UNION` 枝にあるものはエラー化。
`TODAY()`/`NOW()` は実行環境の TZ 依存、`LOGINUSER()` は常に空文字（＝必ず0件）だったため。

**③ 型に合わない関数の組み合わせ**（`WHERE 日付 = NOW()`、`WHERE $id >= TODAY()`）

**`CURRENT_DATE()` / `CURRENT_TIMESTAMP()` は対象外**（押し下げ経路が無く常にローカル TZ で評価）。
D10 レシピで使用中のため留意。

#### 🎉 新しく使えるようになったこと

```sql
SELECT $id, 件名 FROM APP100 WHERE 作成者 in (LOGINUSER())   -- v3.25.0 から
```

実機 console で動く形が kSQL でも書けるようになりました。
対象は `作成者` / `更新者` / ユーザー選択 × `in` / `not in`。
**`グループ選択` は不可**（kintone 公式表でも関数「なし」）。**単独要素のみ**。

`TODAY()` / `NOW()` は相対日付と同じ計画を共有するため、**押し下げできる形はむしろ増えました**。

```sql
WHERE 日付 = TODAY() AND LENGTH(件名) > 1
-- 従来: 全件取得＋クライアント評価
-- v3.25.0: 日付 = TODAY() をサーバーへ押し下げ
```

相対日付が CTE・一時テーブルでも使えます（v3.25.0）。
ただし押し下げ不能な述語が `AND` で混ざる形は、トップレベルでのみ使えます。

#### GROUP BY エイリアス（v3.23.0・K-14）

正しく集計されます。名前の解決順は **同名フィールド優先 → SELECT のエイリアス**。

#### 📊 D10 レシピについて

JOIN の押し下げを調査したところ、**現行の D10 は両アプリとも全件取得**でした。

- `DATE_FORMAT(a.受注日,'%Y-%m') = ...` — 関数付きのため押し下げ不可
- `t.年月 = '2026-07'` — TEXT のため JOIN では押し下げ不可（**v3.26.0 で改善**）

当面の緩和策は `$id` または数値フィールドの述語を `AND` で足すこと（例 `AND a.$id > 200000`）。
