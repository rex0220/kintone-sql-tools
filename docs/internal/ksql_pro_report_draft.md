## 1. 🎉 JOIN で相対日付・kintone 関数が使えるようになりました（v3.28.0）

**ご報告の本命ケースです。**

```sql
SELECT a.担当者, SUM(a.受注金額) AS 売上
FROM APP100 a JOIN APP200 t ON a.担当者 = t.担当者
WHERE a.受注日 = THIS_MONTH()
GROUP BY a.担当者
```

`THIS_MONTH()` が **kintone サーバーへそのまま渡ります**（クライアント評価は 0 回）。
対象は相対日付 12 関数と `TODAY()` / `NOW()` / `LOGINUSER()` の計 15 関数です。

### 使える形

**A. WHERE 全体が片方のアプリだけを参照する形** — `OR` / `NOT` も使えます。

```sql
WHERE a.受注日 = THIS_MONTH() OR a.受注日 = LAST_MONTH()
WHERE NOT (a.受注日 = THIS_MONTH())
```

**B. `AND` でつないだ形** — 関数の部分だけがサーバーへ渡り、残りをクライアントで評価します。
**複数アプリに分散していても、それぞれのアプリへ渡ります。**

```sql
WHERE a.受注日 = THIS_MONTH() AND t.更新日時 >= TODAY() AND LENGTH(a.件名) > 1
-- APP100 へ 受注日 = THIS_MONTH()
-- APP200 へ 更新日時 >= TODAY()
-- クライアント評価は LENGTH(a.件名) > 1 のみ
```

### 使えない形

- **`LEFT` / `RIGHT JOIN`**（外部結合）
- **アプリをまたぐ `OR`** — `WHERE a.受注日 = THIS_MONTH() OR t.更新日時 >= TODAY()`
- JOIN の入力が CTE・一時テーブル・サブテーブル・入れ子 SELECT・派生表の形
- `グループ選択` への `LOGINUSER()`（kintone 公式に対応するクエリ関数がありません）

いずれもレコード取得前にエラーになります（黙って誤った結果を返すことはありません）。

### `EXPLAIN` で確認できます

```sql
EXPLAIN SELECT ... FROM APP100 a JOIN APP200 t ON ... WHERE a.受注日 = THIS_MONTH()
```

```text
pushdown applied: 受注日 = THIS_MONTH()
relation: exact
client residual: (none)
relative date client evaluations: 0
```

**拒否される形も `EXPLAIN` はエラーにならず**、理由を表示します。
`EXPLAIN` の判定と実行の判定は一致するので、**流す前に確認できます**。

```text
plan status: rejected
reason: WHERE_RELATIVE_DATE_REQUIRES_EXACT_PUSHDOWN
client evaluation: forbidden
```

## 2. ⚠ 破壊的変更（`^3` に自動更新で届いています）

### v3.25.0 ① ユーザー系・複数選択系フィールドへの `=`

```sql
WHERE 作成者 = 'taro'        -- ❌ エラー（従来は黙って 0 件）
→ WHERE 作成者 in ('taro')   -- ✅
```

対象は `作成者` / `更新者` / `チェックボックス` / `複数選択`。
`ドロップダウン` / `ラジオボタン` / `ステータス` は**対象外**（従来どおり `=` が使えます）。

**従来は黙って 0 件を返していた**ため、エラー化によって正しい結果が失われることはありません。

### v3.25.0 ② 押し下げできない位置の `TODAY()` / `NOW()` / `LOGINUSER()`

`OR`・入れ子 SELECT・実体化文脈の `UNION` 枝にあるものはエラーになります。
`TODAY()` / `NOW()` は実行環境の TZ 依存、**`LOGINUSER()` は常に空文字＝必ず 0 件**だったためです。

> **JOIN については v3.28.0 で大きく緩和されました**（§1）。
> v3.25.0 時点で JOIN がエラーになっていた形の多くは、v3.28.0 でそのまま通ります。

### v3.25.0 ③ 型に合わない関数の組み合わせ

`WHERE 日付 = NOW()`（日付フィールドに `NOW()` は kintone 公式でも不可）、`WHERE $id >= TODAY()` など。

**`CURRENT_DATE()` / `CURRENT_TIMESTAMP()` は対象外**です（押し下げ経路が無く常にローカル TZ で評価）。
D10 レシピで使用中のため留意してください（§4）。

### v3.27.0 ④ 外部結合＋検索打ち切り

`LEFT` / `RIGHT JOIN` を含むクエリの検索が 10 万件で打ち切られた場合、
警告付きの部分結果ではなく **エラーで終了**します。

従来は行が減るのではなく、**結合相手を取得できなかった行が null 拡張され「該当なし」という誤った値**に
なっていました。行の欠落は警告で気づけますが、**値が間違うのはその行自体が正しく見えるため気づけません**
（集計で合計や平均が静かにずれます）。**現在成功して見えるクエリは実際には誤った値を返している**ため、
エラー化によって正しい結果が失われることはありません。

`INNER JOIN` と単一表は従来どおり警告＋部分結果です。

> **engine ライブラリをお使いの場合は影響ありません。** ライブラリは従来から全クエリ形で
> 打ち切りを hard error として扱っています（部分結果が黙ってアプリロジックへ流れ込むほうが
> 危険なため、意図的に厳格な契約にしています）。

## 3. 🎉 その他の改善

### ログインユーザーでの絞り込み（v3.25.0）

```sql
SELECT $id, 件名 FROM APP100 WHERE 作成者 in (LOGINUSER())
```

実機 console で動く形が kSQL でも書けるようになりました。
対象は `作成者` / `更新者` / `ユーザー選択` × `in` / `not in`、**単独要素のみ**。
`グループ選択` は不可です（kintone 公式表でも関数「なし」）。

### 相対日付が CTE・一時テーブル・派生表で使える（v3.25.0）

```sql
WITH cur AS (
  SELECT 担当者, SUM(受注金額) AS 売上 FROM APP100 WHERE 受注日 = THIS_MONTH() GROUP BY 担当者
)
SELECT * FROM cur
```

### `TODAY()` / `NOW()` の押し下げが増えた（v3.25.0）

```sql
WHERE 日付 = TODAY() AND LENGTH(件名) > 1
-- 従来: 全件取得＋クライアント評価
-- v3.25.0 以降: 日付 = TODAY() をサーバーへ押し下げ
```

### JOIN 述語の押し下げ（v3.26.0・挙動不変の性能改善）

`INNER JOIN` で、日付・文字列・選択系の述語がアプリごとにサーバーへ渡るようになりました。
押し下げ後も元の `WHERE` をクライアントで再評価するため**結果は変わらず**、
取得する候補件数だけが減ります。

### engine ライブラリのエラー理由（v3.27.0）

`KLIKE` / `NOT KLIKE` の検証に失敗したとき、構文自体は正しいのに一律
`SQL statement could not be parsed` と返していた誤導的なメッセージを修正しました。
プラグイン / CLI / MCP と同じ具体的な理由が返ります。

**エラー `code` は従来どおり `PARSE_ERROR`** なので、`code` で分岐しているコードは影響を受けません。

### GROUP BY エイリアス（v3.23.0・K-14）

正しく集計されます。名前の解決順は **同名フィールド優先 → SELECT のエイリアス**。

## 4. 📊 D10 レシピ — 書き換えのご提案

現行の D10 は **両アプリとも全件取得**になっています。実機の `EXPLAIN` で確認しました。

```sql
-- 現行
WHERE DATE_FORMAT(a.受注日,'%Y-%m') = DATE_FORMAT(CURRENT_DATE(),'%Y-%m')
```

```text
kintone query: (全件取得)
client residual: DATE_FORMAT(a.受注日, '%Y-%m') = DATE_FORMAT(CURRENT_DATE(), '%Y-%m')
```

**フィールドを関数で包むと押し下げできません。** `DATE_FORMAT(a.受注日, ...)` の時点で
kintone のクエリとして表現できなくなるためです。

### ✅ `THIS_MONTH()` に書き換えると押し下がります

```sql
-- 提案
WHERE a.受注日 = THIS_MONTH()
```

```text
pushdown applied: 受注日 = THIS_MONTH()
relation: exact
client residual: (none)
relative date client evaluations: 0
```

**同じ「当月」の意味で、全件取得が当月分のみの取得になります。**
これが v3.28.0 で可能になった最大の変化です。

`t.年月 = '2026-07'` のような JOIN 相手側の文字列述語も、v3.26.0 から押し下げ対象です。

> **なお、述語が付いていないアプリは引き続き全件取得です。**
> 上の例では APP200 側に条件が無いため APP200 は全件取得のままです。
> 結合相手側も絞りたい場合は、そちらにも `WHERE` 条件を付けてください。
