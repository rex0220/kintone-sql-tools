# B82 リリース時に公開文書の未リリース表記を検出する

- 起票: 2026-07-27
- ステータス: ✅ **実装済み（未リリース・次回リリースに同梱）**。B70 §7 の残作業を課題化して実装した。
- 出典: B70 §7（v3.27.0 の docs 作業時に codex が検出）
- 関連: [B70 版数同期ガード](ksql_b70_docs_smoke_version_pin_issue.md) / [B81 MCP 語数予算](ksql_b81_mcp_instructions_word_budget_issue.md)

## 1. 事象

**v3.25.0 でリリース済みの B75 / B77 / B78 が、言語リファレンスでは
「Unreleased の破壊的変更」のまま出荷された**（2箇所）。

```
docs/ksql_language_reference.md:10   > **⚠ Unreleased の破壊的変更（minor リリース）**
docs/ksql_language_reference.md:758  > **⚠ Unreleased 移行注意（minor だが破壊的）:**
```

リリース時に `CHANGELOG.md` の `## Unreleased` → `## vX.Y.Z` は直したが、
**言語リファレンスの同種表記を見落とした**。

## 2. 原因＝version-sync-guard の守備範囲外

B70 の `version-sync-guard` は**版数の一致**（8箇所）を検査するもので、
**「Unreleased」という語が残っていること**は別の失敗モードであり対象外だった。

同種の事故は再発している。

| 版 | 残っていた前方参照 |
|---|---|
| v3.25.0 | 言語リファレンスの「Unreleased の破壊的変更」×2 |
| v3.28.0 | `release/README.txt` の「**次回リリース予定の** B76 Phase B で上記2形を追加」 |
| v3.28.0 | `CHANGELOG.md` の「**次回リリースの** B76 Phase B で上記第5許可形を追加」 |

後者2件はリリース作業中に人手で見つけて直したが、**気づかなければそのまま出荷していた**。
「次回リリース」という前方参照は、**そのリリースが出た瞬間に誤りになる**性質を持つ。

## 3. 実装

`scripts/version-sync-guard.mjs` に **`--release` モード**を追加した。

- 対象: `docs/ksql_language_reference.md` / `release/README.txt`
- 検出語: `Unreleased` / `未リリース` / `次回リリース`
- **`CHANGELOG.md` は対象外**。開発中に `## 未リリース` 見出しを持つのが正常で、
  リリース時に版数見出しへ確定させる運用のため
- 失敗時は**ファイル名・行番号・該当行**を出す

配線:

| 実行経路 | モード | 挙動 |
|---|---|---|
| `npm test` → `version:check` | 通常 | **従来どおり**。未リリース機能の記述は正常なので失敗させない |
| `npm run prepack` → `version:check:release` | `--release` | 未リリース表記が残っていたら **exit 1 でリリースを止める** |

開発中に失敗させない点が要件である。仕様策定中のドキュメントに未リリース機能の
記述があるのは正常なので、そこで止めると邪魔にしかならない。

## 4. 検証

v3.25.0 と同じ形の取り残しを再現して確認した。

```
[version-sync] 2 problem(s) found:
- docs/ksql_language_reference.md:3: 未リリース表記「Unreleased」が残っています -> > **⚠ Unreleased の破壊的変更（minor リリース）**
- release/README.txt:3: 未リリース表記「次回リリース」が残っています -> 次回リリース予定: 何か
```

- **リリースモードの exit code = 1**（prepack が止まる）
- **通常モードの exit code = 0**（開発を妨げない）
- 取り残しを戻すと両モードとも green

## 5. 影響・規模

- **公開挙動の変更なし**（リリース工程のガードのみ）
- 0.25 人日
- B70 と同じ「**先に片付ける小さな仕組み**」であり、単独では小さいが
  踏むのはリリース直前の最も焦る場面である

## 6. 残る限界

**語の一致で検出するため、前方参照が別の言い回しなら捕まらない**
（例:「今後のリリースで対応予定」）。完全な検出は不可能なので、
**版に依存しない表現で書く**という書き方そのものを守るほうが本質的である。
リリース履歴の書き方の約束（[`ksql_release_history.md`](../ksql_release_history.md)）に沿って、
公開文書でも「次回リリース」ではなく具体的な版数か、版に依存しない表現を使うこと。
