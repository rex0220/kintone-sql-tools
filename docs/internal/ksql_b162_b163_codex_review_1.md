## 確認内容

1. **依頼した共通原則が立っている**＝情報の 3 分類（静的確定／条件付き静的／実行時）＋
   B131 クラスとの線引き表（§2）。「条件付き静的情報は出所と限界を同じブロックに表示」の
   規範が 2 件を貫く
2. **B162 の方式選定が的確**＝案 A を**系列引数に限定**適用＋案 B fallback。
   **全変数用途への既定値束縛が危険な理由を §5 で網羅列挙**（pushdown 表示の確定化・
   実在判定・機密値表示・dry-run metadata 要否まで）——「安いから全部」へ流れない
   Phase 統制が明文。案 C 単独の棄却理由（静的に計画可能な形が運用問題のまま残る）も正しい
3. **B163 の費用判断が実装事実に基づく**＝既存部品（EXPLAIN relation 列推論・
   `initialRelations`・materialized columns 入力・plain GROUP BY planner・B148 検査）が
   揃っており、欠けているのは**バッチ文間の静的 schema ledger の配線だけ**とファイル:行で特定。
   案 C 先行を「費用上の理由がない」と棄却し、防御契約（InternalError 禁止・
   **文字列 catch での置換禁止＝構造化分類**）を同 Phase に含める
4. **先回りが 2 つ**: ①外部注入値を系列計画に使うと rows/type 経由の**間接漏えい**が起こる
   （Phase 1 では注入値不使用・既存の値非公開契約を維持）②schema ledger を
   `buildExplainWhereAnalysis` 内だけに置くと **B155 静的経路で schema が再び消える**
   （B158 修正 1 と同じ穴の再発防止を仕様が明文で禁止）
5. **deferred の意味規律**＝「正常実行の保証ではない」（§2.3-7）・空 schema での確定禁止
   （§7.5＝空 schema は「列が無い」という誤情報）
6. 受入は起票 2 件の逐語＋deferred 形＋波及非回帰＋B155/B157/B161 非回帰＋DROP/連鎖まで網羅
