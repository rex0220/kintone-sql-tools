# 課題: 切り出し・桁揃え関数がサロゲートペアを分割する（B22）

- 作成日: 2026-07-17
- 位置づけ: B20（正規表現関数）の仕様検討中、`u` フラグの扱いを調べる過程で発見。**B20 / B21 とは独立した既存の欠陥**。
- ステータス: **課題 R1（codex レビュー前）。未実装。**
- 分担: Claude=仕様/観点、Codex=実装/テスト
- 台帳: [ksql_issue_tracker.md](../ksql_issue_tracker.md)

---

## 0. 要約

**`LEFT` / `RIGHT` / `SUBSTRING` / `LPAD` / `RPAD` が、サロゲートペアを途中で割って孤立サロゲート（不正な文字）を返す。**

```
LEFT('𩸽あ😀', 1)      = "\ud867"     ← 孤立した上位サロゲート
RIGHT('𩸽あ😀', 1)     = "\ude00"     ← 孤立した下位サロゲート
SUBSTRING('𩸽あ😀', 1, 1) = "\ud867"
LPAD('😀😀', 3, '0')   = "😀\ud83d"   ← 切り詰めで割れる
LPAD('7', 4, '😀')     = "😀\ud83d7"  ← 埋め文字列そのものが割れる
RPAD('7', 4, '😀')     = "7😀\ud83d"
```

**採用する対策は「UTF-16 のまま、ペアを割る位置では短い方へ寄せる」（§3 案 C）。** 「コードポイント単位にする」（案 A）と「書記素単位にする」（案 B）は、**どちらも kSQL では別の壊れ方をするため却下する**（§3 に経緯を残す）。

---

## 1. 現象（実機実測）

`𩸽`（U+29E3D）と `😀`（U+1F600）はサロゲートペア（各 2 コードユニット）。`'𩸽あ😀'` は **5 コードユニット / 3 文字**。

| 式 | 結果 | 問題 |
|---|---|---|
| `LEFT('𩸽あ😀', 1)` | `"\ud867"` | 上位サロゲート単独＝文字として不正 |
| `RIGHT('𩸽あ😀', 1)` | `"\ude00"` | 下位サロゲート単独 |
| `SUBSTRING('𩸽あ😀', 1, 1)` | `"\ud867"` | 同上 |
| `LPAD('😀😀', 3, '0')` | `"😀\ud83d"` | `str.length >= n` の切り詰め（`evalFunc.ts`）が割る |
| `LPAD('7', 4, '😀')` | `"😀\ud83d7"` | **`padStart` が埋め文字列を 3 ユニットに切って割る** |
| `RPAD('7', 4, '😀')` | `"7😀\ud83d"` | 同上 |

**`LPAD` / `RPAD` は 2 経路で壊れる**（切り詰めと埋め）。**どちらも B19（v2.17.0）で追加したばかりの関数**であり、`LPAD` は「桁揃え・0 埋め」という**書き込み前提の用途**で入れたため、壊れた値が kintone へ流れ得る。

**B19 の受入条件は `LEFT`/`RIGHT`/`SUBSTRING` の文字単位が相互に一致することは確認したが、サロゲートを割ること自体の是非は見ていなかった**（`process.test.ts` の「B19 の文字数単位は LENGTH / SUBSTRING と一致する」）。

### 1.1 副次: `LIKE` だけ単位が違う（本課題では変更しない）

```
'😀' LIKE '_'   → 一致    ← matchLike（evalWhere.ts:370）は "u" フラグ＝コードポイント
'ab'  LIKE '_'  → 不一致  （対照・正常）
LENGTH('😀')    = 2       ← UTF-16 コードユニット
```

`LIKE '_'` は既にコードポイント単位で、`LENGTH` と食い違っている。**本課題では変更しない**（`LIKE` の意味論変更は v2.0.0 級の影響があり、別課題）。§5 に記載する。

## 2. `LENGTH` は UTF-16 のままでなければならない（実機実測）

**これが対策案を決める制約。**

`APP4221` の `文字列MAX`（maxLength = 10）に対する `VALIDATE ONLY`（書き込みゼロ）:

| 値 | UTF-16 | コードポイント | 結果 |
|---|---|---|---|
| `😀`×5 | **10** | 5 | **通過** |
| `😀`×6 | **12** | 6 | **`ERR_LENGTH_MAX`「文字列MAX は 10 文字以下で指定してください」** |
| `あ`×10 | 10 | 10 | 通過 |
| `あ`×19 | 19 | 19 | `ERR_LENGTH_MAX` |

**コードポイント計数なら `😀`×6 は 6 ≤ 10 で通るはずが、弾かれた。** kSQL の Tier-0 検証（B12-A）は **UTF-16 コードユニットで数えている**ことが確定。

これは **B12-A が kintone 本体を実測して確定した仕様**に合わせたもの（[VALIDATE ONLY 実装計画](ksql_validate_only_implementation_plan.md)。「計数は UTF-16 code units」「未設定制約は空文字」「`minLength` は空文字・未指定にも適用」を実機で確定）。

**kintone がそう数える以上、`LENGTH` を変えることはできない** — `LENGTH` は「この値はフィールドに収まるか」を判定する唯一の手段だから。

---

## 3. 対策案の比較（R1 で確定）

### 3.1 案 A: コードポイント単位にする（`[...str]`）— **却下**

`[...str]` / `for...of` はコードポイント単位のイテレータを使うため、サロゲートペアを割らない。**JS の対処としては正しい**が、kSQL では 2 つ壊れる。

**① `LENGTH` と単位が食い違う**

```
LEFT('𩸽あ😀', 1) = '𩸽'  → LENGTH(結果) = 2   ← 1 を頼んだのに 2
LEFT('😀😀😀', 2) = '😀😀' → LENGTH(結果) = 4   ← 2 を頼んだのに 4
```

**② 決定的: 「フィールド上限に収める」が壊れる**

```
maxLength = 64 の欄へ LEFT(x, 64) で詰める（x = 😀×40 = 80 ユニット）
  コードポイント版 → 結果は 80 ユニット → ERR_LENGTH_MAX で拒否される
```

**kintone で `LEFT` / `SUBSTRING` を使う第一の用途は「上限に収める切り詰め」**である。§2 のとおり `LENGTH` は UTF-16 から動かせないため、`LEFT` だけコードポイントにすると **切り詰めた結果が kSQL 自身の検証に弾かれる**という壊れ方をする。**現状（孤立サロゲート）より悪い**とは言わないが、**別の壊れ方に置き換えるだけ**で解決にならない。

### 3.2 案 B: 書記素クラスター単位にする（`Intl.Segmenter`）— **却下**

`Intl.Segmenter` なら結合文字・ZWJ 絵文字・国旗・異体字セレクタまで 1 文字として扱える（Node で実測: `👨‍👩‍👧‍👦` は 11 ユニット / 7 コードポイント / **1 書記素**）。**「人間の見た目の文字数」としては最も正しい。**

**却下理由:**

| # | 理由 |
|---|---|
| 1 | **ホストエンジン依存**。`Intl.Segmenter` は **Firefox 125（2024 年 4 月）でようやく対応**した。**プラグインは利用者のブラウザで動く**ため、Firefox ESR 115 等では `TypeError` になる。B20 仕様 §3.1 で「最も重い残存リスク」とした問題と同型で、**そちらは回避不能だから受け入れたのに対し、本件は案 C を選べば回避できる** |
| 2 | **locale 依存**。`new Intl.Segmenter('ja', …)` の第 1 引数で結果が変わり得る。kSQL の他の関数に locale 依存は無い |
| 3 | **`LENGTH` との乖離が案 A より大きい**。`👨‍👩‍👧‍👦` を kintone は 11 と数えるのに 1 と数える単位を混ぜると、①の用途がさらに壊れる |

**ただし将来の別関数としては有力**（§6）。

### 3.3 案 C: UTF-16 のまま、割る位置では短い方へ寄せる — **採用**

> **結果は常に「n コードユニット以下」かつ「孤立サロゲートを含まない」。**

```
LEFT(x, n)  : x[n-1] が上位サロゲートなら n-1 で切る
RIGHT(x, n) : 開始位置が下位サロゲートなら 1 つ進める
SUBSTRING   : 開始・終了の両方に同じ調整
LPAD/RPAD   : 切り詰めは LEFT と同じ。埋めは「埋め文字列の全体（コードポイント単位）」でのみ行い、
              残りが埋め文字 1 つ分に満たなければ埋めずに終える（＝ n 未満で返す）
```

**プロトタイプで `LEFT`/`RIGHT`/`SUBSTRING` の全境界を検証済み**（`'𩸽あ😀'` に対し n = 0〜5 と `SUBSTRING` の開始×長さ）: **全ケースで孤立サロゲートなし・常に n 以下**。

| | `LENGTH` と同単位 | 上限に必ず収まる | 割れない | ホスト依存なし |
|---|---|---|---|---|
| 現状 | ✅ | ✅ | ❌ | ✅ |
| 案 A コードポイント | ❌ | ❌ | ✅ | ✅ |
| 案 B 書記素 | ❌❌ | ❌ | ✅ | **❌** |
| **案 C 境界調整** | ✅ | ✅ | ✅ | ✅ |

#### 案 C で受け入れる違和感

```
LEFT('𩸽あ😀', 1)  = ''      （'𩸽' は 2 ユニットなので 1 ユニットには収まらない）
RIGHT('𩸽あ😀', 1) = ''
LPAD('7', 4, '😀') = '😀7'   （3 ユニット。残り 1 ユニットに '😀' は入らない）
```

**「1 コードユニットに収まる先頭部分は存在しない」という正しい答え**であり、壊れた半分を返すより良い。**入力を捨てず、静かに壊さない**という B1 / B16 / B19（`GREATEST` の tie-break で `'007'` の桁揃えを保持した判断）と同じ方針。

**リファレンスに明記する**: 「切り出しはコードユニット単位。サロゲートペアを割る位置では、割らずに短くなる方向へ寄せる。結果は必ず指定した長さ以下になる」。

## 4. SemVer

**minor**。

- **挙動変更を含む**（孤立サロゲートを返していた式が、より短い正しい値を返すようになる）
- ただし**変わるのは「壊れた値を返していたケース」だけ**であり、**誤った成功を正しい結果へ変える**方向。B19 の `DATE_ADD` 不正単位（黙って DAY → `ArgumentError`）と同じ判断
- サロゲートペアを含まない値（ほぼ全ての実データ）の挙動は**完全に不変**

## 5. 対象外

| 項目 | 判断 |
|---|---|
| `LENGTH` の単位 | **変更しない**。kintone が UTF-16 で数える以上、変えると「収まるか」の判定ができなくなる（§2） |
| `LIKE '_'` がコードポイント単位である件（§1.1） | **本課題では変更しない**。`LIKE` の意味論変更は v2.0.0 級の影響。別課題として起票の価値はあるが、`_` を単独で使う実需は薄い |
| `INSTR` の戻り値 | **変更しない**。コードユニット位置を返すのが `LENGTH` / `SUBSTRING` と整合する |
| 書記素クラスター（結合文字・ZWJ 絵文字・国旗・異体字セレクタ） | **本課題の対象外**。案 C は**サロゲートペアを割らない**ことだけを保証し、`👨‍👩‍👧‍👦` は依然として分割され得る（§6） |

## 6. 将来候補: `Intl.Segmenter` による書記素対応

`LENGTH_GRAPHEME(x)` のような**別関数**として足せば、既存の単位を壊さずに「人間の見た目の文字数」を提供できる。

**設計上の注意**:

- **ホスト依存を fail-closed にする**。`typeof Intl.Segmenter === 'undefined'` なら `ArgumentError`（Firefox ESR 等で黙って別の値を返さない）
- locale を固定するか、引数で明示させる
- **`LENGTH` を置き換えてはならない**（kintone の計数と乖離する）

---

## 7. 受入条件

- [ ] **孤立サロゲートを返さない**: `LEFT` / `RIGHT` / `SUBSTRING` / `LPAD` / `RPAD` のいずれも、結果に孤立した上位・下位サロゲートを含まない
- [ ] **常に n 以下**: `LENGTH(LEFT(x, n)) <= n` が全ての n で成り立つ（`RIGHT` / `LPAD` / `RPAD` も同様）
- [ ] **境界の全数テスト**: `'𩸽あ😀'`（5 ユニット / 3 文字）に対し `LEFT` / `RIGHT` を n = 0〜5 の全てで検証。`SUBSTRING` は開始 1〜5 × 長さ 1〜5 と長さ省略
- [ ] **`LPAD` / `RPAD` の 2 経路**: ①切り詰め `LPAD('😀😀', 3, '0')` が `"😀\ud83d"` にならない ②**埋め文字列** `LPAD('7', 4, '😀')` が `"😀\ud83d7"` にならない
- [ ] **上限に収まる**: `LEFT('😀'×40, 64)` が **64 コードユニット以下**で、`文字列MAX`（maxLength = 10）相当の `VALIDATE ONLY` を通る
- [ ] **非回帰**: サロゲートペアを含まない値（`'ABCDE'` / `'東京都千代田区'`）で B19 の既存テストが全て pass。特に `LEFT(s,2)` = `SUBSTRING(s,1,2)` の相互一致
- [ ] **`LENGTH` は不変**: `LENGTH('😀')` = `2`（UTF-16・§2 の制約）
- [ ] **`LIKE` は不変**: `'😀' LIKE '_'` は引き続き一致（§5・本課題の対象外）
- [ ] **`INSTR` は不変**: コードユニット位置を返す
- [ ] **書き込み経路**: `CREATE TEMP TABLE … AS SELECT LEFT(…)` → `UPDATE … FROM` で、孤立サロゲートが kintone へ流れない
