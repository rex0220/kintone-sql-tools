# kintone の文字列とソートの仕様まとめ — 公式ドキュメントと実機検証

kintone の「文字数の数え方」と「並び順」の仕様は、複数の公式ページ（cybozu developer network / kintone ヘルプ）に分散していて全体像が掴みにくく、公式に書かれていない挙動もあります。kintone のデータを外部ツールから正確に扱う必要があり、公式仕様の突き合わせと実機検証を行ったので、結果をまとめます。

**凡例**

| マーク | 意味 |
|---|---|
| ✅ 公式 | 公式ドキュメントに規定がある |
| 🔬 実測 | 実機（cybozu.com・2026年7月時点）で確認した。公式の保証ではない |
| ❓ 未確認 | 公式規定が見つからず、実測もしていない。依存しないこと |

実測はいずれも特定環境・特定時点のものです。公式に規定のない挙動は、予告なく変わる可能性があります。

---

## 1. 文字数は UTF-16 コードユニットで数える

kintone の文字列（1行）フィールドの「文字数の制限」（minLength / maxLength）は、**UTF-16 コードユニット単位**で数えます 🔬。JavaScript の `str.length` と同じ数え方です。

| 例 | 見た目 | UTF-16 | コードポイント | 書記素（人間の1文字） |
|---|---|---:|---:|---:|
| `あ` | 1文字 | 1 | 1 | 1 |
| `😀` (U+1F600) | 1文字 | **2** | 1 | 1 |
| `𩸽` (U+29E3D・ほっけ) | 1文字 | **2** | 1 | 1 |
| `葛󠄀` (U+845B + 異体字セレクタ U+E0100) | 1文字 | **3** | 2 | 1 |
| `が` (U+304B + 結合濁点 U+3099・NFD) | 1文字 | 2 | 2 | 1 |

実務上の帰結:

- **maxLength=10 のフィールドに絵文字は 5 個しか入りません** 🔬
- サロゲートペア（絵文字・𩸽 のような追加漢字）は 2 と数えます
- **minLength も UTF-16 単位です** 🔬: 「2文字より長く」（minLength=3）制約のフィールドへ `😀😀`（見た目 2 文字・コードポイント 2・UTF-16 で 4）を書き込むと**受理されました**。書記素やコードポイントで数えるなら 2 文字なので拒否されるはずです
- `が` (U+304C・NFC) と `が` (U+304B U+3099・NFD) は**見た目が同じでも別の文字列**です。kintone は Unicode 正規化を行いません 🔬 — NFD のまま書き込むと NFD のまま保存され、文字数も 2 のままです（NFC 化されるなら 1 になるはず）

JavaScript カスタマイズで文字数を検査するなら `str.length` がそのまま kintone と一致します。「人間が見た文字数」（書記素）で数えたい場合は `Intl.Segmenter` が必要ですが、それは kintone の数え方とは**一致しなくなる**点に注意してください。

### サロゲートペアを分断する切り出しの罠

maxLength に収める目的で `slice` / `substring` を使うと、切断位置がサロゲートペアの中間に落ちることがあります:

```js
'あ😀い'.slice(0, 2)   // → "あ\uD83D" — 😀 の前半だけが残る（単独サロゲート）
```

単独サロゲートは Unicode として不正な文字列で、表示は文字化け（�）になり、API 連携先によってはエラーや置換の原因になります。切り詰めるときは「長さは UTF-16 で数えつつ、境界はコードポイント（できれば書記素）を跨がない位置に丸める」実装にしてください。

### 制約を後付けしたアプリの罠

🔬 **kintone は UPDATE（PUT）時にレコード全体を再検証します。** 運用開始後に minLength などの制約を追加した場合、既存レコードが新しい制約に違反していると、**そのフィールドを更新対象にしていなくても** PUT が `CB_VA01` で失敗します。

🔬 minLength は空文字にも適用されます。「空欄なら免除」ではないため、minLength を後付けすると空欄の既存レコードが上記の状態になります。

## 2. ソートできるフィールド

公式ヘルプ「[ソートで選択できるフィールド・項目](https://jp.kintone.help/k/ja/trouble_shooting/app_qa/sort)」の一覧と、REST API（`records.json` の `order by`）へ全フィールド型を 1 つずつ投げた実測 🔬 は**完全に一致**しました。

**ソート可（`order by` に指定できる）** ✅🔬

> レコード番号 / $id / 作成者 / 更新者 / 作成日時 / 更新日時 / 文字列（1行）/ 数値 / 計算 / ラジオボタン / ドロップダウン / 日付 / 時刻 / 日時 / リンク / ルックアップ / ステータス

**ソート不可（`GAIA_IS02` で拒否される）** ✅🔬

> 文字列（複数行）/ リッチエディター / チェックボックス / 複数選択 / ユーザー選択 / 組織選択 / グループ選択 / 作業者 / カテゴリー / 添付ファイル / 関連レコード一覧 / テーブル（サブテーブル内のフィールド含む）/ グループ

拒否時のエラーは全型で同一形式です 🔬:

```
GAIA_IS02: 「<ラベル>」フィールドはソート条件に使用できません。
```

境界が直感に反するところ:

- **リンクはソート可、文字列（複数行）は不可**。「テキストだから」では判断できません
- 計算フィールドは表示形式（数値・日時・時間…）によらず**一律ソート可**です ✅
- ルックアップはコピー元の型で扱われます（NUMBER 基底・テキスト基底とも可を実測 🔬）

## 3. 型ごとの並び順

「ソートできる」ことと「どう並ぶか」は別の問題です。型ごとに第一キーの意味論が違います。

| 型 | 並び順 | 根拠 |
|---|---|---|
| 数値・計算(数値) | 数値順。空セルは ASC で先頭（最小側） | 🔬 |
| 文字列（1行） | **UTF-8 の文字コード順**（公式）＝有効な文字列では **Unicode コードポイント順**。**数字も文字として比較**（`1 → 10 → 2 → 9` の順） | ✅🔬 公式ヘルプ「[文字列（1行）]フィールドの数値が意図どおりにソートされません」＋実測 |
| ドロップダウン / ラジオボタン | **選択肢の定義順**（フォーム設定の並び）。五十音順でもコード順でもない | 🔬✅ |
| ステータス | **プロセス定義順**（後述） | 🔬✅ |
| 作成者 / 更新者 | **ユーザーID順**。表示名順でもログイン名順でもない | ✅ 公式FAQ |
| 日付 / 日時 / 時刻 | 時系列 | 🔬 |
| リンク | 記号・英字は Unicode 符号位置順と整合する結果を確認（`.` < 英字 など） | 🔬（一部） |
| レコード番号 | レコードID順。**ただしアプリコード設定時は後述の注意** | ✅/❓ |

テキストの照合規則には公式規定があります ✅。公式ヘルプ「[［文字列（1行）］フィールドの数値が意図どおりにソートされません](https://jp.kintone.help/k/ja/trouble_shooting/app_trouble/order_numbers_text_field)」に「**UTF-8 の文字コード順でソートされます**」と明記されています。有効な Unicode 文字列では、UTF-8 のバイト順は**コードポイント順と必ず一致**する（Unicode 標準が保証するバイナリソート特性）ため、これは「Unicode コードポイント順」という契約です。次節のとおり実測とも完全に一致します 🔬。

つまり「日本語として自然な辞書順」（読み・五十音・全角半角の同一視）には**なりません** — かなは漢字より前、全角英字は漢字より後ろに来ます。

### サロゲートペアとソート順 — kintone はコードポイント順、JS の既定ソートはコードユニット順

U+10000 以上の文字（絵文字、`𠮷`・`𩸽` のような追加漢字）は、UTF-16 では**サロゲートペア**（上位 U+D800〜DBFF ＋ 下位 U+DC00〜DFFF の 2 コードユニット）で表現されます。絵文字だけの話ではありません — `𠮟`（しかる・U+20B9F）は **2010 年に常用漢字表へ追加された正字**で、人名の `𠮷`（つちよし）とあわせて業務データに普通に現れます。このため「辞書順」には解釈が 2 つ生まれます:

- **コードユニット順**: JavaScript の `str1 < str2` や `Array.prototype.sort()` の既定。サロゲート領域（0xD800〜）は全角英数字（U+FF21〜）より小さいので、**絵文字が全角文字より前**に来る
- **コードポイント順**: 符号位置そのままの順。絵文字（U+1F600）は全角文字（U+FF21）より**後ろ**

kintone がどちらなのか、境界を跨ぐ 8 値を文字列（1行）フィールドに投入し `order by ... asc` で実測しました 🔬:

| 並べ方 | 結果 |
|---|---|
| **kintone `order by`** 🔬 | `A → z → あ → 吉 → Ａ → ～ → 😀 → 𠮷` |
| Unicode コードポイント順 | `A → z → あ → 吉 → Ａ → ～ → 😀 → 𠮷` — **完全一致** |
| JS 既定ソート（コードユニット順） | `A → z → あ → 吉 → 😀 → 𠮷 → Ａ → ～` |
| `localeCompare('ja')`（ICU 照合） | `～ → 😀 → A → Ａ → z → あ → 吉 → 𠮷` |

（A=U+0041、z=U+007A、あ=U+3042、吉=U+5409、Ａ=U+FF21、～=U+FF5E、😀=U+1F600、𠮷=U+20BB7）

**kintone の並びはコードポイント順**でした。実務上の帰結:

- **JS の `sort()` 既定では kintone の並びを再現できません**。食い違うのは、サロゲートペア文字と「U+E000〜U+FFFF の文字」（全角英数字・全角記号・半角カナなど、日本語データに普通に現れる文字）が混在するときです。絵文字が 1 つ混ざっただけで並びが変わります
- `localeCompare('ja')`（ICU 照合）も一致しません。こちらは記号→英字→かな→漢字の順・全角半角をほぼ同一視という、まったく別の並びになります
- 追加漢字はコードポイント順どおり **BMP 漢字の後ろ**にまとまります（`吉` U+5409 < `𠮷` U+20BB7。見た目が近くても隣には並びません）

kintone の並びを JS で再現するには、コードポイント単位の比較関数を書きます:

```js
const byCodePoint = (a, b) => {
  const as = [...a], bs = [...b];  // スプレッドはコードポイント単位に分解する
  const len = Math.min(as.length, bs.length);
  for (let i = 0; i < len; i++) {
    const d = as[i].codePointAt(0) - bs[i].codePointAt(0);
    if (d !== 0) return d;
  }
  return as.length - bs.length;
};
rows.sort((x, y) => byCodePoint(x.value, y.value));
```

この実測は前節の公式契約（UTF-8 の文字コード順＝コードポイント順）と完全に整合します ✅🔬。別の実測でも、**共通接頭辞は短い方が先**（`ab` < `abc`）、**正規化はされない**（NFD の `が` U+304B U+3099 が NFC の `が` U+304C より**前**に並び、同値扱いにもならない。正規化して比較するなら両者は tie になるはずです）、**異体字セレクタも共通接頭辞扱い**（`葛` < `葛󠄀`）と、いずれもコードポイント順どおりでした 🔬。上の `byCodePoint` はこれらもすべて再現します。

### ステータスは states.*.index 昇順

プロセス管理のステータスは、[プロセス管理設定の取得 API](https://cybozu.dev/ja/kintone/docs/rest-api/apps/settings/get-process-management-settings/)（`status.json`）が返す **`states.<ステータス名>.index` の昇順**で並びます ✅。実測でも `未処理(0) → 処理中(1) → 完了(2) → 保留(3)` の定義順になり、文字コード順（保留が先頭になるはず）ではありませんでした 🔬。

`status.json` を使うプログラムの注意点:

- **`index` は文字列型です**（`"0"`, `"1"`, …）✅🔬。辞書順のまま使うと、ステータスが 2 桁になった時点で `"10" < "2"` と壊れます。**必ず数値に変換**してください
- 🔬 **プロセス管理を無効にしたアプリでも、過去の設定が `states` に残って返ります**。「一度も設定していないアプリ」だけが `null` です ✅。有効かどうかは `enable` を見てください
- 必要権限はレコード閲覧（または追加）権限だけです ✅。レコードを読めるユーザーは常に `status.json` も読めます

### レコード番号とアプリコード

アプリコードを設定すると、レコード番号の値は `APPCODE-1` のような**文字列**になります ✅（[フィールド形式](https://cybozu.dev/ja/kintone/docs/overview/field-types/)）。アプリコード未設定ならレコードIDと同じです。

アプリコード付きレコード番号を `order by` に指定したときの並び（数値部分の順か、文字列全体の辞書順か）は**未測定**です ❓。確実にレコードID順で並べたい場合は、次の `$id` を使ってください。

## 4. 同値の並びと `$id` — 「安定した順序」が必要なとき

### order by を省略すると「レコードIDの降順」

✅ [クエリ記法](https://cybozu.dev/ja/kintone/docs/overview/query/)に明記されています。「登録順に返る」と思い込みがちですが、**新しい順**です。

### 同値グループ内の順序は保証されない → `$id` を明示する

`order by 金額 asc` のように 1 キーだけ指定した場合、**同じ値を持つレコード同士の順序は公式に規定されていません** ❓。ページングと組み合わせると、同値の行が取得のたびに入れ替わり、ページ境界で行が重複・欠落する原因になります。

対策は **`$id` を最後のソートキーに明示する**ことです:

```
order by 金額 asc, $id asc
```

🔬 実測では、数値・日付・日時・時刻・リンク・ラジオボタン・ステータスのすべてで、`$id asc` を明示すると同値グループ内が `$id` 昇順に揃いました。ただしこれは実測であって、明示しない場合の順序に公式保証はありません。**「明示する」のが正解**です。

### `$id` はレコード番号の代役になる

✅ 公式クエリ記法に「絞り込み条件と `order by` でレコード番号のフィールドコードを指定する代わりに、`$id` でレコード番号フィールドを指定できます」とあります。`$id` は常に数値なので、アプリコードの影響も受けません。

## 5. クエリの制限 — limit / offset / 演算子

### limit と offset の上限

✅ [レコード取得 API](https://cybozu.dev/ja/kintone/docs/rest-api/records/get-records/) の規定:

- `limit`: 0〜500（省略時 100）
- `offset`: 0〜10,000（省略時 0）

🔬 `offset=10001` を指定しても **HTTP 200 が返ります**（エラーになりません）。しかし公式範囲外であり、その状態でアプリを一覧表示すると警告が表示されます。**「エラーにならないから使える」ではありません。** 10,000 件を超えるデータは、`$id` をカーソルにしたページングで取得してください:

```
($id > 最後に取得したID) order by $id asc limit 500
```

### 演算子はフィールド型ごとに違う

✅ 公式クエリ記法に型×演算子の対応表があります。特に間違えやすいところ:

| フィールド | 使える演算子 | 罠 |
|---|---|---|
| 文字列（1行）・リンク | `=` `!=` `in` `not in` `like` `not like` | **`>` `<` などの範囲演算子は使えない**。投げると `GAIA_IQ03` 🔬 |
| ドロップダウン・ラジオボタン・チェックボックス・複数選択 | `in` `not in` | **`=` は使えない** 🔬（`GAIA_IQ03`） |
| テーブル内・関連レコードのフィールド | `in` `not in` | 日時など通常 `=` が使える型でも `in` が必須 ✅ |
| 数値・計算・日付・時刻・日時 | `=` `!=` `>` `<` `>=` `<=` ほか | 範囲比較ができるのはこちら側だけ |

「テキストフィールドに `>` で範囲検索」は kintone ではできません。範囲で絞りたい値は数値・日付型のフィールドに入れるのが原則です。

### like は「部分一致」ではなく単語検索

✅ 公式に「クエリで文字列検索する場合は単語検索です」と明記されています。🔬 実測では:

- **英語**: 単語単位で一致（`like "test"` は `test` という語を含むレコード。`testing` の一部にはヒットしない）
- **日本語**: 2 文字以上の部分一致に近い挙動

SQL の `LIKE '%...%'` と同じ感覚で使うと結果がずれます。

## 6. 数値の精度はアプリ設定（numberPrecision）

数値フィールドの有効桁数は固定ではなく、**アプリの一般設定**です ✅（[一般設定の取得 API](https://cybozu.dev/ja/kintone/docs/rest-api/apps/settings/get-general-settings/)）。

```json
"numberPrecision": {
  "digits": "16",          // 全体の桁数: 1〜30
  "decimalPlaces": "4",    // 小数部の桁数: 0〜10
  "roundingMode": "HALF_EVEN"  // HALF_EVEN / UP / DOWN
}
```

🔬 `digits: "16"` のアプリへ 17 桁の数値を書き込むと `CB_VA01`（有効桁数を超えています）で拒否されました。**「16 桁で落ちた」はそのアプリの設定であって kintone の上限ではありません**。上限は 30 桁まで広げられます。

外部ツールで kintone の数値を検証・再現する場合は、このアプリ設定を先に取得する必要があります。丸めモードの既定は銀行丸め（HALF_EVEN）です。

---

## 7. 日時フィールドの秒・ミリ秒は保存されない

🔬 日時（DATETIME）フィールドへミリ秒付きの ISO 8601（`2026-07-16T11:21:25.174Z` — `new Date().toISOString()` がまさにこの形式）を書き込むと、**エラーにならず受理され、分単位に切り捨てて保存**されます（`11:21:00Z` になる）。

- 書き込みが成功しても、読み返した値は秒以下が消えています
- 「書いた値と読んだ値が一致する」前提のロジック（差分検出など）はここで壊れます

---

## 8. 「空」の表現が型と API で違う

✅ [フィールド形式](https://cybozu.dev/ja/kintone/docs/overview/field-types/)に規定があります。**同じ「空」でも、フィールド型と API の種類で値が違います**:

| フィールド型 | REST API で取得 | JS API（追加/編集画面） |
|---|---|---|
| 文字列（1行/複数行）・数値・日時・リンク・ルックアップ | `""` | `undefined` |
| 日付・時刻 | `null` | `undefined` |
| ドロップダウン | `null` | `undefined`（それ以外の画面では `""`） |
| ラジオボタン | `null` | `""` |
| チェックボックス・複数選択・ユーザー/組織/グループ選択・添付・テーブル | `[]` | `[]` |

さらに:

- **ラジオボタン・カテゴリー・作業者は、API から空に戻す手段がありません** ✅（空にする値の指定が存在しない）
- クエリの `is empty` は、完全な空だけでなく**空白文字・改行・タブのみの文字列も「空」扱い**です ✅

## 9. まとめ — 外部ツールから kintone を扱うときのチェックリスト

1. 文字数は **UTF-16**（JS の `str.length`）。絵文字は 2 文字（minLength / maxLength とも）。切り詰めはサロゲートペアを分断しない位置で
2. PUT は**レコード全体を再検証**する。後付け制約は既存レコードの更新を止める
3. ソート可否は**型の allowlist**で決まる（リンク可・複数行不可のような直感に反する境界がある）
4. 並び順は型ごとに意味論が違う: テキストは**コードポイント順**の辞書順（JS 既定のコードユニット順ソートとはサロゲートペア混在時にずれる）・選択肢は**定義順**・ステータスは**プロセス定義順**・作成者は**ユーザーID順**
5. `status.json` の `index` は**文字列**。数値に変換してから使う
6. 同値の順序は保証されない。**`$id asc` を最後のキーに明示**する
7. `offset` は 10,000 まで。**200 が返っても 10,001 以上は使わない**。カーソルページングにする
8. テキストに範囲演算子は**ない**。`like` は**単語検索**
9. 数値の桁数上限は**アプリ設定**（最大 30 桁・丸めモード付き）
10. 日時の秒以下は**保存されない**。書いた値は読み返すと変わっている
11. 「空」の表現は型 × API で `""` / `null` / `[]` / `undefined` に分かれる
