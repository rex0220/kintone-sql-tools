# 仕様案: オプションUIのポップアップ化 + タブ切替

## 1. 背景
- 現在のUIは、SQLエディタ周辺にオプション（表示/取得/補助）が常時表示され、画面面積を圧迫している。
- 特に詳細/編集/追加画面では、結果テーブルと併用時に縦方向・横方向の可読性が低下する。

## 2. 目的
- 常時表示を減らし、SQL入力と実行結果を優先表示する。
- 必要なときだけ設定を開ける構造にし、操作性と視認性を両立する。

## 3. 方針
- `⚙ オプション` クリック時のみ、設定パネルをポップアップ表示する。
- ポップアップ内はタブで機能を分離する。
- ポップアップを閉じても、現在設定の要約はヘッダー付近に表示する。
- 表示方式は **ボタンアンカー型ポップオーバー** とする（右寄せドロワーは採用しない）。

## 4. UI構成
1. トリガー
- 既存の `⚙ オプション` ボタンを利用。

2. 表示形式
- `⚙ オプション` ボタン直下にアンカー表示する `ポップオーバー` を採用。
- kintone標準のコメント/履歴UIと競合しないよう、表示位置はボタン基準で算出する。
- 幅は固定幅とする（レスポンシブ時は画面内に収まる範囲で縮小）。
- 閉じる方法:
  - 閉じるボタン
  - `Esc`
  - 外側クリック

3. タブ構成
- `表示`
  - ユーザー（そのまま/名前/コード）
  - 配列（そのまま/カンマ区切り）
  - テーブル（そのまま/行数のみ）
  - 日時（そのまま/ローカル形式）
- `取得`
  - 最大取得件数
  - 上限到達時の動作（エラー/打ち切って続行）
- `保存SQL`
  - 保存SQL一覧
- `フィールド`
  - フィールド一覧
- `履歴` はタブに含めない（現行の履歴UIを維持）。

## 5. 表示ルール
1. 初期状態
- ポップアップは閉じた状態で開始。
- 開いたときの初期タブは「前回開いていたタブ」を復元する。

2. サマリ表示（常時）
- `⚙ オプション` 横に現在値の要約を表示する。
- 例: `表示: 名前/カンマ, 取得: 3000/打ち切り`

3. 編集時の反映
- 値変更は即時反映（保存ボタンなし）。
- 既存仕様どおり、追加/編集画面では保存時にレコード項目へ同期。

## 6. データ反映仕様（既存互換）
1. 表示タブ
- `ユーザー` `配列` `テーブル` `日時` の各項目に反映。

2. 取得タブ
- `最大取得件数` を `maxRecords` に反映（未入力/不正値は 3000）。
- `上限到達時の動作` を `onLimitReached` に反映。

3. 補助機能
- `保存SQL` `フィールド` はタブ内で提供する。
- `履歴` は現行UIを維持し、タブ化しない。

## 6.2 保存タイミング（確定）
1. 追加・編集画面
- オプション変更は画面内表示に即時反映する。
- レコードへの永続化は保存時のみ行う。
- 保存時（submit）に、現在のUI状態を `event.record` へ反映して保存する。

2. 詳細画面
- オプション変更は表示上のみ有効（レコードには保存しない）。
- レコード切り替え時は、対象レコードの値を再読込して表示へ反映する。

## 7. 受け入れ条件
1. 常時表示面積
- オプションの常時表示高さが現状より縮小している。

2. 機能同等性
- 現在提供している各オプション機能が欠落しない。
- 実行結果・表示変換・上限制御が従来どおり機能する。

3. 操作性
- キーボード操作（Esc）で閉じられる。
- タブ切替時の状態保持が正しく行われる。

4. 画面互換
- 一覧/詳細/編集/追加のいずれでも崩れない。
- body横スクロールを新たに発生させない。
- kintone標準のコメント/履歴UIと重なっても操作不能にならない。

## 8. 実装ステップ案
1. Step 1: ポップアップコンテナ導入
- 現行 `ksql-opt-panel` をポップアップ化。

2. Step 2: タブ化
- 表示/取得/保存SQL/フィールドの4タブに分離（履歴は現行維持）。

3. Step 3: サマリ表示
- 現在値の要約をボタン近傍に追加。

4. Step 4: 微調整
- キーボード操作、レスポンシブ、余白/幅の最終調整。
