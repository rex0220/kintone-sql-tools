修正 (B141 ゼロ除算ガードが空セルを捕まえない) ★本リリースの要点:
- 言語リファレンスで「ゼロ除算を避けるには CASE WHEN を使う」として載せていた例が、
  除数が空セルの行で NaN になっていました。
    NG  CASE WHEN 金額 = 0 THEN '' ELSE 1000 / 金額 END
    OK  CASE WHEN 金額 = '' OR 金額 = 0 THEN '' ELSE 1000 / 金額 END
- 空文字は算術では 0 になりますが、比較では 0 と等しくないため、= 0 だけでは
  空セルの行が ELSE へ落ちて、そこでゼロ除算が起きます。
- 除数が空になり得る場面 (LEFT JOIN で一致しなかった行、LAG / LEAD の端の行、
  NULLIF の結果) では両方を書いてください。
- 動作は変わりません。文書の誤りの修正です。

修正 (B140 消せないことがある警告に、その旨を併記):
- v3.52.0 で CTE 経路の案内を直しましたが、月次集約を LAG で読む形では
  案内された「その表の中で一意になる列」が CTE の中に存在せず、従いようが
  ありませんでした (ORDER BY の 年月 が GROUP BY キーそのもののため)。
- 「集約結果の列は一意でも証明できないため、すでに一意な場合もこの警告が
  出ます」を併記しました。
- 値は正しく、警告を出す条件と値は変えていません。

修正 (B140 実行できないタイブレーク助言を出さない) (v3.52.0):
- ウィンドウの ORDER BY が全順序と判定できないときの警告で、CTE や一時テーブルを
  読む場合にも「ORDER BY にレコード番号などのタイブレークキーを足してください」と
  案内していました。しかしその表に レコード番号 は無いため、案内どおりに直すと
  unknown field code(s): レコード番号 で落ちていました。
- 経路に応じて案内を変えます。
    CTE / 一時テーブル  その表の中で一意になる列（元の集約のキーなど）を
                        ORDER BY に含めてください
    物理アプリ          ORDER BY にレコード番号などのタイブレークキーを足して
                        ください（従来どおり）
- 既定フレーム (RANGE) の警告と LAG / LEAD の警告の両方に効きます。
  警告を出す条件と値は変えていません。

文書 (レシピ R17 「行の無いもの」を 0 として並べる) (v3.52.0):
- GROUP BY はデータのある行しか作りません。集計対象が 0 件のものは行ごと消え、
  エラーも警告も出ないため「0 だった」と「そもそも無かった」の区別が付きません。
  検出したいのがまさにその 0 件（動きが止まった製品など）のときに効きます。
- マスタ起点の LEFT JOIN で 0 を出す形を示しました。条件を WHERE に書くと
  LEFT JOIN の後に効いて元の問題へ戻る点も併記しています。
- 日付には起点になるマスタが無いため同じ手が使えないことも明記しました。
新機能 (B128 LAG / LEAD) (v3.51.0):
- 前月比・前年同月比を SQL 側で書けるようになりました。
    LAG(expr [, offset])  OVER (PARTITION BY ... ORDER BY ...)
    LEAD(expr [, offset]) OVER (PARTITION BY ... ORDER BY ...)
- 前後の行がパーティションの外なら空文字を返します。offset は省略時 1 で、
  非負の整数リテラルだけを受け付けます。第 3 引数 (既定値) は未対応です。
- 引数の型を引き継ぎます。CTE や一時テーブルの次の段でも、数値順・日付順・
  選択肢の定義順など元の列の比較規則を保ちます。
- 前月比は 3 段で書きます。ウィンドウ結果を同じ SELECT の式に含める形は
  従来どおり拒否され、次の段へ分ける診断が出ます。

    WITH 月次 AS (
      SELECT DATE_FORMAT(日付, '%Y-%m') AS 年月, SUM(個数) AS 出庫数
      FROM APP4228 WHERE 入出庫区分 = '出庫' GROUP BY 年月
    ), 前月付き AS (
      SELECT 年月, 出庫数, LAG(出庫数) OVER (ORDER BY 年月) AS 前月 FROM 月次
    )
    SELECT 年月, 出庫数, 前月,
           CASE WHEN 前月 = '' THEN ''
                ELSE ROUND((出庫数 - 前月) * 100.0 / 前月, 1) END AS 前月比
    FROM 前月付き ORDER BY 年月

- ORDER BY が全順序と判定できないときは警告が出ます。値は正しく、
  同順の行があるときの前後関係が未規定であることの注意です。

修正 (B137 列数の違う UNION / UNION ALL をエラーにする) (v3.50.0):
- UNION / UNION ALL の左右で列数が違う場合、エラーで停止するようになりました。
  従来は右辺の列が足りないと空文字で埋め、余ると黙って捨てていたため、
  成功しても意図しない結果になり得ました。
    修正前  SELECT 製品名, 仕入先 FROM APP4228 UNION SELECT 製品名 FROM APP4229
            → 右辺由来の行では 仕入先 が空文字になっていた
    移行後  SELECT 製品名, 仕入先 FROM APP4228 UNION SELECT 製品名, '' FROM APP4229
- 足りない側へリテラルを追加して列数を揃えてください。
- 列名は従来どおり左辺から取り、左右の列を位置で対応させます。列名の一致と
  型の互換性は検査しません。
- EXPLAIN は従来どおり計画を返します (行を取らないため列が実体化されません)。
- 言語リファレンスは以前から「両辺の列数が一致しない場合はエラー」と書いていました。
  文書が正しく、実装がその契約を守っていませんでした。挙動の追加ではなく、
  文書どおりに直したものです。
