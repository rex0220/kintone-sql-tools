挙動が変わります (B142 値が無いときの MIN / MAX が 0 から空文字へ) (v3.54.0):
- 集計する値が 1 つも無いときの MIN / MAX が、0 ではなく空文字を返します。
    SELECT MIN(製品名) FROM APP100 WHERE 分類 = '存在しない分類'
      旧 "0" (長さ 1 の文字列。= '' をすり抜ける)   新 ""
- 同じ状況が形によって割れていたためです。空セルは MIN / MAX では値として
  保持されるため、値が 1 個なら空文字、0 個なら 0 になっていました。
    LEFT JOIN で一致しないグループ (空セル 1 個)  ""   従来から
    WHERE が全部落ちる (値 0 個)                  "0"  ← 変わった
    CASE に ELSE が無く全行が非一致 (値 0 個)     "0"  ← 変わった
- MODE / MEDIAN / 統計集約は以前から空文字でした。標準 SQL も MIN / MAX の
  空集合は型に依らず NULL です。COUNT / SUM / AVG は変わりません。
- 移行: MIN / MAX の結果を 0 件かどうかの判定に使っている場合は影響します。
  DML では書き込む値が変わります。
    UPDATE APP88 SET 上限費用 = (SELECT MAX(合計費用) FROM APP88) WHERE ...
    サブクエリが 0 件のとき、書き込む値が 0 から空になります。
  該当が無いのに「最大値は 0」と書くのは事実に反するための変更ですが、
  対象が必須フィールドなら、これまで通っていた UPDATE が失敗します。
  既に 0 が書き込まれているレコードは遡って変わりません。

新機能 (B128 LAG / LEAD) (v3.51.0):
- LAG / LEAD で前月比・前年同月比を SQL 側で書けます。前後の行がパーティションの
  外なら空文字、offset は省略時 1 (非負整数リテラルのみ)、第 3 引数は未対応です。
- 引数の型を引き継ぐので、次の段でも元の列の比較規則を保ちます。
- 前月比は 3 段で書きます。書き方は ksql_docs の recipes/r16 にあります。

修正 (B137 列数の違う UNION / UNION ALL をエラーにする) (v3.50.0):
- 左右で列数が違う UNION はエラーで停止します (従来は空文字で埋める / 黙って捨てる)。
  足りない側へリテラルを追加して列数を揃えてください。
    移行後  SELECT 製品名, 仕入先 FROM APP4228 UNION SELECT 製品名, '' FROM APP4229
- 言語リファレンスは以前からエラーと書いており、実装が契約を守っていませんでした。
